# [R-026] Verify Hang Timeout Recovery

## Context

Loop Manager는 전체 verify 실패를 Worker에게 돌려보내고 같은 실패 지문이 수정 후 세 번 재발하면 계획을 차단한다. 그러나 `scripts/verify` 실행 자체에는 시간 제한이 없다. 테스트 코드가 CPU를 계속 점유하며 종료되지 않으면 실패 결과를 만들지 못해 Worker 수정, Review 또는 차단 단계로 진행할 수 없다. 시간 초과는 무한 반복뿐 아니라 중복 테스트 실행이나 필요한 검증에 비해 짧은 설정값으로도 발생할 수 있다. 기존의 실행·세션·rebase 복구 계획과 분리해 verify 프로세스의 종료 경계와 원인별 후속 처리를 보강해야 한다.

## Requirement

Loop Manager는 전체 verify에 종료 시간 상한을 적용한다. 공통 `verify_timeout_seconds`의 기본값은 1800초이고 사용자가 양의 정수로 조정할 수 있어야 한다. 제한을 넘으면 우선 verify와 그 자식 프로세스를 강제 종료해 CPU 점유가 남지 않았는지 확인하고, 시간 초과를 실패 결과로 보존한다. Worker에게는 현재 profile·session 선택과 검증 피드백 계약에 따라 제한된 진단을 전달한다.

Worker는 남은 출력과 진행 위치, 실행된 테스트와 verify 스크립트를 확인해 무한 반복·교착, 중복 실행 또는 불필요한 테스트가 있는지 먼저 점검한다. 수정 가능한 문제가 확인되면 필요한 범위만 고치고 자신이 변경한 코드·테스트의 targeted test를 수행한다. Loop Manager가 같은 시간 상한으로 전체 verify를 다시 실행한다. 필요한 검증을 삭제하거나 단순히 상한을 늘려 실패를 숨기지 않는다.

필요한 테스트가 정상적으로 진행됐고 설정한 상한만 부족하다는 근거가 확인되면 같은 시간 초과를 반복하지 않고 해당 계획을 `PLAN_BLOCKED`로 두며 현재 상한, 관찰한 진행 상황과 사용자에게 필요한 설정 변경을 알린다. 사용자가 `verify_timeout_seconds`를 늘리면 이 사유의 차단만 해제하고 보존된 작업 공간에서 verify를 다시 진행한다. 원인을 확정할 수 없는 시간 초과는 기존 verify 실패 지문과 반복 차단 정책을 따른다. 프로세스 종료 여부를 확인할 수 없으면 다음 Worker나 verify를 시작하지 않고 프로젝트 안전 차단과 사용자 알림으로 전환한다. 시간 초과를 성공으로 처리하거나 verify 단계를 건너뛰지 않는다. G-041의 Worker session binding과 G-045의 rebase correction 계약은 이 변경의 수정 대상이 아니다.

## Acceptance Criteria

- 정상 verify는 제한 시간 안에 기존과 같이 성공 또는 실패로 처리된다.
- 종료되지 않는 verify는 기본 1800초 또는 설정한 상한에서 중단되고, 그 자식 테스트 프로세스까지 종료돼 CPU 점유가 남지 않는다.
- verify 시간 초과의 진단과 제한된 출력은 기존 Worker profile·session 및 피드백 계약을 따라 수정 경로에 전달된다. Worker는 무한 반복·교착, 중복 실행과 불필요한 테스트를 먼저 점검하고, 확인된 문제만 검증 범위를 약화하지 않으면서 수정한다.
- Worker가 수정한 뒤에는 Loop Manager가 같은 시간 상한으로 전체 verify를 재실행한다. 원인을 확정할 수 없어 동일한 시간 초과가 Worker 수정 후 세 번 재발하면 기존 verify 지문 정책에 따라 해당 계획만 `PLAN_BLOCKED`가 된다. 성공하면 verify 실패 이력이 초기화된다.
- 필요한 검증의 정상 진행과 부족한 시간 상한이 근거로 확인되면 반복 verify 없이 해당 계획을 `PLAN_BLOCKED`로 전환하고 사용자에게 현재 상한, 판단 근거와 설정 조정 방법을 알린다. 설정값이 늘어난 뒤에는 해당 차단을 해제하고 기존 작업 공간에서 verify를 재개한다.
- 시간 초과만으로 테스트가 정상이라고 단정하거나 시간 상한을 자동으로 늘리지 않으며, 필수 검증을 삭제·건너뛰지 않는다.
- verify 프로세스 종료를 확인할 수 없으면 다음 Agent·verify·저장소 변경을 시작하지 않고 안전 차단 원인과 잔존 프로세스 정보를 사용자에게 알린다.
- `verify_timeout_seconds`가 생략되면 1800초이고 0, 음수, 정수가 아닌 값은 작업 시작 전에 설정 오류로 거부한다.
- 시간 초과 처리 중 사용자 변경과 작업 공간을 임의로 삭제하거나 로그에 비밀값을 노출하지 않는다.
- G-041의 Worker session 전이와 G-045의 rebase 충돌 교정은 이 Requirement의 구현으로 변경되지 않는다.

## Product Impact

- 종료되지 않는 테스트가 검증 단계를 무기한 점유하지 않으며, 수정 가능한 테스트·스크립트 문제를 먼저 교정한다. 필요한 검증에 비해 설정 한도가 짧다고 확인되면 사용자에게 조정 근거를 알린다.

## Non-Goals

- CPU 사용률 표본만으로 정상적으로 오래 걸리는 검증을 오작동으로 판정하지 않는다.
- 테스트 실패를 숨기거나 verify를 생략해 PR을 게시하지 않는다.
- Agent session 선택, rebase 충돌 복구 또는 전체 실행 오류 알림 정책을 변경하지 않는다.
- 별도 감시 서비스를 도입하지 않는다.
