# [R-086] 영향 기반 부분 검증과 일반 선행 Review

## Context

Worker 교정마다 전체 verify를 반복하면 Reviewer가 거부할 후보에도 긴 검증 비용이 발생한다. Manager가 모델 없이 관련 회귀 테스트를 먼저 검사하고 일반 선행 Review를 수행해 이 비용을 줄인다. Worker의 R-003 targeted test 제한과 전체 검증·게시·복구 계약은 유지한다.

문서 수정이나 정적 분석의 불확실성 표식만으로 부분 검증을 배제하면 일반 작업에 활용하기 어렵다. 문서의 용도와 참조 대상을 확인해 관련 테스트를 선정하고, 영향 범위를 확인하지 못한 경우에는 기존 전체 검증 경로를 유지한다.

## Requirement

- 첫 지원 범위는 Loop Manager 자체 저장소의 Python unittest 어댑터다. 부분 verify·일반 선행 Review 경로는 기본 사용하며 `[loop] verify_partial = false`로 끌 수 있다. 옵션 생략 시 true이며, 안전한 선정·검토 증거를 확인하지 못하면 기존 전체 verify → Reviewer 경로를 사용한다.
- Worker 완료 뒤 기존 커밋·최신 기준 브랜치 조정으로 준비한 후보와 기준 커밋의 전체 변경을 사용한다. 변경 전후의 전체 Python AST 그래프에서 직접·역방향 간접 의존성으로 테스트 모듈을 고르고 변경된 테스트를 포함한다. 삭제·이름 변경·이동 전의 참조 모듈도 확인하고 실제 수집 명세의 모듈·테스트 ID로 정규화한다. 파일명 유사도와 AI 선정은 사용하지 않는다.
- 코드와 함께 변경한 계획·작업·설계 문서가 검토 입력으로만 쓰임을 확인하면 테스트 선정의 거부 사유로 삼지 않는다. 문서 내용과 전체 변경은 선행 Review·최종 승인 입력에 보존한다. 확장자·디렉터리나 검증 입력 목록 밖이라는 사실만으로 비영향을 인정하지 않는다. 테스트가 읽는 문서·공통 준비 자료·템플릿, 실제 지침·설정과 역할을 확인하지 못한 비Python 입력은 관련 테스트를 증명하지 못하면 기존 전체 경로를 사용한다. 문서만 변경해 테스트 대상이 없거나 R-082 별도 문서 처리가 진행 중이면 기존 경로를 유지한다.
- 불확실성은 참조 종류와 확인한 대상 범위로 구분한다. 참조 대상이나 한정된 모듈 집합을 정적으로 확인하면 의존성 관계로 반영하고 관련 테스트를 포함한다. 객체 속성 조회나 외부 명령 사용만으로 저장소 전체를 거부하지 않되, 모듈 선택 또는 변경 대상과 무관하다는 근거가 있어야 한다. 동적 모듈 조회·실행 시 선택·분석 실패·미해결 내부 참조로 숨은 참조 모듈의 범위를 확인하지 못하면 기존 전체 경로를 사용한다. 역방향 그래프에 관계가 없다는 사실만으로 비영향을 판단하지 않는다.
- 공개 API·공통 테스트 지원 코드 변경은 변경 전후의 참조 모듈과 공통 준비 범위를 확인하면 관련 테스트를 확대한다. 공통 진입점을 통해 제공되는 API도 실제 사용 관계를 확인한 경우에만 영향 범위를 좁힌다. 모듈을 불러올 때의 초기화·부작용·동적 접근 관계를 누락하지 않으며, 확인하지 못하면 기존 넓은 범위 또는 전체 경로를 유지한다. 실행 단위는 수집 명세의 테스트 모듈이다.
- Git·SQLite·상태·권한·복구·게시, 패키지 초기화·루트 진입점과 테스트 수집·검증 설정·검증 실행·인터프리터·실행 차단·프로세스 종료·자원 예약의 공통 경계는 영향 범위를 확인하지 못하면 전체 경로를 사용한다. 경로 단어만으로 일반 보조 모듈까지 일괄 거부하지 않고 실제 보호 경계와 근거를 확인한다. 삭제·이동 분석이 불충분하거나 대상이 없어도 전체 경로를 사용한다. 영향 범위 불명과 큰 실행 비용의 사유를 구분하고, 넓은 선택의 비용은 실제 부분/전체 실행 시간과 선정 규모로 평가한다. 부분 모드에서 전체 테스트를 실행한 뒤 전체 verify를 반복하지 않는다.
- 부분 verify는 Agent 밖에서 기존 프로젝트 인터프리터·실행 차단·프로세스 종료 확인·직렬/독립 실행·자원 예약 정책을 사용한다. 전체 테스트 수집과 공통 준비·건너뛰기 의미를 유지하며 선택 모듈의 결과 누락·중복·식별 오류를 성공으로 인정하지 않는다. 미선택 모듈은 NOT_SELECTED로 구분한다. 시간 초과·취소·종료 불명은 기존 안전 정책을 따른다.
- 부분 결과에 후보·기준 커밋, 수집 명세·선택 모듈/테스트 ID, 선정 또는 전체 경로 선택 이유·규모, 알고리즘·설정 식별 정보, 시간·실패 진단을 남긴다. 추가한 참조 모듈·해소한 불확실성·제외 근거와 남은 불확실성을 구분한다. 분류·선정 규칙의 변경을 식별 정보에 반영해 오래된 선택·선행 승인을 재사용하지 않는다. 부분 성공은 전체 verify의 token·receipt 또는 verified_head를 만들지 않는다.
- 부분 FAIL은 기존 verify 교정·반복 차단으로, 선행 Review FAIL은 기존 ISSUE_ID·실패 감사·Worker 수준 교정으로 연결한다. 선행 FAIL이면 전체 verify를 호출하지 않는다. 부분 PASS와 선행 PASS 뒤에는 실제 전체 verify를 수행하며 전체 FAIL은 기존 교정 정책을 따른다.
- 일반 선행 PASS는 독립된 후보 증거다. 같은 작업 주기·HEAD·기준 커밋·전체 변경·검토 문서·사용자 결정·실제 Reviewer 지침·제공자·모델·추론 수준·실행 환경·정책과 현재 후보에 유효한 실제 전체 verify 성공 기록을 모두 확인한 경우에만 추가 모델 호출 없이 최종 승인한다. 증거 부재·변경·중단·원격 변경/기준 브랜치 조정 중 경쟁에서는 기존 최종 Reviewer 또는 안전한 전체 경로를 사용한다. 게시 직전 최신 원격 상태·lease·작업물 소유권·선행 작업·사용자 결정 조건을 확인한다.
- R-082 문서 변경 선행 Review의 PASS/VERIFY_REQUIRED는 최종 승인 근거로 재사용하지 않는다. G-183의 마지막 최종 승인 재사용과 G-241의 전체 verify 생략은 별도 작업이다.
- 같은 실행 환경과 범위의 실제 기록으로 부분/전체 시간·선택 규모·부분 PASS 이후 전체 FAIL·Review FAIL로 생략한 전체 검증·Reviewer 호출/토큰·Worker 교정/총시간·전체 경로 선택 사유를 비교한다. 측정하지 않은 시간·토큰 절감을 만들지 않는다.

## Acceptance Criteria

- 직접·간접 참조, 변경 테스트, 삭제·이름 변경·이동 전의 참조 모듈 선정과 후보 변경 거부를 검증한다. 공개 API·지원 코드의 참조 모듈을 확인하면 관련 테스트를 확대하고, 확인하지 못하면 부분 실행 없이 전체 경로로 전환한다.
- 코드와 검토 전용 문서를 함께 수정하면 코드 기준으로 테스트를 선정하고 문서 내용·전체 변경을 승인 입력에 보존한다. 같은 확장자의 테스트 자료·지침·설정과 역할 불명·문서만 변경해 대상이 없는 경우·R-082 별도 처리를 구분한다. 선행 승인 뒤 문서 변경은 승인 재사용을 거부한다.
- 고정된 모듈 이름·별칭·한정된 모듈 집합과 비영향을 증명한 객체 속성 조회·외부 명령은 일괄 거부하지 않는다. 그래프 밖의 동적 참조·대상 불명·분석 실패·미해결 내부 참조 또는 전체 범위만 확인되는 경우에는 좁은 PASS를 만들지 않는다. 해소·제외·전체 경로 선택 근거를 진단에서 확인한다.
- 공통 진입점의 직접 API 사용·별칭·재노출·지원 코드 경유를 비교하고 모듈 초기화·부작용·미해결 동적 관계를 누락하지 않는다. 핵심 공통 경계·검증 설정·대상 없음·넓은 선택에서 전체 경로로 전환하는 조건을 확인한다.
- 실제 수집 명세와 선택 모듈의 식별 정보·필수 결과·공통 준비의 건너뛰기/실패·시간 초과/취소/종료 불명·자원 정책을 검증한다. 부분 성공과 전체 receipt는 분리되며 선정 규칙 변경 뒤 과거 선택·승인을 거부한다.
- 부분 FAIL/선행 FAIL은 Worker로 돌아가고 선행 FAIL 이후 전체 verify 호출 수는 0이다. 선행 PASS 뒤 실제 전체 성공과 동일 입력에서는 Reviewer 호출 1회로 게시 승인에 도달한다.
- 후보·기준 커밋·전체 변경·명세·지침·실행 조건의 변경, 증거 부재·재시작·원격 변경·기준 브랜치 조정 중 경쟁에서 오래된 승인으로 게시하지 않는다. 전체 FAIL 뒤 교정과 문서 선행 Review·수동 제출/waiver·사용자 결정·게시 경계의 회귀를 확인한다.
- 선정 개선과 비용 기준 조정의 효과를 구분해 보고하며 임의의 절감률을 완료 기준으로 삼지 않는다.

## Product Impact

Manager의 부분 검증은 Review 전 회귀 검사이며 최종 보장은 별도 전체 verify와 유효한 Review 승인 및 게시 조건이 제공한다.

## Non-Goals

- 커버리지·AI·실행 이력을 통한 테스트 추천, 함수·라인별 선택과 다른 언어·프레임워크 지원.
- Worker 테스트 제한 완화·중복 제거, 전체 verify 생략, Review/verify 병렬 실행과 G-250 병렬 최적화 중복 구현.
