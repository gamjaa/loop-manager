# [R-072] 입력 동일성이 증명된 구현 후보 성공 결과 재사용

## Context

Archive된 [R-063](archive/%5BR-063%5D%20Manager-Owned%20Deterministic%20Work%20and%20Minimal%20Model%20Use.md)은 commit ID 변경과 실제 입력 변경을 구분해 이미 성공한 구현 후보 검증을 재사용하도록 요청했다. 현행 후보 revision별 무효화만으로는 ID만 바뀐 경우에도 Worker·test·verify·Review를 반복할 수 있다. 이 문서는 그 미완료 목표를 활성 입력으로 보존한다.

## Requirement

- 같은 계획·작업 주기에서 관리 rebase 등으로 commit ID만 바뀌었고 역할별 실제 입력의 동일성을 Manager가 증명할 수 있으면, 성공한 Worker 판단·targeted test·전체 verify·Reviewer 결과 중 조건을 충족한 것만 재사용한다.
- 각 역할의 판단·실행에 영향을 주는 코드·문서 내용과 파일 mode, ExecPlan·사용자 결정·공통 및 프로젝트 지침, 기준 내용과 최종 diff, 검증 command·설정·환경 및 provider·Model·Effort를 비교한다. 전체 verify에는 전체 검증 대상과 실행 입력의 동일성이 필요하다.
- 검증이 Git HEAD·이력·revision에서 생성한 값 등을 사용하면 SHA 변경도 실제 입력 변경으로 처리한다. tree 동일성만으로 성공을 재사용하지 않는다. 내용이 바뀌거나 비교 자료가 불완전하면 필요한 단계부터 다시 수행한다.
- 과거 SHA의 성공 token을 그대로 복사하지 않는다. 원래 성공 결과와 동일성 확인 근거를 현재 후보 revision에 연결해 현재 후보의 유효한 증거를 남긴다. 실패·timeout·미완료·출처 불명 또는 다른 계획·작업 주기의 결과는 재사용하지 않는다.
- 새로운 Review issue·사용자 결정·검증 실패·역할 설정 변경이 있으면 영향을 받는 결과부터 재사용 조건을 다시 확인한다. 최신 원격 base·branch·PR identity·lease·소유권·dependency·사용자 승인과 게시 gate는 매번 확인한다.
- 기존 정적 코드맵·유지보수 모듈 결과의 재사용과 완료 후보의 문서 전문 확인을 유지한다. Requirement 최종 충족 판단은 R-068에 따라 실제 Merge된 최신 원격 구현을 확인하며, 미반영 후보의 입력 동등성만으로 이를 대신하지 않는다.
- 재사용한 입력·이유·원래 결과를 기록한다. 중단·재시작에서 연결 근거를 재검증하며 출처가 불확실하면 재검증으로 돌아간다. 생략된 실행의 invocation·토큰 사용량이나 측정하지 않은 시간·비용 절감을 만들어내지 않는다.

## Acceptance Criteria

- ID만 바뀐 후보에서 역할별 입력 동일성이 증명된 성공 결과만 재사용되고, 원래 성공과 현재 후보를 연결하는 근거를 확인할 수 있다.
- 코드·문서·mode·diff·지침·승인·profile·검증 command·환경이 바뀌면 영향을 받는 단계부터 재검증한다.
- Git revision 의존 검증, 비교 근거 누락, 실패·미완료와 다른 계획·작업 주기의 결과는 재사용되지 않는다.
- 과거 성공 token 복사만으로 후보가 통과하지 않으며, 최신 ref·lease·ownership·dependency·승인·게시 조건을 매번 확인한다.
- 재사용 저장 중단·재시작·원격 경쟁에서도 근거와 작업물을 보존하고, 불확실한 성공을 현재 결과로 승격하지 않는다.
- 실제 모델을 호출하지 않는 검증으로 동일 입력의 호출 감소와 입력 변경·불확실성에서 필요한 Worker·test·verify·Review 수행을 함께 확인할 수 있다.
- 재사용 로그는 실제 실행·사용량과 구분되고, 새 작업 주기의 최종 문서 확인과 Merge 뒤 Requirement 충족 판단을 생략하지 않는다.

## Product Impact

- 후보 revision이 달라도 역할별 실제 입력이 같다고 증명된 성공 결과는 재사용한다.
- 실제 입력 변경·근거 부족에는 재검증하고 현재 후보의 게시 안전 조건은 항상 다시 확인한다.

## Non-Goals

- 검증·Review·사용자 Merge를 생략하거나 실패 결과를 성공으로 바꾸지 않는다.
- 다른 계획·작업 주기의 최종 판단을 가져오거나 미반영 후보로 Requirement 완료를 선언하지 않는다.
- 기존 코드맵·모듈 검토 재사용과 Worker 세션 feedback 축소를 재구현하지 않는다.
- Agent 격리·권한 정책이나 비호환 상태 모델을 변경하지 않는다.
