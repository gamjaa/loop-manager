# [R-066] Agent CLI 지침의 독립성

## Context

프로젝트의 개발 지침 해석은 AI Agent CLI가 담당한다. Loop Manager가 같은 파일을 등록·승인·계획 입력으로 별도 관리하면 CLI의 작업 문맥과 중복된 정책이 생긴다.

## Requirement

- Manager는 프로젝트 루트 `AGENTS.md`의 존재·내용·인코딩·해시를 등록 조건이나 계획 입력으로 사용하지 않는다. 명시적인 읽기 지시·변경 제안·사전 승인·patch 대조·승인 대기 처리를 제거한다.
- Agent의 일반 역할·목표·사용자 결정과 Git 소유권·검증·Review·게시 조건은 유지한다. 파일 이름을 이유로 Worker의 일반 작업 범위를 제한하거나 별도 승인 권한을 만들지 않는다.
- 과거 등록·승인 감사와 문서는 삭제하지 않는다. 과거 승인 내용은 현재 권한이나 적용 patch로 사용하지 않으며 기존 승인 대기는 파일 내용을 재검사하지 않고 일반 작업·복구 흐름으로 전환한다.
- 프로젝트 준비 도구는 CLI 지침 파일을 조회·검증·생성하지 않는다. Loop Manager 자체 개발의 루트 지침은 이 저장소에서 유지한다.

## Acceptance Criteria

- 등록 문서 검사는 제품·설계·계획 규칙과 활성 Requirement 조건만 확인하며 CLI 지침의 유무·형식은 결과에 영향을 주지 않는다.
- Planner·Worker·Reviewer 호출에 프로젝트 루트 지침의 읽기·승인·복원 지시가 없다.
- Worker 결과·verify·rebase·게시에서 과거 승인 patch나 대상 내용을 대조하지 않는다.
- 과거 감사 데이터와 작업물·session을 보존하며 다른 차단 원인과 일반 사용자 결정을 해제하지 않는다.
- 문서·복사 도구·예약 경로 목록과 코드가 같은 경계를 따른다.

## Product Impact

프로젝트 개발 지침은 Agent CLI의 문맥으로 처리하고 Manager는 자동 작업의 역할과 실행·검증 책임을 관리한다.

## Non-Goals

- provider의 지침 해석이나 공통·역할별 runtime instruction 고정을 변경하지 않는다.
- 과거 감사 데이터와 프로젝트 파일을 삭제하거나 사용자 결정을 대신 작성하지 않는다.
