# [R-058] 테스트별 시간 기록과 실제 Agent 없는 테스트

## Context

현재 전체 verify는 설정된 `verify_timeout_seconds`를 적용하고 초과 시 프로세스를 종료한다. Worker에게 무한 반복·교착·중복 검증을 먼저 조사하고 시간 상한을 임의로 올리지 않도록 요청한다. 그러나 verify 스크립트의 unittest 실행은 각 테스트의 소요 시간을 기록하지 않아 오래 걸리는 지점을 비교하기 어렵다.

테스트별 실제 소요 시간을 근거로 검증 비용을 줄이고, 실제 AI Agent 호출에 의존하는 테스트를 배제한다. 우선 전수 적용 대상은 Loop Manager 자체 테스트이며, 자동 작업에서 새로 작성·변경하는 테스트와 verify에도 같은 원칙을 적용한다.

## Requirement

### 소요 시간 기록

- 전체 테스트 실행에서 각 테스트의 식별자, 시작·종료, 실제 소요 시간과 결과를 기록한다. 성공뿐 아니라 실패·오류·skip도 구분하고, fixture 준비·정리 또는 공통 초기화 비용이 큰 경우 그 비용이 기록에서 사라지지 않게 한다.
- 실행 revision, 테스트 명령과 전체 소요 시간을 함께 확인할 수 있고, 완료한 테스트를 소요 시간 순으로 비교할 수 있어야 한다. 시간 측정은 실행 시간 진단을 위한 것이며 결과 판정·실행 순서·검증 범위를 임의로 바꾸지 않는다.
- 전체 verify가 제한 시간으로 강제 종료돼도 이미 완료한 테스트 기록과 현재 실행 중이던 테스트 또는 공통 단계의 식별자·경과 시간을 확인할 수 있게 한다. 종료되지 않은 테스트를 완료 시간이나 성공 결과로 기록하지 않는다.
- 기록은 Manager의 기존 상태·로그 보존 경계를 따르고, Worker에게 전달하는 실패 출력이 길이 제한으로 잘려도 필요한 시간 진단을 확인할 수 있어야 한다. 테스트 실행마다 새로운 외부 모니터링 서비스에 의존하지 않는다.

### 시간 초과 진단과 최적화

설정된 제한 시간 내에 전체 verify가 끝나지 않으면 기존 프로세스 종료 확인을 먼저 마친 뒤 Worker에게 시간 기록과 진행 위치를 전달한다. Worker는 완료한 테스트 중 오래 걸린 항목과 현재 종료되지 않은 항목·준비·정리 단계를 우선 조사한다. 단순 누적 시간 외에 무한 반복·교착·실제 외부 호출·불필요한 대기·반복 fixture와 중복 검증을 확인한다.

각 느린 테스트가 보호하는 동작, 다른 테스트와의 중복 및 더 작은 결정적 검증으로 같은 회귀를 잡을 수 있는지 확인해 실제 병목을 줄인다. 삭제·통합·mock 전환은 필요한 계약·실패·복구 검증을 보존한 근거가 있을 때만 수행하고, 시간 상한을 맞추려고 필수 테스트를 skip하거나 전체 검증을 targeted test로 대체하지 않는다.

Worker는 변경한 테스트·코드에 직접 관련된 최소 unit test만 실행한다. 최적화 전후 전체 verify와 시간 변화는 Manager가 Agent 밖에서 실행한 결과로 확인한다. 모든 필수 검증이 정상 진행하며 현재 한도만 부족하다는 구체적 근거가 남은 경우에는 사용자 설정 조정 절차를 따르고, 상한을 자동으로 늘리지 않는다. 설정·도구·timeout 등 로컬 환경을 수정한 뒤의 제한된 재검사는 R-062를 따르며, 원격 입력 변경이나 기존 실패 이력 삭제를 요구하지 않는다.

### 실제 AI Agent 호출 금지

테스트 실행은 Planner·Worker·Reviewer 또는 다른 실제 AI Agent의 CLI·API를 호출하지 않는다. 시간 측정이나 timeout 진단을 위한 테스트도 포함한다. Agent 실행·사용량·session·출력·오류·중단·복구가 필요한 검증은 mock·stub 또는 고정된 출력 fixture로 처리하고 실제 인증·사용 한도·네트워크 응답을 요구하지 않는다.

기존 테스트를 전수 확인해 실제 Agent 실행으로 이어질 수 있는 경계를 mock 처리하고, 예기치 않은 실제 호출이 성공으로 흘러가지 않게 한다. mock은 프로그램이 필요한 인자·역할·세션·결과·실패 처리 계약을 검증할 수 있어야 한다. AI가 테스트 코드를 작성·수정하는 개발 절차와 테스트 프로세스가 실제 Agent를 실행하는 행위를 구분한다. 필요한 실제 Git·SQLite·운영체제 동작의 검증까지 모두 mock으로 바꾸지는 않는다.

## Acceptance Criteria

- Windows·Linux 전체 verify에서 실행된 각 테스트의 ID·소요 시간·결과와 전체 실행 정보가 기록되고, 느린 순서로 확인할 수 있다. fixture·공통 준비·정리의 큰 비용도 식별할 수 있다.
- 테스트 성공·실패·오류·skip과 프로세스 강제 종료가 구분된다. 시간 초과 시 이미 완료한 기록과 중단된 항목·단계의 경과 시간은 남고 거짓 완료 시간은 기록되지 않는다.
- timeout 피드백으로 Worker가 긴 테스트와 중단 지점부터 필요성·대기·교착·중복·fixture·외부 호출을 점검할 수 있다. 출력 길이 제한으로 시간 진단 전체가 사라지지 않는다.
- 최적화는 보호하는 동작과 회귀 검증을 유지한다. 상한 자동 증가, 필수 테스트의 무근거 삭제·skip 또는 전체 verify의 targeted 축소가 발생하지 않는다.
- Worker의 최소 targeted test와 Manager의 전체 verify 책임을 유지하며, 최적화 효과는 같은 검증 범위와 비교 가능한 실행 조건의 실제 시간으로 확인한다. 측정 전 절감 효과를 확정하지 않는다.
- 전체 기존 테스트와 새 시간 측정·timeout 테스트가 실제 Codex·Claude 또는 다른 Agent CLI·API를 실행하지 않는다. Agent 경계를 mock 처리하고 정상·오류·재개 계약을 검증한다.
- 테스트가 실제 AI 인증·계정 사용량·외부 응답에 의존하지 않으며, 예상 밖의 실제 Agent 호출 시도는 테스트 실패로 드러난다.
- 시간 기록 자체가 기존 결과·종료 코드·프로세스 종료 확인·검증 범위를 약화하지 않는다.

## Product Impact

- 전체 verify 시간 초과를 테스트별 실행 근거로 진단하고 필수 검증을 보존하며 소요 시간을 줄인다.
- 자동 검증에서 실제 AI Agent 실행 비용과 외부 응답 의존성을 제거한다.

## Non-Goals

- 테스트의 AI 사용 금지를 Planner·Worker·Reviewer의 정상 제품 실행 금지로 확대하지 않는다.
- 테스트 parallelization, 새 테스트 프레임워크 또는 외부 성능 모니터링 서비스를 필수로 도입하지 않는다.
- 기존 등록 프로젝트의 모든 테스트를 일괄 수정하거나 설정 시간 상한을 자동 변경하지 않는다.
- 필수 실제 Git·SQLite·운영체제 회귀 검증을 일괄 mock으로 대체하지 않는다.
