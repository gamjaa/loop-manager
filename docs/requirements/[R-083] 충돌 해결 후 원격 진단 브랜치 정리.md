# [R-083] 충돌 해결 후 원격 진단 브랜치 정리

## Context

현재 `loop-manager/diagnostics/...` 원격 브랜치는 없으면 생성하고, 같은 commit이면 재사용하며, 다른 commit이면 갱신을 거부한다. 충돌 해결이나 작업 완료 뒤 자동으로 삭제하지 않아 임시 보존용 브랜치가 원격에 계속 남는다.

진단 브랜치에는 충돌 자료 또는 원래 작업 브랜치에 게시하지 못한 작업물이 들어간다. 로컬 충돌 해소만으로 삭제하면 아직 게시되지 않은 결과나 복구 자료를 잃을 수 있다. 해결 결과의 원격 반영과 원인 해소를 확인한 뒤 해당 진단 브랜치를 정리해야 한다.

이 Requirement는 [R-060](archive/%5BR-060%5D%20Collaborative%20Git%20Recovery%20and%20Remote%20Blocked%20Snapshots.md)의 원격 보존 정책에 충돌 해결 후의 정리 조건을 추가한다. 현재 생성·재사용·갱신 거부 조건과 미해결 작업의 보존 원칙은 유지한다.

## Requirement

### 정리 시점과 범위

Manager는 다음 조건이 모두 확인된 뒤 최초의 안전한 실행 경계에서 해당 충돌에 연결된 원격 진단 브랜치를 자동으로 정리한다.

- 실제 충돌과 관련 Git operation이 해소됐고, 보존된 작업물을 포함한 해결 결과가 해당 정상 원격 작업 브랜치에 반영됐음이 확인됐다.
- 해당 충돌 원인의 해소와 차단 해제 또는 충돌 복구 완료가 SQLite에 확정됐다. 새 원격 commit 관측, 로컬 충돌 marker 제거나 rebase 완료만으로 정리하지 않는다.
- 해당 ref를 필요로 하는 미해결 원인이나 진행 중인 진단 보존·게시가 없다. 같은 ref를 여러 원인에서 재사용했으면 모두 확인한다.
- 아래의 소유권·원격 OID·자료 보존 조건이 충족됐다.

정리 때문에 PR Merge나 전체 작업 완료까지 추가로 기다리지는 않는다. 반대로 작업 상태가 완료라는 사실만으로 원인·게시·보존 조건을 생략하지 않는다. 다른 차단이나 Review 교정이 남아 있어도 해당 ref가 더 이상 필요하지 않으면 정리할 수 있으며, 그 상태를 함께 해제하지 않는다. 브랜치 정리는 Worker 확인·targeted test·전체 verify·Review·게시 승인이나 작업 완료의 근거가 아니다.

정리 대상은 저장된 게시 기록으로 등록 프로젝트·해당 작업·충돌 원인과의 관계 및 Manager의 생성·게시가 확인되는 `loop-manager/diagnostics/...` ref로 제한한다. prefix나 작업 ID만으로 소유권을 추정하지 않는다. 같은 충돌에서 여러 진단 ref를 만들었으면 각각 판정한다. 원래 작업 브랜치·base·사용자 브랜치와 다른 작업 또는 미해결 원인의 진단 ref는 삭제하지 않는다.

기능 적용 전에 생성된 ref도 다음 정상 실행에서 같은 근거로 판정할 수 있으면 정리한다. 관계나 게시 기록이 불충분한 과거 ref는 보존하며 원격 namespace 전체를 일괄 삭제하지 않는다. 원래 작업 브랜치가 없는 planning 실패와 충돌 이외 원인의 진단 정리는 이 변경의 대상이 아니다.

### 원격 삭제의 안전 조건

삭제 직전에 현재 등록 origin과 저장된 게시 대상의 identity, 원인 해소 상태, ref의 다른 사용 여부를 재확인한다. 원격에서 정확한 ref를 조회하고, 게시 성공으로 확인해 저장한 OID를 기대값으로 사용한다.

| 현재 원격 상태 | 처리 |
|---|---|
| 저장된 게시 OID와 일치 | 그 OID의 정확한 lease로 해당 ref만 삭제하고, 원격 부재를 확인한 뒤 정리 완료를 확정한다. |
| ref가 이미 없음 | 추가 push나 재생성 없이 정리 완료로 처리한다. |
| 다른 OID가 있음 | 삭제를 보류하고 불일치를 기록한다. 현재 OID를 새 기대값으로 바꿔 삭제하지 않는다. |
| 조회 실패 또는 응답 불명확 | 부재로 간주하지 않고 미확정 상태와 이유를 보존한다. |

조회와 삭제 사이에 원격 commit이 바뀌면 lease 실패로 보존한다. 기존 자원 조율·게시 대상 검증을 준수하며, 다른 실행의 진단 게시와 같은 ref를 동시에 변경하지 않는다. 권한·branch protection·원격 경쟁을 강제 삭제나 다른 원격 대상 사용으로 우회하지 않는다.

### 자료와 이력 보존

삭제 대상의 원문 진단 자료는 원격 ref 없이도 기존 로컬 보존 영역에서 복구 가능함을 확인해야 한다. commit OID 문자열이나 일시적으로 남은 Git 객체만으로 보존을 인정하지 않는다. 부모 없는 별도 진단 commit의 파일·diff·blob·manifest도 이 조건을 적용하며, 로컬 자료가 없거나 손상됐거나 동일성을 확인할 수 없으면 삭제를 보류한다.

원격 브랜치 정리는 기존 로컬 진단 자료·작업물·session·실패 및 알림 감사·게시 intent와 확정 기록의 삭제를 수반하지 않는다. 과거 ref·OID와 정리 결과를 함께 남겨 이전 원격 보존 성공과 현재 원격 ref 존재 여부를 구분한다. 정리된 ref를 계속 존재하는 원격 보존물로 보고하지 않는다.

### 실패와 중단 후 재개

정리 대상 ref·기대 OID·연결 원인과 처리 결과는 상태 원본에 보존한다. 조회·삭제·삭제 후 원격 확인·SQLite 확정 사이에 중단돼도 다음 정상 실행에서 실제 원격 상태와 대조해 재개한다. 원격 삭제 성공 뒤 상태 저장이 중단됐으면 부재를 확인해 완료하고, 확인 실패만으로 삭제 성공을 추측하지 않는다.

일시적인 삭제·조회 실패는 이후 정상 실행에서 안전 조건을 다시 확인해 재시도한다. 원격 OID 불일치·소유권 불확실·자료 보존 실패에는 삭제 push를 반복하지 않고 근거가 바뀐 뒤 재평가한다. 같은 실행에서 무한 재시도하지 않으며 실패 자체로 해결된 작업을 다시 차단하거나 기존 복구·검증·게시·독립 작업을 멈추지 않는다. 정리 성공·보류·재시도만으로 새 사용자 알림을 만들지 않는다.

정리 완료된 과거 진단을 기존 보존 재시도로 다시 생성하지 않는다. 이후 새 충돌은 독립된 원인으로 기존 보존 정책을 적용하며, 과거 게시 성공 기록만으로 삭제된 ref가 현재 존재한다고 간주하지 않는다.

## Acceptance Criteria

- 실제 충돌 해소, 해결 결과의 정상 작업 브랜치 원격 반영, 해당 원인의 해소 확정 및 자료 보존을 확인하면 연결된 진단 ref가 자동 삭제된다. PR Merge 대기 중에도 같은 조건으로 정리된다.
- 로컬 충돌만 해소됐거나 해결 결과가 미게시·미확정이면 삭제하지 않는다. 다른 차단 원인이 남아 있어도 해당 ref를 사용하지 않으면 대상 원인의 정리는 가능하고 다른 상태는 바뀌지 않는다.
- 여러 진단 ref와 같은 ref의 복수 원인 재사용을 각각 판정한다. 미해결 원인 또는 진행 중 게시가 사용하는 ref는 보존한다. 원래 작업·base·사용자·다른 작업의 브랜치는 변경되지 않는다.
- 원격 OID가 저장된 게시 OID와 같을 때만 정확한 lease로 삭제한다. 삭제 직전 경쟁 변경과 처음부터 다른 OID인 경우 모두 사용자 commit을 보존하고, 원격 조회 실패를 부재로 처리하지 않는다.
- 부모 없는 진단 commit도 원문 자료의 로컬 복구 가능성을 확인한다. 자료가 없거나 손상됐으면 ref를 보존하고, 정상 삭제 뒤에도 기존 원문 자료와 감사·게시 기록을 조회할 수 있다.
- 삭제 전, 삭제 성공 후, 원격 부재 확인 후 및 SQLite 완료 확정 전의 중단에서 실제 ref와 저장 기록을 대조해 재개한다. 이미 없는 ref에는 중복 삭제나 재생성이 없고, 삭제 후 확인 실패는 미확정으로 남는다.
- 일시 실패는 다음 정상 실행에서 재시도하며 반복 경쟁·권한 거부·불충분한 근거로 무한 삭제를 시도하지 않는다. 정리 실패가 작업 재차단·후속 진행 중단·중복 알림을 만들지 않는다.
- 과거 생성 ref 중 충분한 기록과 현재 안전 조건이 있는 대상은 정리하고, 기록이 부족한 ref는 보존한다. 정리된 과거 intent의 재시도로 ref가 되살아나지 않으며, 새 충돌의 보존은 정상적으로 수행된다.

## Product Impact

- 충돌 해결 후 더 이상 필요하지 않은 관리 원격 진단 브랜치는 안전 조건을 확인해 자동 정리한다.
- 정리 뒤에도 로컬 진단 자료와 감사 이력은 유지하며, 불확실하거나 여전히 필요한 원격 보존물은 남긴다.

## Non-Goals

- planning 실패·충돌 이외 원인의 진단 정리, 원격 namespace 일괄 삭제, 기간 기반 보존 정책이나 별도 정리 CLI를 추가하지 않는다.
- 로컬 진단 자료·작업 공간·session의 수명 정책과 충돌 해결·검증·Review·PR Merge 조건은 변경하지 않는다.
