# [R-073] 호출 목적과 사용량 범위 기록 및 조회

## Summary

실제 Agent 호출 종료 직후 기존 ledger에 목적·실행 여부·profile·session 전이·결과·시간과 provider 사용량 범위를 연결하고 기간·프로젝트·역할·목적별로 조회한다. 누적·중복·부분 수집·미확인과 실제 0을 구분하며 생략을 실제 호출로 세지 않는다. R-055의 삭제 확정 작업은 해당 호출·로그·사용량도 제거하고 집계에서 제외한다. 추가 모델 호출·추정 비용 없이 기존 집계를 확장하고 관측 실패가 작업 결과나 필수 안전 증거를 바꾸지 않게 한다.

## Context

Archive된 [R-063](archive/%5BR-063%5D%20Manager-Owned%20Deterministic%20Work%20and%20Minimal%20Model%20Use.md)의 기본 호출 결과 보존은 구현돼 있지만, 작업 목적·실제 실행 여부·사용량 범위와 기간별 조회 목표는 남아 있다. 현재 기록만으로는 같은 역할 안의 반복 교정과 부분 수집을 구분해 호출 감소의 효과를 확인하기 어렵다. 이 문서는 기존 ledger와 provider 사용량 파싱을 유지하며 남은 관측 목표를 활성 입력으로 보존한다.

## Requirement

- 모든 실제 Agent CLI 실행의 종료·실패·timeout·중단 직후 사용량 관측 결과를 기존 호출 기록과 실행 로그에 연결한다. 일회 실행·세션 시작·재개·교체·fallback·교정·복구를 포함하고 성공한 작업 전체 종료까지 기록을 미루지 않는다. 사용량은 구조화된 CLI 출력에서 코드로 수집하며 이를 위한 추가 모델 호출은 없다.
- 호출 식별자, 프로젝트와 가능한 대상 계획·batch·파일, 역할·작업 목적, 실제 provider·Model·Effort·CLI 버전, session 전이·재시도 사유와 횟수, 시작·종료·소요 시간과 결과를 연결한다. 일반 계획·최종 확인·유지보수 검토·발견 처리·계획 작성·Worker 구현·검증 교정·Review 교정·충돌 해결 등을 실제 호출 위치의 목적으로 구분한다. 목적을 분류하기 위해 생략된 단계를 다시 실행하지 않는다.
- 실행 준비와 실제 실행을 구분한다. 설정·격리·프로세스 생성 중 실행 전에 거부된 시도는 실제 모델 호출 수에서 제외하고 실행 여부를 확정할 수 없으면 미확인으로 표시한다. 버전 조회와 모델 없는 sandbox 점검도 제외한다. 과거 기록에 목적·실행 여부·범위 근거가 없으면 추측해서 채우지 않는다.
- 제공된 input·cache read·cache write·output·reasoning token과 포함 관계를 보존한다. 현재 turn·실제 호출·세션 누적 중 사용량 범위, 하위 Agent 포함 여부와 제공되는 모델별 원본을 확인할 수 있게 한다. 같은 사용량의 중간·최종·모델별 이벤트를 이중 합산하지 않는다.
- 재개 시 누적 수치는 비교 가능한 이전 수치·범위·reset 여부가 확인된 경우에만 이번 호출 증가분으로 계산한다. 불확실하면 누적 원본과 증가분 미확인을 구분한다. 누락·부분 수집·형식 오류·중단을 가짜 0이나 완전한 호출 합계로 처리하지 않는다.
- 기간·프로젝트·역할·목적·Model·Effort·session 전이별 실제 호출 수·토큰 분류별 사용량·시간·재시도·실패 비중을 코드로 조회할 수 있게 한다. 실제 실행 전 거부와 실행 여부 미확인은 별도 계수한다. 토큰별 알려진 호출 수·부분 합계·알려진 대상의 평균과 누락·오류 수를 함께 보여준다.
- 캐시·비캐시 비중과 합계는 같은 provider·범위의 비교 가능한 값으로 계산한다. input에 포함된 cache read와 output에 포함된 reasoning을 다시 더하지 않으며 청구 비용을 추측하지 않는다. 사용량·시간이 큰 목적·호출과 반복 교정을 원래 호출 로그·관련 계획으로 추적할 수 있게 한다.
- 호출 생략·성공 결과 재사용은 이유와 근거만 남기며 실제 invocation·사용량을 새로 만들지 않는다. 측정하지 않은 시간·비용 절감과 토큰만으로 불필요한 호출이라는 판단을 보고하지 않는다.
- 수집·로그·집계·조회 실패만으로 Agent 결과·작업 상태를 바꾸거나 작업을 차단·재호출하지 않는다. 수집 문제와 실제 Agent 실패를 구분한다. 필수 격리·소유권·검증 증거 저장은 유지하고, 로그에 인증 자료·비밀값·prompt·코드·문서 전문을 추가하지 않는다. 기존 호출 기록·기본 집계와 호환되며 동일 종료를 재시작 뒤 중복 기록하지 않는다.

- R-055의 삭제 확정 작업에 귀속된 호출·로그·사용량은 제거하고 조회·기간별 집계에도 반영한다. 공유 기록의 다른 작업 데이터는 보존하며 삭제한 수치를 익명 합계나 취소 감사로 유지하지 않는다.

## Acceptance Criteria

- Codex·Claude의 일회 실행·재개·fallback·교정·완료·실패·timeout·중단을 호출 식별자·목적·profile·결과·시간과 제공된 사용량으로 종료 직후 연결할 수 있다.
- 실행 전 거부·프로세스 생성 실패·실행 여부 미확인과 실제 CLI 실행이 구분되고, 모델 없는 probe와 근거 없는 legacy 행이 실제 호출·완전한 사용량으로 집계되지 않는다.
- provider별 포함 관계, turn·call·session 범위와 하위 Agent·모델별 집계를 구분한다. 중복 이벤트·부분 필드·누적 재개·reset·형식 오류에서 이중 합계·가짜 0·알 수 없는 증가분을 만들지 않는다.
- 기간·프로젝트·역할·목적·Model·Effort·session 전이로 사용량·시간·재시도·실패와 수집 누락을 조회하고, 부분 합계·평균의 알려진 대상 수와 누락 수를 함께 확인할 수 있다.
- 사용량·시간이 큰 목적·호출과 반복 교정에서 원래 호출 로그·관련 계획을 찾을 수 있고, 호출 생략·결과 재사용은 새 invocation·사용량으로 집계되지 않는다.
- 중단·재시작에서 같은 종료를 중복 기록하지 않으며 수집·로그·조회 실패가 Agent 성공·상태·필수 안전 증거에 영향을 주지 않는다. 비밀값·prompt·코드·문서 전문은 관측 로그에 추가되지 않는다.
- 실제 CLI·모델을 호출하지 않는 fixture 검증으로 두 provider, 실행 여부·사용량 범위·누락·중복·누적 reset과 기존 저장·집계의 호환성을 확인할 수 있다.

- R-055에 따른 삭제 뒤 대상 작업의 호출·사용량은 조회·집계에서 사라지고 다른 작업의 공유 사용량은 유지된다.

## Product Impact

- 실제 호출의 목적·실행 여부·사용량 범위와 수집 상태를 함께 확인한다.
- 부분 수집을 전체 사용량으로 보고하지 않고 반복 비용을 원래 호출까지 추적한다.
- 관측 실패는 작업 성공과 필수 안전 검증에 영향을 주지 않는다.

## Non-Goals

- 새 측정 서비스·Agent·상시 benchmark·외부 유료 서비스를 도입하지 않는다.
- provider가 보고하지 않은 청구 비용이나 누락 사용량을 추정하지 않는다.
- R-055의 삭제 확정 작업을 제외한 과거 기록을 삭제하거나 근거 없는 목적·실행 여부·범위를 채우지 않는다.
- 기본 사용량 파싱·ledger 보존·세션 재개 정책을 재구현하거나 격리 정책을 바꾸지 않는다.
