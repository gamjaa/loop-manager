# [R-078] 실행 중 로컬 복구 요청 접수

## Context

`recover`는 전역 실행 잠금을 먼저 요구하므로 다른 작업이 진행 중이면 로컬 환경을 고친 사용자의 요청도 접수하지 못한다. 수동 명령처럼 요청 접수와 실제 실행을 분리해 복구 요청을 보존한다.

## Requirement

- `recover <repository> [--plan <id>]`는 다른 작업 중에도 등록 대상과 현재 설정을 검증하고 요청을 저장할 수 있다. 실제 복구는 전역 실행 잠금과 기존 프로젝트 실행 자리·소유권·승인 조건을 유지한다.
- 실행 가능하면 같은 명령에서 기존 복구 경로를 사용한다. 전역 잠금이나 다른 계획·planning·유지보수의 실행 자리 때문에 대기하면 요청을 보존하고 다음 `run`에서 실행 가능한 시점에 처리한다. 현재 작업을 선점하지 않는다.
- 프로젝트별 미완료 요청은 하나이며 같은 범위의 반복 명령은 동일 요청을 재사용한다. 다른 범위는 이유를 알리고 거부한다. 중단 후에도 요청 identity, 이미 소비한 제한 재검사와 실패·교정·승격 이력을 유지한다.
- 완료는 종료 코드 0, 접수 후 대기·진행 중·미해결·입력 거부는 0이 아닌 코드로 보고한다. 대기 출력에는 대상, 요청 identity와 다음 `run`에서 이어진다는 안내를 포함한다.

## Acceptance Criteria

- 다른 작업이 전역 잠금을 보유한 상태에서 유효한 복구 요청을 저장하며 복구·Agent·대상 Git 변경을 시작하지 않는다.
- 반복 접수는 중복 요청을 만들지 않고, 다른 범위·미등록 저장소·없는 계획·잘못된 설정은 성공으로 보고하지 않는다.
- 다음 `run`은 저장된 요청 identity와 계획 범위를 기존 복구 경로에 전달한다. 다른 계획이 실행 자리를 사용하면 일반 실행을 계속하고 요청은 대기로 보존한다.
- 즉시 실행과 지연 실행 모두 실제 미해결 원인을 판정하고, 완료한 요청이나 소비한 제한 재검사를 자동으로 새 요청·시도로 반복하지 않는다.
- 요청 접수용 runtime은 자동 실행과 분리되며 원격 SHA·부모 잠금·작업 공간 소유권 검증과 자기 runtime만 정리하는 규칙을 유지한다.

## Product Impact

- 로컬 환경 복구 요청은 다른 작업 중에도 접수할 수 있고, 실제 복구는 직렬 실행 조건을 유지하며 다음 정상 실행에서 이어진다.

## Non-Goals

- 복구와 자동 Worker·verify·Review·게시의 동시 실행, 현재 작업 종료 직후 즉시 재개 보장과 별도 최우선 처리는 추가하지 않는다.
- 기존 원인별 복구·승인·차단 해제 기준과 재시도 한도를 변경하지 않는다.
