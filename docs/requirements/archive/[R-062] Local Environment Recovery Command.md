# [R-062] 로컬 환경 수정 후 복구 재검사 명령

## Context

원격 코드·문서 수정 이후의 자동 복구는 R-060, 계획별 차단과 프로젝트 안전 gate의 구분은 R-055에서 정의한다. 설정·인증·도구·권한·검증 timeout 등 로컬 환경만 고치면 원격 입력은 그대로일 수 있어, 정상 실행의 변경 감지나 기존 재시도 한도만으로 다시 검사하기 어렵다.

사용자가 로컬 문제를 수정한 뒤 선택한 작업의 재검사를 요청할 수 있는 Loop Manager 명령을 추가한다. SQLite 직접 편집과 의미 없는 원격 commit을 복구 절차로 요구하지 않는다.

## Requirement

### 명령과 대상

- `recover <repository> [--plan <id>]` 명령을 제공한다. 기존 `--state-dir` 선택을 따르며 등록된 저장소 루트를 필수로 받는다. `--plan`이 있으면 해당 계획과 그 실행에 필요한 프로젝트 환경을, 없으면 그 프로젝트의 환경과 로컬 환경 원인으로 중단된 작업·planning을 재검사한다.
- 등록되지 않은 저장소, 그 프로젝트에 없는 계획 ID와 손상되거나 찾을 수 없는 운영 상태는 이유를 알리고 거부한다. 이 명령으로 프로젝트를 새로 등록하거나 빈 SQLite로 기존 운영 상태를 대체하지 않는다.
- 기존 중복 실행 lock과 프로젝트 변경 실행 자리를 준수한다. 같은 상태 디렉터리의 다른 실행과 동시에 DB·Git·worktree를 변경하지 않으며, 다른 프로젝트의 작업이나 무관한 차단을 재시도하지 않는다.

### 재검사와 재개

- 현재 설정, 해당 원인과 관련된 인증·도구·경로·권한·timeout 및 사용 중인 저장소·작업 자원을 다시 확인한다. 원격 기준과 작업 branch는 R-060, 차단 범위는 R-055의 동일한 판정·복구 정책을 적용한다. 명령 전용의 느슨한 해제 기준을 만들지 않는다.
- 로컬 환경 원인에는 원격 OID·ExecPlan·Requirement 변경을 재검사 조건으로 요구하지 않는다. 명령 호출은 선택한 원인의 새 검사 한 번을 요청한다. 과거 한도가 소진됐어도 이 제한된 검사는 허용하되, 기존 실패·교정·승격 이력을 지우거나 모든 재시도 횟수를 초기화하지 않는다. 실패 결과를 반복 소비하며 자동으로 새 시도를 무한 생성하지 않는다.
- 현재 근거로 원인이 해소됐으면 해당 원인만 해제하고 보존된 branch·worktree·session과 단계에서 다음 정상 실행이 이어갈 수 있게 한다. Worker·verify 등 실제 실행으로 확인해야 하는 원인은 그 검사나 복구에 필요한 단계까지만 제한된 재시도를 허용한다. 아직 수행하지 않은 검증을 성공으로 기록하거나 검사 전에 모든 차단을 일괄 해제하지 않는다.
- 실패·중단 시 작업물과 미해결 원인을 보존한다. 재시작은 미완료 요청을 재구성하며 이미 완료한 재검사·해제를 중복 수행하지 않는다. 후보가 바뀌면 기존 Worker 확인·targeted test·Manager 전체 verify·읽기 전용 Review와 PR 게시 조건을 다시 만족해야 한다.
- 사용자 승인·AGENTS 변경 결정, 미충족 dependency, Merge 없이 닫힌 PR, 실제 범위 위반·소유권 불확실성과 독립 차단은 명령 호출만으로 해제하지 않는다. 일반적인 원격 수정은 이 명령 없이 정상 실행에서 자동 복구돼야 한다.

### 결과와 안내

- 재개 가능, 검사·복구 진행 중 또는 남은 원인과 필요한 사용자 조치를 프로젝트·계획·planning 단위로 출력한다. 선택한 범위의 재검사·복구가 끝나고 해당 원인이 해소됐으면 종료 코드 0, 미해결·실행 자리 대기·입력 거부·명령 실패에는 0이 아닌 값을 반환한다. 검사·복구 진행 중을 성공으로 보고하지 않는다.
- 로컬 환경 오류 안내에는 실제 수정 대상과 수정 후 사용할 명령을 포함한다. 설정을 읽기 전 발생한 시작 오류도 파일·형식 등 확인 가능한 원인을 알리고, 수정 후 같은 명령을 다시 실행할 수 있어야 한다. 성공 판정을 위해 설정 검사를 건너뛰지 않는다.
- 호출 범위, 검사 결과와 원인별 해제·미해결 결과를 감사 기록에 남긴다. 상태 원본은 SQLite이며 결과를 ExecPlan frontmatter에 쓰지 않는다. 출력·로그·원격 진단에 인증 정보나 비밀값을 노출하지 않는다.

## Acceptance Criteria

- 사용자는 로컬 설정·인증·도구·권한 문제를 수정한 뒤 명령으로 해당 원인을 재검사하고, 원격 commit이나 직접 SQLite 수정 없이 보존된 작업을 재개할 수 있다.
- timeout 등 실제 실행으로 확인해야 하는 환경 수정은 기존 한도 소진 뒤에도 선택 범위의 제한된 새 검사로 확인할 수 있다. 아직 실패하는 원인은 유지되고 이력 삭제·일괄 한도 초기화·무한 재시도는 발생하지 않는다.
- 프로젝트 단위와 계획 단위 선택이 서로 다른 대상에 영향을 주지 않는다. 개별 계획 문제는 독립 계획을 막지 않으며 실제 공유 안전 문제는 계속 거부한다.
- 승인 대기·dependency·닫힌 PR·실제 소유권 문제를 로컬 복구 명령으로 우회하지 않는다. 변경된 후보는 필요한 검증·Review를 다시 통과해야 한다.
- 실행 중인 다른 Manager와 동시에 운영 상태나 작업 공간을 변경하지 않는다. 미완료 복구의 중단·재시작에서 작업·session·실패 기록을 보존하고 완료된 처리를 중복하지 않는다.
- 잘못된 대상·손상된 설정·없는 운영 상태와 미해결 원인은 정확한 결과와 0이 아닌 종료 코드로 확인할 수 있다. 설정 수정 후 재호출이 가능하고 비밀값이 출력되지 않는다.
- 원격 사용자 수정만으로 해결되는 작업은 명령 없이 다음 정상 실행에서 자동 복구된다. 사용 안내는 원격 자동 복구와 로컬 환경 수정 후 재검사를 구분한다.

## Product Impact

- 원격 변경 없이 로컬 환경을 수정한 사용자가 선택한 작업의 복구 재검사를 요청할 수 있다.
- 복구 명령은 실제 해소된 원인만 처리하며 기존 작업·이력·승인·검증 조건을 보존한다.

## Non-Goals

- 수동 SQL 수정, 강제 unblock·reset·clean, 자동 승인·PR Merge 또는 새 복구 서비스·Agent 역할을 추가하지 않는다.
- R-055의 전수 조사와 R-060의 Git 통합·원격 보존 정책을 별도 정책으로 재정의하지 않는다.
- 명령 실행으로 모든 프로젝트의 일반 작업을 시작하거나 무관한 실패의 재시도 한도를 초기화하지 않는다.
