# [R-087] 문서 보고 교정 반복 제한

## Summary

선택된 ExecPlan을 제외한 변경 문서 전체의 보고 누락·형식·hash 오류를 검증 실행·재사용 판단 전에 한 번에 교정하고 게시 직전 최종 diff 검사도 유지한다. 선택된 ExecPlan의 보고 제출 의무만 제외하고 기존 diff 검토·범위 검증은 유지한다. 같은 후보·명세·base의 동일 오류는 시각·진단 경로·세션 변화와 무관하게 기존 한도로 누적한다. PR 문서 보고에는 파일명·요약·이유·영향만 표시하고 발췌·patch·diff 링크·hash는 넣지 않되 실제 검증 근거는 유지한다.

## Context

같은 구현 후보가 검증과 Review를 통과해도 Worker가 변경 문서의 설명을 번갈아 누락하면 게시 교정이 반복된다. 검증 출력의 시각과 진단 경로 변화가 동일 오류의 반복 횟수를 초기화해 교정 한도도 적용되지 않는다.

## Requirement

최종 후보에서 선택된 ExecPlan을 제외한 모든 변경 문서의 보고 누락·형식 오류·hash 불일치를 한 번에 전달한다. 교정 Worker는 최종 응답의 PR_SUMMARY에 보고 대상 문서 전체의 DOCUMENT_CHANGE를 함께 제출한다. 선택된 ExecPlan은 PR 문서 변경 요약과 DOCUMENT_CHANGE 제출 대상에서 제외하고 이전 Worker 결과에 남은 해당 경로의 보고도 무시한다. 기존 diff 검토·범위 검증과 PR의 ExecPlan 링크·Purpose는 유지한다. 후보와 base를 확정한 뒤 검증 실행·재사용 판단 전에 보고를 검사하고, 게시 직전 최종 diff/hash 검사도 유지한다.

PR 본문의 문서 보고에는 파일명·변경 요약·이유·영향만 포함한다. 실제 변경 내용의 발췌·전체 patch·diff 링크·검증용 hash는 본문에 넣지 않는다. 추가·삭제·rename의 대상 문서는 파일명으로 식별하며 검증에는 계속 실제 최종 diff와 hash를 사용한다.

동일 후보·명세 입력·base에서 같은 Worker 보고 오류는 검증 출력의 시각·진단 경로나 Agent 세션 변화와 무관하게 누적해 기존 교정 한도에서 차단한다. 실제 후보나 명세 입력·base 변경은 새 입력으로 구별한다. 보고만 수정해도 기존 입력 증명·receipt·검증 및 Review gate를 거치며 이전 PASS를 무조건 재사용하지 않는다.

## Acceptance Criteria

- PRODUCT와 ARCHITECTURE를 함께 변경한 후보는 두 문서의 유효한 보고가 함께 있으면 통과한다.
- 선택된 ExecPlan만 변경한 후보는 DOCUMENT_CHANGE 없이 문서 보고 검사를 통과하고 PR에 별도 문서 변경 요약을 표시하지 않는다. 다른 문서도 변경한 후보는 그 문서의 보고를 계속 요구하며 선택된 ExecPlan의 기존 diff 검토·범위 검증과 PR의 링크·Purpose는 유지한다.
- 여러 보고 누락·hash 불일치·형식 오류는 한 응답에 전체 대상 경로와 현재 patch hash를 포함한다.
- 보고가 누락된 후보는 전체 verify와 Review를 실행하기 전에 Worker 교정으로 돌아간다.
- 시간·진단 경로만 바뀐 검증 출력과 세션 변화는 동일 오류 횟수를 초기화하지 않으며 기본 한도 3에서 차단한다.
- 실제 후보·명세 입력·base 변경은 새 반복 횟수로 시작한다.
- 게시 직전 검사와 기존 검증 입력 증명·성공 receipt·Review gate는 유지한다.
- PR 문서 보고는 파일명·변경 요약·이유·영향만 표시하며 실제 변경 내용·patch·diff 링크·hash는 포함하지 않는다.

## Product Impact

문서 보고 교정이 전체 검증을 불필요하게 반복하거나 기존 교정 한도를 회피하지 않는다.

## Non-Goals

- 운영 상태 DB 수동 수정, 검증 gate 우회, 실행 중인 runtime 교체는 포함하지 않는다.
