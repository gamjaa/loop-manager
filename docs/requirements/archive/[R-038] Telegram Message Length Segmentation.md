# [R-038] Telegram Message Length Segmentation

## Context

Loop Manager는 현재 알림 한 건의 본문을 Telegram `sendMessage` 요청 한 번으로 전송한다. BLOCKED 원인과 수정 대상처럼 본문이 길어지면 Telegram의 메시지 길이 한도 때문에 알림 전체가 실패할 수 있다. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)는 `sendMessage`의 `text`를 entity 해석 후 1~4096자로 제한한다. 기존 outbox는 논리적 알림 한 건의 전송 성공 여부만 기록하므로, 여러 조각 중 일부만 전송된 경우에도 재시도 범위를 구분해야 한다.

## Requirement

Loop Manager는 Telegram으로 보낼 알림 본문이 한도를 넘으면 원문을 순서대로 최대 4096자 단위의 일반 텍스트 메시지로 나눠 전송한다. 한도 이하의 본문은 기존처럼 메시지 한 건으로 전송한다. 각 조각은 Telegram이 검사하는 길이 한도 안에 있어야 하며, 조각을 순서대로 이어 붙이면 원래 알림 본문과 정확히 같아야 한다. 임의 축약, 누락, 문자 손상 또는 빈 조각 전송은 허용하지 않는다.

분할된 메시지는 한 논리적 알림으로 취급한다. 앞 조각의 전송 성공을 확인한 뒤 다음 조각을 보내고, 모든 조각이 성공했을 때만 알림을 완료 처리한다. 중간 조각이 실패하면 뒤 조각은 보내지 않고, 다음 실행에서 이미 성공이 확인된 조각은 건너뛰어 실패한 조각부터 재시도한다. 프로세스 중단 등으로 특정 조각의 실제 수신 여부를 확인할 수 없는 경우에는 기존 outbox의 불확실한 전송 재시도 원칙을 적용하되, 성공이 확인된 조각을 다시 보내거나 미전송 조각을 건너뛰지 않는다.

PR 생성 직후 전송과 일반 pending 전송을 포함한 모든 Telegram 알림에 같은 한도·분할·재시도 규칙을 적용한다. 분할 전송 실패는 기존처럼 프로젝트 작업 상태를 변경하지 않으며, 자격 증명과 본문을 오류 로그에 노출하지 않는다. Telegram이 비활성화된 경우에는 기존처럼 전송하지 않는다.

분할된 BLOCKED 알림의 일부 조각이 도착한 뒤 차단이 해제되면, 미전송 조각은 오래된 차단 알림으로 취급해 보내지 않는다. 이미 조각을 받은 사용자는 차단을 통지받은 것으로 보아, 해당 작업이 실제로 재개될 때 기존 재개 알림 규칙을 적용한다.

## Acceptance Criteria

- 알림 본문이 한도 이하이면 기존과 동일한 본문으로 `sendMessage`를 한 번 호출한다.
- 한도를 넘는 본문은 순서가 유지된 여러 `sendMessage` 호출로 전송되며, 각 조각의 길이는 Telegram 한도 이하이고 가능한 한 한도 단위로 분할된다. 모든 조각을 이어 붙인 내용은 원문과 같다.
- 한도 경계와 바로 다음 문자에서 한 조각 또는 두 조각으로 정확히 나뉘며, 한글·이모지·줄바꿈을 포함해도 문자가 손상되거나 빠지지 않는다.
- 두 번째 이후 조각이 실패하면 알림은 pending으로 남고 뒤 조각은 전송되지 않는다. 다음 실행에서는 성공이 확인된 앞 조각을 중복 전송하지 않고 실패한 조각부터 순서대로 보낸다.
- 마지막 조각까지 성공한 뒤에만 논리적 알림 한 건이 완료로 기록되며, 같은 사건을 다시 관측해도 새 알림이나 조각을 중복 생성하지 않는다.
- BLOCKED 알림의 일부 조각만 전송된 뒤 차단이 해제되면 남은 차단 조각은 전송하지 않고, 이미 전송된 조각을 근거로 실제 작업 재개 시 재개 알림을 한 번 보낸다.
- PR 생성 직후 전송과 일반 pending 전송, 기존 및 이후 추가되는 알림 유형에 동일한 규칙이 적용된다.
- 일부 조각의 실패·중단 또는 Telegram 비활성화가 Worker·Planner·PR·프로젝트 완료 상태를 바꾸지 않고, 전송 오류 기록에 token·chat ID·알림 본문이 노출되지 않는다.

## Product Impact

- 긴 Telegram 알림도 내용 손실 없이 여러 메시지로 수신하고, 실패한 나머지는 이후 실행에서 이어서 받는다.

## Non-Goals

- 알림 내용을 요약하거나 길이에 맞춰 잘라 버리지 않는다.
- Telegram 외의 전송 채널이나 메시지 서식 기능은 추가하지 않는다.
- Telegram이 성공 응답을 보낸 직후 기록 전에 프로세스가 중단된 경우까지 외부 전송의 정확히 한 번 수신을 보장하지 않는다.
