# [R-034] Notified Block Resumption Alert

## Context

Loop Manager는 사용자 조치가 필요한 차단을 알린다. 이후 차단 원인이 해결돼 작업을 다시 시작하더라도, 앞서 차단 알림을 받은 사용자는 정상 실행이 재개됐는지 알기 어렵다. 자동 복구 실패뿐 아니라 guidance 승인 대기, 닫힌 PR과 계획 오류도 해제 후 정상 작업으로 돌아갈 수 있다. 단순한 일시 오류, 아직 알리지 않은 차단과 다른 독립 계획의 진행까지 재개 알림으로 취급하면 알림이 중복된다.

## Requirement

Loop Manager는 원인과 관계없이 기존 BLOCKED 알림의 전송 성공이 기록된 차단 사건이 해제되고 정상 작업이 재개되면 한 번 알린다. `PLAN_BLOCKED`는 해당 ExecPlan의 Worker 작업 또는 재개된 PR 처리가 시작될 때, `PROJECT_BLOCKED`는 안전 gate 해제 뒤 프로젝트의 정상 작업이 시작될 때 알린다. `planning_error`처럼 BLOCKED로 알린 계획 중단도 Planner가 다시 시작할 때 같은 규칙을 적용한다. 차단 기록만 해제됐거나 다른 독립 계획만 진행한 시점에는 알리지 않는다.

재개 알림에는 프로젝트, 차단 scope와 관련 ExecPlan, 앞서 알린 차단 원인 및 실제 재개한 작업을 담는다. 사용자 수정으로 해결됐을 수도 있으므로 자동 복구가 성공했다고 단정하지 않는다. 같은 차단 사건의 반복 실행·프로세스 재시작은 알림을 다시 만들지 않으며, 재개 뒤 별개의 차단이 발생해 사용자에게 다시 알려진 경우에만 새로운 재개 사건이 될 수 있다.

차단 알림의 전송 성공 기록이 없거나 Telegram이 비활성화된 경우에는 재개 알림을 만들지 않는다. 분할된 차단 알림은 한 조각이라도 전송에 성공해 사용자에게 표시됐으면 통지된 차단으로 취급한다. 차단이 해제되기 전에 전송되지 못한 오래된 차단 알림의 나머지 조각을 뒤늦게 보내 현재도 차단 중인 것처럼 오인시키지 않아야 한다. 사용자 승인 대기, 닫힌 PR과 자동 복구 실패는 모두 같은 재개 알림 규칙을 따른다. 알림은 기존 전송·재시도 경로를 사용하며 실행 상태나 작업 선택을 바꾸지 않는다.

## Acceptance Criteria

- BLOCKED 알림의 전송 성공이 기록된 뒤 해당 차단이 해제되고 정상 작업이 시작되면 원인에 관계없이 재개 알림이 한 번 생성된다. guidance 승인 해제, 닫힌 PR 재개, 자동 복구 실패 해제와 `planning_error` 해제를 포함한다.
- `PLAN_BLOCKED` 해제 뒤 해당 계획의 Worker나 PR 처리가 아직 시작하지 않았거나 다른 독립 계획만 실행 중이면 그 계획의 재개 알림을 만들지 않는다. `PROJECT_BLOCKED`와 `planning_error` 해제 뒤에도 해당 정상 작업 시작 전에는 만들지 않는다.
- 재개 알림에 이전 차단의 프로젝트·scope·관련 ExecPlan·원인과 새로 시작한 작업을 표시하며, 해결 주체나 자동 복구 성공 여부를 추측하지 않는다.
- 같은 차단 사건의 반복 실행·재시작·전송 재시도는 재개 알림을 중복 생성하지 않는다. 재개 뒤 별도로 알린 새 차단은 독립 사건으로 처리한다.
- 일시 오류와 전송 성공 기록이 없는 차단에는 재개 알림을 만들지 않는다. 차단 해제 전에 미발송 상태였던 차단 알림은 뒤늦게 전송하지 않는다.
- 분할된 BLOCKED 알림의 일부 조각이 성공한 뒤 차단이 해제되면 미전송 조각은 폐기하고, 해당 작업이 실제로 재개될 때 한 번 알린다.
- Telegram 비활성화나 알림 전송 실패는 차단 해제와 정상 작업 시작을 막지 않으며, 상태와 로그에서 재개 사실을 확인할 수 있다.

## Product Impact

- 사용자에게 알린 차단의 원인과 관계없이 해당 작업이 실제로 재개되면 한 번 알린다.

## Non-Goals

- 재개 알림을 위해 차단 해제 조건, 복구 절차 또는 작업 우선순위를 변경하지 않는다.
- 실제 작업 재개 전의 단순 차단 해제나 일시 오류 회복에는 알림을 추가하지 않는다.
- 새 알림 서비스나 별도 감시 프로세스를 도입하지 않는다.
