# [R-080] Git Mock Defaults for Tests

## Context

Loop Manager 자체 테스트는 상태·정책의 조건 조합을 검사할 때도 Git 저장소 생성과 관측을 반복해 verify 비용이 커지고 있다. Git 관측값만으로 판단을 검증할 수 있는 테스트는 mock을 사용하고, 실제 Git 동작이 검증 대상인 회귀에 실행 비용을 집중해야 한다.

## Requirement

Loop Manager 자체 테스트의 Git 호출은 mock을 기본으로 한다. 실제 Git 실행은 mock으로 확인할 수 없는 Git 동작이나 프로세스 연결 계약을 검증하는 데 필요한 경우에만 허용하며, 테스트에서 그 필요성이 드러나야 한다. 통합 테스트라는 분류나 기존 fixture의 편의만으로 실제 Git을 실행하지 않는다.

상태 전이·재시도·차단·복구 정책은 정상·실패·중단·관측값 변화의 입력을 mock으로 재현하고 실제 운영 판단과 저장 결과를 검증한다. 필요한 SQLite·파일 보존 검증은 유지하며, 판단 결과 자체를 mock의 성공값으로 대체하지 않는다.

기존 실제 Git 테스트를 전환할 때 검증 조건과 assertion의 대응을 유지한다. 실제 충돌·rebase·index·worktree·원격 lease와 bootstrap의 부모/자식·runtime 연결처럼 실제 효과를 확인해야 하는 계약은 필요한 통합 회귀로 남긴다. 같은 계약의 조건 조합은 mock으로 검증할 수 있는 범위에서 분리한다.

새 테스트와 기존 시나리오의 확장은 확인할 계약에 필요한 준비·실행·재개만 수행한다. 공통 연결 동작마다 역할·브랜치·오류의 모든 조합을 전체 실행으로 반복하지 않으며, 조합에 따른 판단은 실제 상태·저장 로직을 사용하는 mock 테스트로 검사한다. 실제 연결에 영향을 주는 조건의 상호작용은 통합 회귀로 유지한다. 중단 후 재개가 확인되면 해당 테스트를 끝내고, 그 뒤의 교정 소진·차단·게시가 별도 검증 대상이면 전용 테스트에 맡긴다. 기존 assertion을 이동하거나 실행 횟수를 줄일 때는 그 조건을 계속 검사하는 테스트의 대응을 확인한다.

## Acceptance Criteria

- Git 관측값으로 판정 가능한 상태·정책 테스트는 Git 프로세스를 실행하지 않고 실제 판단·상태 전이·저장 결과를 검사한다.
- mock으로 성공·실패·오류와 연속 관측 사이의 값 변화를 재현하며, 실패·예상 밖 입력이 일괄 성공 처리로 숨겨지지 않는다.
- 실제 Git을 사용하는 테스트는 mock으로 확인할 수 없는 동작 또는 연결 계약과 그 assertion을 확인할 수 있다.
- 전환 전후 검증 조건의 대응을 확인할 수 있고, 필수 Git 통합 회귀와 격리·실패 시 보존·중단 후 재개 검증이 유지된다.
- 전체 verify에 전환한 테스트와 필요한 통합 회귀가 포함되며, 테스트 skip·timeout 확대·수집 범위 축소로 비용 감소를 대신하지 않는다.
- 새 실제 Git·CLI 실행과 시나리오 조합에는 검증할 계약·효과 및 기존 테스트로 충족되지 않는 이유가 드러나며, 재개 이후의 불필요한 교정·차단·게시와 같은 계약의 반복 실행을 추가하지 않는다.

## Product Impact

자체 verify의 필수 회귀 검증을 유지하면서 불필요한 Git 실행 비용을 줄인다. 설계 경계는 [ARCHITECTURE.md](../ARCHITECTURE.md#검증과-재시도)를 따른다.

## Non-Goals

- 운영 코드의 실제 Git 실행·소유권·원격 lease·복구 정책 변경.
- 다른 등록 프로젝트의 테스트 프레임워크 일괄 변경.
- 실제 Git·SQLite·운영체제의 효과 검증을 전부 mock으로 대체하거나 전체 verify를 생략하는 변경.
