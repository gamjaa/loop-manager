# [R-080] Git Mock Defaults for Tests

## Summary

자체 테스트의 상태·정책 조합은 Git 관측을 mock으로 제공해 실제 판단·SQLite·파일 보존 결과를 검사하고, 실제 Git·CLI는 그 효과나 연결 계약을 확인해야 할 최소 회귀에 사용한다. assertion과 실패·중단·재개 조건을 유지하고 불필요한 조합·재개 후 반복을 줄인다. 실제 Git fixture는 seed부터 자식까지 사용자 설정·template에서 격리하며 비용 감소를 검증 범위 축소로 대신하지 않는다.

## Context

Loop Manager 자체 테스트는 상태·정책의 조건 조합을 검사할 때도 Git 저장소 생성과 관측을 반복해 verify 비용이 커지고 있다. Git 관측값만으로 판단을 검증할 수 있는 테스트는 mock을 사용하고, 실제 Git 동작이 검증 대상인 회귀에 실행 비용을 집중해야 한다.

[테스트 시간 절감 분석](chatgpt-conversation://6ac824ad-6efc-83e8-b289-d5654a16670a)의 `f810c75ca520c4c1869225be88c1edb7bad10d9c` Linux 표본은 verify 실패 4회 테스트의 Git 1,241회·2.89초, Planner 동일 입력 skip gate의 591회·1.45초, Worker 결과 오류/session 재개의 544회·1.32초와 역할·경로 테스트 5개의 386회·1.16초를 기록했다. Python 3.12.14·Git 2.51.1에서 수집·모듈 import를 제외한 한 번의 측정이며 현재 Windows의 병목 비중·절감률로 사용하지 않는다.

기존 [G-222](../plans/%5BG-222%5D%20계획%20catalog%20유지보수%20정책%20테스트의%20Git%20관측%20분리.md)·[G-223](../plans/%5BG-223%5D%20실행%20검증%20복구%20정책%20테스트의%20Git%20관측%20분리.md)·[G-224](../plans/%5BG-224%5D%20등록%20runtime%20격리%20테스트의%20Git%20관측%20분리.md)의 전환 범위를 재사용한다. 역할·경로 판정과 반복 verify 실패를 대표 대상으로 삼고 이후 실제 느린 모듈 자료로 대상을 선택한다. 기존 작업의 진행 기록이나 문서 변경만으로 전환 완료를 선언하지 않는다. 배정·최초 import와 가드·임시 경로 개선은 각각 [R-065](%5BR-065%5D%20실제%20부하%20기반%20verify%20병렬%20실행.md)·[R-067](%5BR-067%5D%20프로젝트%20공통%20verify%20실행%20규약.md)의 범위다.

## Requirement

현재 코드와 명세를 기준으로 불필요해진 자체 테스트를 조사하고 제거한다. 폐기된 동작만
검사하는 테스트와 다른 테스트가 동일 조건·assertion을 모두 보장하는 중복 테스트를 구분하고,
제거 근거와 남은 회귀 검증의 대응을 확인한다. 참조가 없어진 전용 fixture·helper도 정리한다.
현재 지원하는 호환성·정상·실패·보안·데이터 보존·실제 외부 연동 계약의 검증은 유지하며,
실패하거나 느리다는 이유만으로 삭제·skip·assertion 약화를 하지 않는다.

Worker는 현재 작업과 관련된 불필요한 테스트를 발견하면 같은 변경에서 정리하고 남은 관련
테스트로 검증한다. 유지보수 Planner도 같은 기준으로 조사해 제거 대상·근거·남길 검증을
기존 비종료 계획이나 허용된 mode의 새 ExecPlan에 연결하며 테스트는 직접 수정하지 않는다.
공통·역할별 실행 지침에 이 기준과 권한 경계를 반영한다.

Loop Manager 자체 테스트의 Git 호출은 mock을 기본으로 한다. 실제 Git 실행은 mock으로 확인할 수 없는 Git 동작이나 프로세스 연결 계약을 검증하는 데 필요한 경우에만 허용하며, 테스트에서 그 필요성이 드러나야 한다. 통합 테스트라는 분류나 기존 fixture의 편의만으로 실제 Git을 실행하지 않는다.

상태 전이·재시도·차단·복구 정책은 정상·실패·중단·관측값 변화의 입력을 mock으로 재현하고 실제 운영 판단과 저장 결과를 검증한다. 필요한 SQLite·파일 보존 검증은 유지하며, 판단 결과 자체를 mock의 성공값으로 대체하지 않는다.

기존 실제 Git 테스트를 전환할 때 검증 조건과 assertion의 대응을 유지한다. 실제 충돌·rebase·index·worktree·원격 lease와 bootstrap의 부모/자식·runtime 연결처럼 실제 효과를 확인해야 하는 계약은 필요한 통합 회귀로 남긴다. 같은 계약의 조건 조합은 mock으로 검증할 수 있는 범위에서 분리한다.

새 테스트와 기존 시나리오의 확장은 확인할 계약에 필요한 준비·실행·재개만 수행한다. 공통 연결 동작마다 역할·브랜치·오류의 모든 조합을 전체 실행으로 반복하지 않으며, 조합에 따른 판단은 실제 상태·저장 로직을 사용하는 mock 테스트로 검사한다. 실제 연결에 영향을 주는 조건의 상호작용은 통합 회귀로 유지한다. 중단 후 재개가 확인되면 해당 테스트를 끝내고, 그 뒤의 교정 소진·차단·게시가 별도 검증 대상이면 전용 테스트에 맡긴다. 기존 assertion을 이동하거나 실행 횟수를 줄일 때는 그 조건을 계속 검사하는 테스트의 대응을 확인한다.

실제 Git을 사용하는 테스트 저장소의 명령은 사용자 global/system 설정과 초기화 template의 우연한 영향을 받지 않도록 테스트 범위에서 격리한다. hooks·commit signing·filters·fsmonitor 등 필요한 설정은 명시적인 테스트 입력으로 제공한다. 설정 상속 자체가 검증 대상이면 격리된 입력 환경을 구성해 실제 상속 동작을 검사한다. 격리는 fixture의 최초 seed 생성부터 후속 Git 명령과 필요한 자식에 적용하며 사용자 설정 파일과 운영 checkout의 설정·환경을 수정하지 않는다.

기존 fixture·관측 경계를 재사용하며 실제 판단·저장 함수를 성공 mock으로 대체하지 않는다. 반복 verify 실패처럼 반복 횟수가 계약이면 횟수·session·실패 이력·Reviewer no-call·최종 차단 assertion을 유지한다. 비용 비교는 R-065의 같은 환경·범위 측정 기준을 따르며 Git 호출 감소·국소 시간 변화·전체 경과 시간을 각각 보고한다.

## Acceptance Criteria

- 제거한 테스트마다 현재 명세·구현에서 불필요한 이유와 유지되는 검증의 대응을 확인할 수 있으며, 필요한 회귀 검증과 무관한 테스트는 보존된다.
- Worker가 작업 관련 불필요한 테스트를 정리하고 유지보수 Planner가 같은 기준의 정리 작업을 계획하도록 공통·역할별 지침이 제공된다.
- Git 관측값으로 판정 가능한 상태·정책 테스트는 Git 프로세스를 실행하지 않고 실제 판단·상태 전이·저장 결과를 검사한다.
- mock으로 성공·실패·오류와 연속 관측 사이의 값 변화를 재현하며, 실패·예상 밖 입력이 일괄 성공 처리로 숨겨지지 않는다.
- 실제 Git을 사용하는 테스트는 mock으로 확인할 수 없는 동작 또는 연결 계약과 그 assertion을 확인할 수 있다.
- 전환 전후 검증 조건의 대응을 확인할 수 있고, 필수 Git 통합 회귀와 격리·실패 시 보존·중단 후 재개 검증이 유지된다.
- 전체 verify에 전환한 테스트와 필요한 통합 회귀가 포함되며, 테스트 skip·timeout 확대·수집 범위 축소로 비용 감소를 대신하지 않는다.
- 새 실제 Git·CLI 실행과 시나리오 조합에는 검증할 계약·효과 및 기존 테스트로 충족되지 않는 이유가 드러나며, 재개 이후의 불필요한 교정·차단·게시와 같은 계약의 반복 실행을 추가하지 않는다.
- 격리된 사용자 입력의 hook·서명·template 등이 기본 fixture에 개입하지 않고 명시적인 설정 테스트에는 적용된다. seed·후속 명령·필요한 자식의 격리를 확인하며 사용자 설정 파일과 운영 checkout의 설정·환경은 변하지 않는다.

## Product Impact

자체 verify의 필수 회귀 검증을 유지하면서 불필요한 Git 실행 비용을 줄인다. 설계 경계는 [ARCHITECTURE.md](../ARCHITECTURE.md#검증과-재시도)를 따른다.

## Non-Goals

- 운영 코드의 실제 Git 실행·소유권·원격 lease·복구 정책 변경.
- 다른 등록 프로젝트의 테스트 프레임워크 일괄 변경.
- 실제 Git·SQLite·운영체제의 효과 검증을 전부 mock으로 대체하거나 전체 verify를 생략하는 변경.
- 사용자 Git 설정 변경과 새 전역 cache·runner·범용 fixture 체계 도입.
