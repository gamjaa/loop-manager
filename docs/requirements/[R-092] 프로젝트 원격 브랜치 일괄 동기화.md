# [R-092] 프로젝트 원격 브랜치 일괄 동기화

## Summary

프로젝트의 전체 원격 branch 동기화에서 branch별 네트워크 조회·fetch를 일괄 처리해 branch 수에 따른 대기를 줄인다. 실제로 받은 branch별 commit과 현재 ref를 확인하고 기존 Manager Git journal·자원 잠금·중단 복구를 유지한다. 조회 뒤 일반 branch가 삭제되면 제한 재조회로 이어가되 필수 base 부재와 조회 실패를 구분하며, 사용자 checkout·다른 ref·태그·기존 작업 이력을 보존한다.

## Context

현재 `remote_base()`는 원격 branch 목록을 조회한 뒤 각 branch에 `_recorded_base_fetch()`를 순차 호출한다. 이 함수는 branch마다 원격 OID를 다시 조회하고, 추적 ref와 OID가 다르면 객체를 fetch한 뒤 기록된 ref 전이로 반영한다. 변경이 없어 실제 fetch를 생략하는 실행도 원격 조회는 branch 수만큼 반복한다. 이 동작은 프로젝트 준비의 `reconcile_catalog_and_cleanup` 단계에 포함돼 catalog 처리와 같은 경과 시간으로 표시된다.

일반 `git fetch origin`으로 대체하면 사용자 refspec에 따른 ref 변경이 기존 Manager 기록 절차보다 먼저 발생할 수 있다. 필요한 개선은 네트워크 왕복의 일괄화이며, 실제 Git 전이의 소유권·중단 복구와 원격 입력 검증은 유지해야 한다.

## Requirement

### 일괄 동기화와 원격 입력

- 프로젝트 전체 원격 branch 동기화는 branch별 원격 조회·fetch를 반복하지 않는다. 정상적인 한 번의 동기화에서는 전체 원격 branch 목록을 한 번 조회하고, 객체 수신이 필요하면 하나의 fetch로 모아 받는다. 변경과 미완료 적용이 없으면 객체 수신을 생략할 수 있다.
- 원격 목록의 정확한 ref와 OID를 검증하고, 객체 수신 시 실제로 받은 branch별 commit을 대조한 뒤 해당 ref 전이를 적용한다. 복수 branch의 수신 결과를 단일 `FETCH_HEAD` commit으로 대신하거나, 이전 실패 호출의 수신 결과를 성공 근거로 재사용하지 않는다.
- 동기화 결과로 채택하는 base는 검증한 원격 commit이다. 로컬 base·사용자 checkout 또는 오래된 추적 ref를 확인되지 않은 원격의 대체 입력으로 사용하지 않는다.
- branch 수가 늘어도 명령줄 길이 제한 때문에 동기화가 실패하거나 branch별 네트워크 호출로 되돌아가지 않아야 한다.

### 삭제·관측 경쟁·실패

- 목록 조회 뒤 필수 base가 아닌 branch가 삭제돼 객체 수신이 실패하면, 원격 목록을 다시 확인해 삭제와 조회 실패를 구분한다. 삭제가 확인된 일반 branch는 이번 동기화 대상에서 제외하고 기존 추적 ref와 저장 PR head·작업 기록을 보존한 채 나머지 branch를 일괄 동기화한다.
- 원격 조회 또는 수신 결과에서 필수 base의 부재·삭제가 확인되면 해당 원격 입력 준비를 실패로 처리하고 기존 작업을 보존한다. 일반 branch 삭제 허용으로 필수 base의 부재를 숨기지 않는다. 전체 동기화 대상에서 제외하는 판단은 [R-055](%5BR-055%5D%20차단%20경로%20전수%20조사와%20불필요한%20작업%20중단%20축소.md)의 원격 작업 branch 삭제·재시작 정책을 대체하지 않는다.
- 조회와 객체 수신 사이에 branch별 OID가 달라지면 서로 다른 관측을 섞어 ref를 확정하지 않는다. 삭제 또는 관측 경쟁에 대한 전체 재조회·일괄 수신 재시도는 최초 시도 뒤 한 번으로 제한하고, 계속 변하면 기록을 보존해 다음 실행에서 재관측할 수 있게 한다. 이를 Agent 접근 위반이나 영구적인 소유권 오류로 바꾸지 않는다.
- 인증·통신·명령 실패와 잘못되거나 중복된 ref·OID 응답을 branch 부재로 취급하지 않는다. 유효한 수신 결과를 확인하지 못한 시도는 ref 반영과 catalog 소비로 진행하지 않으며, 실제 실패 진단을 보존한다.

### Git 자원·기록·사용자 작업 보존

- 객체 수신 결과 확인과 ref 반영에는 기존 공유 Git 자원 잠금과 ref별 예상 이전 값 검사를 적용한다. 같은 repository의 `FETCH_HEAD`를 쓰고 읽는 다른 Manager fetch 경로도 수신·결과 확보를 같은 잠금 경계에서 수행해 서로의 결과를 덮어쓰지 않는다. 다른 Manager 작업이나 외부 Git 작업이 현재 대상 ref를 바꿨으면 그 값을 강제로 덮어쓰지 않는다.
- ref 변경은 기존 Manager Git journal의 intent·소유 표식·실제 결과 확정·중단 복구 계약을 유지한다. 일괄 수신 자체를 모든 ref 변경의 완료 근거로 삼지 않는다. 여러 ref 반영 중 중단되면 완료한 전이를 보존하고 미완료 전이부터 재개한다.
- 다른 작업의 fetch 잠금 경합은 일시적인 재시도로 남긴다. 같은 원격 관측을 처리 완료·최종 거부로 소비해 후속 복구를 막지 않는다.
- 변경 없는 ref와 전체 원격 OID가 같다는 이유로 기존 미확정 journal의 복구를 건너뛰지 않는다. 변경 전 버전에서 남긴 미완료 fetch도 실제 현재 상태와 기존 기록을 대조해 재개하며 완료한 ref 쓰기를 반복하거나 성공 기록을 합성하지 않는다.
- 사용자 설정의 fetch refspec·prune·tag·submodule·파생 HEAD 정책 때문에 대상 밖 ref·태그·다른 repository를 변경하지 않는다. 원격에서 사라진 branch의 추적 ref를 이번 최적화로 자동 삭제하지 않으며, 기본 checkout과 다른 worktree의 파일·index·HEAD·로컬 branch를 보존한다.
- [R-056](%5BR-056%5D%20원격%20기준을%20유지하는%20비차단%20로컬%20base%20동기화.md)의 원격 기준과 별도 로컬 동기화, [R-091](%5BR-091%5D%20프로젝트%20공정%20배정과%20우선순위%20기반%20병렬%20작업.md)의 병렬 실행·공유 자원 보호를 유지한다. 단일 branch를 반드시 받아야 하는 bootstrap·게시·작업별 복구 경로의 대상·삭제 판정·완료 조건은 확대하지 않는다.

## Acceptance Criteria

- 원격 branch 수와 변경된 branch 수를 달리한 mock 관측에서 정상 전체 동기화의 원격 목록 조회가 1회이고, 실제 객체 수신은 필요할 때 최대 1회임을 확인한다. 변경 없는 실행은 branch별 원격 재조회를 하지 않으며 기존 미완료 journal도 누락하지 않는다.
- 서로 다른 OID의 복수 branch와 새 branch를 한 번에 수신하고, 정확한 branch별 commit 검증 뒤 해당 추적 ref만 반영한다. 수신 결과 누락·중복·잘못된 OID·관측 OID 변경과 명령 실패 뒤 남은 `FETCH_HEAD`를 성공으로 수용하지 않는다.
- 조회 뒤 일반 PR branch 삭제는 제한된 전체 재조회·일괄 수신으로 진행하고 해당 추적 ref·저장 PR head를 보존한다. 필수 base의 최초 부재·조회 뒤 삭제와 인증·통신 실패는 성공 처리하지 않는다. 반복 경쟁은 실행별 한도 안에서 종료하고 다음 실행에서 재관측한다.
- 객체 수신 후 ref 반영 전, 일부 ref 반영 뒤, ref 쓰기 후 결과 기록 전에 각각 중단해도 이미 완료한 효과를 반복하지 않고 기존 journal로 재개한다. 이전 버전의 미완료 기록과 원격 변경 없는 재개도 포함한다.
- fetch 자원 또는 대상 ref를 다른 작업이 점유한 경우 인수하거나 강제로 갱신하지 않는다. 단일 branch 복구와 일괄 수신이 겹쳐도 다른 fetch의 `FETCH_HEAD`를 자신의 결과로 채택하지 않는다. 실제 외부 ref 변경은 현재 쓰기의 경쟁으로 다루고 사용자 작업·원래 intent·실패 감사를 보존한다.
- 사용자 refspec이 로컬 branch나 다른 공유 ref를 가리키거나 prune·tag·submodule 갱신 설정이 켜진 실제 Git 회귀에서 의도한 추적 ref 외의 ref·태그·사용자 checkout이 보존됨을 확인한다. 공백·한글 경로, 유효한 특수 문자 branch 이름과 긴 branch 목록도 지원한다.
- 정책·실패 조합과 호출 횟수는 [자체 테스트의 Git 경계](../ARCHITECTURE.md#자체-테스트의-git-경계)에 따라 mock으로 검사한다. 일괄 수신·ref 보존·journal 중단 복구의 실제 Git 효과는 최소 회귀로 확인하고, Windows 명령 입력·경로의 핵심 회귀는 WSL 전체 검증과 구분한다. 같은 원격 응답·branch 수·변경 조건에서 전후 비용을 비교하며 실제 원격의 미측정 성능을 개선 실측으로 기록하지 않는다.
