# [R-085] Codex·Claude 인증 전용 자동 실행 환경

## Context

Loop Manager의 자동 실행에서는 사용자의 Codex·Claude Plugin·Hook을 사용하지 않으면서 기존 CLI 인증은 재사용해야 한다. 설정·인증 파일만 역할별 실행 홈에 연결하면 설정의 최초 부재나 CLI의 파일 생성·원자적 교체 뒤에 홈 사이의 상태가 달라져 다음 호출이 실패할 수 있다. 따라서 개인 홈과 자동 실행 홈은 분리하되, 같은 공급자의 자동 호출은 하나의 홈을 직접 사용해야 한다.

Codex는 `automation-codex`, Claude는 `automation-claude`를 각각 공통 홈으로 사용한다. 이번 변경은 공통 홈 선택·설정 수명과 호출별 임시 폴더·작업 권한 분리를 다룬다. 당장 실행할 수 없는 session 재개·CLI 호환성·실계정·OS별 검증은 Non-Goals에 후속 확인 메모로만 남기며 이번 변경의 선행 조건이나 완료 조건으로 요구하지 않는다.

## Requirement

- Codex와 Claude는 DB·잠금에 실제 사용하는 선택된 `state_dir` 아래의 `automation-codex`·`automation-claude`를 각각 자동 실행의 공통 홈으로 직접 사용한다. 같은 상태 루트의 모든 Codex 호출은 `CODEX_HOME=<state_dir>/automation-codex`, 모든 Claude 호출은 `CLAUDE_CONFIG_DIR=<state_dir>/automation-claude`를 사용하며 역할·repository·worktree별 홈으로 다시 바꾸지 않는다. 공급자와 상태 루트가 다르면 홈을 공유하지 않는다. 기존 상태 루트 선택 규칙과 bootstrap/runtime 전달을 유지하고 사용자명·cwd·외부 provider home에서 상태 루트를 추정하지 않는다. cron·작업 스케줄러의 공급자 홈 지정은 없어도 되며 외부의 다른 값도 같은 결과를 낸다. 부모 환경은 바꾸지 않는다.
- 새 전용 경로의 인증 파일이 없고 기본 인증 파일이 있으면 Codex의 `~/.codex/auth.json` 또는 Claude의 `~/.claude/.credentials.json`만 절대 경로의 심볼릭 링크로 연결한다. 기본 경로는 실행 사용자의 홈이며 외부 provider home으로 바꾸지 않는다. 기존 전용 파일·링크는 보존·재사용하며 끊긴 링크·읽기 불가·링크 생성 실패는 보존·진단한다. 기본 파일이 없으면 빈 파일·끊긴 링크·인증 사본을 만들지 않고 전용 경로에서 인증을 확인한다. 기존 허용 인증 환경변수의 필터·전달 정책은 유지한다. 로그인·로그아웃·인증 복사·이동·삭제를 자동 실행하지 않으며 비밀값을 prompt·명령행·로그·DB에 기록하지 않는다.
- 개인 `~/.codex`·`~/.claude`와 자동 실행 홈을 분리한다. 개인 `config.toml`·Claude settings 및 기타 개인 설정·Plugin·Hook·MCP·규칙·지침을 자동 실행 저장소에 연결하거나 복제하지 않는다. 인증이 아닌 사용자 설정 파일을 인증 재사용에 함께 가져오지 않는다. Claude는 설정 디렉터리 밖의 개인 설정 source도 실제 호출에서 제외하며 별도 홈 지정만으로 분리가 완료됐다고 간주하지 않는다.
- Manager는 Codex `config.toml`이나 Claude 사용자 설정 파일을 생성·덮어쓰지 않는다. 빈 설정은 파일이 없는 상태를 뜻하며, CLI가 공통 홈에 설정을 생성·수정·원자적으로 교체한 뒤에는 다음 호출이 그 홈의 현재 상태를 사용한다. 설정 파일의 최초 부재나 정상 생성·교체 자체를 runtime 입력 위반으로 거부하지 않는다. 역할별 runtime에 설정·인증 파일을 연결하거나 복제해 두 홈을 동기화하지 않으며 과거 설정 복원·빈 파일 생성·개인 설정 재연결로 대체하지 않는다. 실제 사용하는 설정의 읽기 실패·소유권 불명·검사 뒤 변경과 권한·확장 기능 충돌은 기존 검증에 따라 보존·진단하고 해당 호출을 시작하지 않는다.
- Model·Effort·Fast 선택, 공통·역할별 지침 및 쓰기 제한·자동 승인 검토에 필요한 실행값은 기존 Manager 설정과 명시적인 호출 입력으로 제공한다. 호출·역할별 값을 공통 홈의 설정에 저장해 다른 호출에 전달하지 않는다. 설정 상속은 공통 홈·프로젝트·관리 설정을 사용하는 CLI 기본 동작을 따른다.
- 인증 확인, 설정·권한 확인과 실제 Agent 호출은 같은 자동 실행 환경을 사용한다. 사용하지 않는 개인 설정의 Plugin·Hook을 이유로 호출을 차단하거나 개인 설정을 다시 읽지 않는다. 신규 session·재개·재시도·새 session fallback에 같은 분리를 적용한다.
- 호출별 임시 폴더·로그·결과와 repository·worktree·role의 호출 식별을 공통 홈과 별도로 관리한다. Agent 도구의 쓰기 허용은 기존 선택 worktree와 소유 임시 경로로 제한하며 공통 홈·개인 홈을 추가하지 않는다. CLI 자체의 상태 저장과 Agent 도구의 쓰기 권한을 구분하고 Reviewer의 읽기 전용 계약을 유지한다.
- 저장된 session ID와 repository·worktree·role·작업의 기존 결합과 새 session fallback 규칙을 유지하며 공통 홈의 가장 최근 session으로 대체하지 않는다. 기존 역할별 홈의 session·설정·인증·작업물·로그와 DB의 작업·실패 이력을 보존하고 홈 전체를 복제하거나 비가역 이동·초기화하지 않는다. 재개 불가는 원래 session과 실패를 보존한 기존 최소 문맥의 새 session fallback으로 처리하며 재개 성공으로 표시하지 않는다. 실제 사용하지 않는 과거 runtime 설정은 새 호출의 입력으로 검사·복원하지 않는다.
- 같은 공통 홈을 사용하는 동시 호출에서도 session·임시 폴더·로그·결과·역할별 실행값·권한·사용량이 다른 호출과 섞이거나 덮어써지지 않아야 한다. 공통 상태 저장의 경쟁·중단 때문에 다른 호출의 작업을 초기화하지 않으며 기존 프로젝트별 실행 조율을 유지한다.
- 기존 provider·OS별 설정·파일/credential store 선택과 로그인·갱신 정책을 유지한다. 파일 링크로 경로에 종속된 credential store까지 공유했다고 표시하지 않으며, 공통 홈에서 인증 재사용을 확인할 수 없는 저장 방식은 거부·진단한다. 기본 인증 파일의 갱신·원자적 교체 뒤에도 같은 원본을 읽고, CLI가 링크를 사본으로 교체하면 정상 공유로 처리하지 않는다. 실패 메시지는 실제 전용 경로의 로그인·상태 확인 명령을 안내하며 설정·인증을 자동 교체하거나 조직 정책을 완화하지 않는다. 공유한 파일의 갱신은 기본 인증에도 영향을 줄 수 있음을 운영 안내에 명시한다.
- Linux·macOS와 지원되는 native Windows 호출에 같은 원칙을 적용한다. provider·OS별 공식 인증 방식의 차이를 허용하되 개인 설정 전체를 다시 상속하는 대체 실행은 하지 않는다. 인증 재사용 실패는 해당 provider·프로젝트의 오류로 처리하며 다른 provider로 임의 전환하거나 독립 작업을 중단하지 않는다.
- 별도 home만으로 프로젝트·관리 설정의 Plugin·Hook까지 비활성화됐다고 간주하지 않는다. 기존 프로젝트 지침과 관리 정책의 적용·검증, 확장 기능 비활성화 및 충돌 거부를 유지한다. 이 변경으로 Agent의 쓰기 범위나 자동 승인 정책을 완화하지 않는다. 환경 변경으로 과거 호출 근거가 달라지면 기존 재검증·session 복구 규칙을 적용하며 작업·교정·실패 이력을 초기화하지 않는다.

## Acceptance Criteria

- 외부 provider home의 미설정·다른 값·Windows 이름 대소문자 차이와 cwd/runtime 전환에 관계없이 인증·설정 조회부터 실제 자식 호출까지 공급자별 공통 홈을 직접 사용하고 부모 환경을 보존한다. 역할·repository·worktree가 달라도 같은 공급자·상태 루트이면 홈이 같고, 공급자나 상태 루트가 다르면 경로가 섞이지 않는다.
- 새 전용 경로는 기본 인증 파일만 심볼릭 링크로 연결하고 반복·생성 경쟁이 기존 파일을 덮어쓰지 않는다. 기존 파일·정상 링크 보존, 끊긴 링크·원본 부재·읽기 불가·링크 권한 실패와 기본 파일의 갱신·원자적 교체 및 CLI의 링크 교체를 임시 파일·모의 호출로 확인한다.
- 개인 설정에 Plugin·Hook이 있는 fixture에서 그 파일·디렉터리가 자동 실행 환경에 복사·연결되지 않고, 개인 Hook이 호출되거나 그 설정 때문에 사전 검사가 거부되지 않는다. 실제 사용자 Plugin·Hook을 실행하지 않는 모의 호출과 fixture로 확인한다.
- 새 자동 실행 저장소에 Codex `config.toml`·Claude 사용자 설정 파일이 없는 상태로 호출할 수 있다. 개인 설정을 읽는 링크와 Manager가 생성한 빈 config 파일이 없으며 필요한 Model·Effort·지침·권한 설정은 명시적인 호출 입력으로 전달된다.
- 두 공급자의 공통 홈에서 설정의 최초 부재·CLI 생성·수정·원자적 교체·삭제·재생성을 연속 호출로 확인한다. 신규·재개·재시도·새 session fallback은 현재 공통 홈의 설정을 사용하고, 과거 runtime의 설정 파일·끊긴 링크를 복원하거나 그 존재만으로 호출을 거부하지 않는다. 역할별 설정·인증 연결이나 Manager의 빈 설정 생성이 없으며 실제 설정 지문과 기존 권한·확장 충돌 판정은 유지된다. 임시 fixture와 모의 호출로 확인하고 실제 사용자 설정을 변경하지 않는다.
- 인증 확인·설정 검사·신규 호출·재개·fallback이 동일한 저장소와 설정 범위를 사용한다. 개인 config 변경만으로 자동 호출의 유효 설정 지문이 달라지지 않으며 실제 사용하는 Manager·프로젝트·관리 설정의 변경은 계속 판정에 반영된다.
- 이전 홈·공통 홈의 session·설정·인증과 기존 작업물·로그·DB 이력이 보존되고 저장된 session ID·작업 결합과 기존 fallback 규칙을 변경하지 않는다. 같은 상태 루트의 외부 공급자 홈 환경값 제거 전후에도 DB·인증과 작업·호출의 연결을 재초기화하지 않는다. 실제 사용하는 경로의 소유권 불명·읽기 실패·검사 뒤 변경은 임의 삭제·덮어쓰기 없이 보존·거부한다.
- 같은 공통 홈을 사용하는 서로 다른 프로젝트·worktree·역할의 호출 준비와 환경·출력 분리를 임시 fixture·모의 호출로 확인한다. 각 호출의 session ID·임시 폴더·로그·결과·명시적 Model/Effort/Fast·지침·권한·사용량이 구분되며 다른 호출의 저장 상태를 덮어쓰거나 초기화하지 않는다. 공통 홈과 다른 호출의 임시 경로는 Agent 도구의 쓰기 허용 범위에 포함되지 않는다.
- 기존 인증 재사용의 성공·실패와 거부 정책을 임시 fixture·모의 호출로 확인한다. 실패 시 개인 home 재사용·설정 일괄 복제·대화형 로그인·권한 확대가 발생하지 않으며 비밀값이 출력이나 저장 기록에 노출되지 않는다. 모의 검증을 실계정 호출 성공으로 기록하거나 기존 미지원 호출의 허용 근거로 사용하지 않는다.
- 기존 프로젝트·관리 설정의 확장 기능 충돌, 역할별 쓰기 제한·자동 승인 검토와 Reviewer 읽기 전용 계약을 유지한다. 원본 사용자 저장소와 부모 환경은 변경되지 않는다.

## Product Impact

- 개인 CLI의 Plugin·Hook 설정을 유지하면서 Codex·Claude 자동 실행에는 인증만 재사용한다.
- scheduler별 provider home 주입이나 개인 config 편집 없이 Manager가 분리된 실행 환경을 준비한다.
- 같은 공급자의 자동 호출은 공통 홈에서 설정과 session 상태를 사용하며 작업 권한·임시 파일·호출 결과는 호출별로 분리한다.
- 자동 실행의 모델·지침·권한은 Manager가 전달하는 실행 입력과 기존 프로젝트·관리 정책으로 결정된다.

## Non-Goals

- 기존 session의 공통 홈 재개 가능 여부와 session 이전·재개 호환성 검증. 기존 session·작업 이력 보존과 fallback 규칙은 유지하고 호환성 확인은 나중에 별도 작업으로 수행한다.
- Claude CLI의 버전·OS·인증 저장소·설정 source·session 호환성 검증과 실제 동시 모델 실행 검증. 이 확인은 후속 작업이며 이번 공통 홈 변경의 선행 조건·완료 조건이나 미완료 사유로 사용하지 않는다. 기존 미지원 호출 거부와 권한·인증 검증은 유지한다.
- 실계정 인증·로그인·토큰 갱신, OS credential store 재사용과 현재 환경에서 실행할 수 없는 OS의 실제 CLI·격리 효과 검증. 기존 임시 fixture·모의 호출의 인증·링크·권한 회귀는 유지한다. 후속 확인 메모: 해당 CLI·계정·OS 환경이 준비되면 필요한 범위만 확인하며 지금 모의 검증을 실환경 성공으로 기록하지 않는다.
- 사용자 Plugin·Hook의 설치·삭제·설정 변경 또는 자동 실행에서의 활성화.
- 새 인증 방식·계정 관리·대화형 로그인 기능과 인증 자료의 별도 복제 저장.
