# [R-054] 주기에 도달한 리팩터링의 우선 실행

## Context

현재 유지보수 평가는 MERGED 계획 수와 `refactoring_review_interval`을 기준으로 시작한다. 그러나 미게시 평가가 기존 READY에 실행을 양보하거나, `PLAN_BLOCKED`와 `PR_OPEN`을 함께 대기 상태로 취급해 평가를 보류하는 경로가 있다. 일반 계획이 계속 남아 있으면 주기에 도달한 리팩터링이 밀릴 수 있다.

Merge 대기 PR이 없을 때는 주기에 도달한 유지보수 평가와 필요한 리팩터링을 다음 작업 선택의 최우선으로 처리한다.

## Requirement

- 실행 중인 Agent·verify·Review·게시·복구 작업을 선점하지 않는다. 저장된 진행 작업과 미확정 게시를 안전하게 복구·확정한 다음 작업 선택 경계에서 우선순위를 적용한다.
- 프로젝트의 관리 PR 상태를 실제 GitHub 상태와 동기화한 뒤 Merge 대기 중인 Open PR이 없고 유지보수 평가가 due이면, 일반 Planner·빠른 점검과 일반 READY Worker보다 유지보수 평가를 먼저 시작한다. READY의 개수·priority, 변경된 일반 계획 입력 또는 독립된 `PLAN_BLOCKED` 존재만으로 미루지 않는다.
- 유지보수 평가가 아직 리팩터링 계획을 게시하지 않았다는 이유로 일반 READY에 실행을 양보하지 않는다. 중단·재시작 뒤에도 같은 우선순위로 평가를 이어간다.
- 평가가 리팩터링 필요 없음을 확인하면 성공 기준을 확정한 뒤 일반 계획 선택으로 돌아간다. 리팩터링이 필요하면 기존 prerequisite·리팩터링 DAG·barrier·사후 재검증을 따르고, cycle이 끝날 때까지 일반 READY보다 우선한다.
- Open PR이 남아 있으면 새 due 평가의 시작을 보류하고 기존 PR 관측·충돌 복구와 독립 작업 선택 규칙을 따른다. 마지막 대기 PR의 Merge 또는 Close를 반영한 다음 안전한 선택 경계에서는 due 평가를 먼저 시작한다. 유지보수 cycle 자체가 만든 PR은 기존 cycle의 Merge·dependency 대기 규칙으로 처리한다.
- 실제 `PROJECT_BLOCKED`, 필요한 prerequisite의 차단과 dependency 미충족은 우회하지 않는다. 유지보수 planning 오류는 새 평가·계획 수립을 보류하되, R-055에 따라 안전성과 관계가 확인된 기존 리팩터링 계획은 계속 선택할 수 있다. 유효성을 확정할 수 없는 계획은 해당 범위만 보류하며, 유지보수와 무관한 계획 차단을 프로젝트 전체의 유지보수 금지로 확대하지 않는다.
- 주기 도달 사실과 평가 성공 기준은 원래의 MERGED 수·파일별 평가 근거를 유지한다. PR 대기 또는 일시 실패만으로 due를 해소하거나 성공 기준을 전진시키지 않는다. 로그에서 우선 선택 또는 보류의 실제 이유를 확인할 수 있어야 한다.

## Acceptance Criteria

- 주기에 도달했고 Open PR과 현재 변경 작업이 없으면, 일반 READY가 여러 개이거나 priority가 critical이어도 유지보수 평가가 먼저 시작된다.
- 같은 조건에서 명세·코드 변경으로 일반 Planner 또는 빠른 점검이 필요한 경우에도 due 평가가 먼저 실행되며, 이후 해당 변경 입력을 누락하지 않고 처리한다.
- 독립된 `PLAN_BLOCKED`만 남은 프로젝트도 안전한 유지보수 평가를 시작한다. 실제 프로젝트 안전 차단과 유지보수 prerequisite 차단은 유지된다.
- 미게시 평가와 평가 중단 뒤 재시작이 일반 READY에 실행을 양보하지 않는다. 평가 결과 리팩터링이 불필요하면 일반 작업을 재개한다.
- Open PR 존재 여부를 판단하기 전에 프로젝트의 관리 PR 상태를 실제 GitHub 상태와 조회·동기화한다. 동기화 후에도 Open PR이 있으면 새 평가를 보류하고, 마지막 PR의 실제 Merge·Close 반영 뒤 일반 READY보다 먼저 시작한다. PR 조회 실패를 대기 PR 없음으로 처리하지 않는다.
- 생성된 리팩터링 DAG와 사후 재검증이 기존 dependency·승인·검증·barrier 조건을 유지한다. 활성 작업의 강제 중단이나 자동 Merge는 발생하지 않는다.
- 보류·실패·재시작으로 평가 주기의 성공 기준이 임의로 전진하지 않으며 선택 사유를 로그에서 확인할 수 있다.

## Product Impact

- Merge 대기 PR이 없으면 due 리팩터링을 일반 계획보다 먼저 처리한다.
- 일반 READY와 무관한 계획 차단이 정기 유지보수를 계속 밀어내지 않는다.

## Non-Goals

- 평가 주기, 파일 선정 기준 또는 리팩터링의 제품 동작 보존 범위를 바꾸지 않는다.
- 실행 중인 작업을 선점하거나 안전 차단·dependency·사용자 승인을 우회하지 않는다.
- 일반 계획의 priority 체계와 같은 프로젝트의 직렬 실행을 변경하지 않는다.
