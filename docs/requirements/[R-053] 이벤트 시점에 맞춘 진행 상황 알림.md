# [R-053] 이벤트 시점에 맞춘 진행 상황 알림

## Summary

Telegram은 실제 사용자 대응이 필요한 사건과 알아야 할 확정된 진행 상황을 구분한다. 신규 일반 ExecPlan·draft의 게시와 안정적 작업 소진은 일반 알림, Worker 최초 시작·차단 해제 후 실제 작업 시작·프로젝트 전체 완료는 무음 알림으로 전달한다. 사용자 결정·승인·권한·PR 검토/Merge·자동 복구 불가능한 중단·무진전 지속 장애는 기존 일반 알림으로 유지한다. 정상 재시도·단순 실패·내부 단계에서는 보내지 않고, 현재성 재검사·중복 제거·durable outbox·분할 전송·전송 감사를 보존한다.

## Context

이전에는 새 계획·작업 시작·차단 뒤 재개·안정적인 대기·전체 완료도 Telegram으로 전달했지만 사용자 조치 중심 정책으로 바꾸면서 정보성 알림과 무음 메시지까지 제거되었다. 사용자는 불필요한 내부 처리 알림 없이도 실제 작업이 언제 시작되고 새 문서가 만들어졌으며 모든 작업이 막혔거나 완료되었는지 알아야 한다.

현재 구현은 이들 진행 알림을 생성하지 않는다. 따라서 확정된 게시·실제 실행 시작·안정적인 작업 소진·최종 완료만 복원하고, Git·verify·외부 CLI의 일시 오류와 자동 재시도는 기존대로 제외한다. 복구 불가 여부와 사용자 행동 필요성은 정보성 상태 사건과 별도로 엄격하게 판단한다.

## Requirement

### 사용자 대응·지속 운영 장애 알림

| 사건 | 현재 상태에서 확인할 조건 |
|---|---|
| 사용자 결정·승인·조치 | 유효한 명세·질문·출처·현재 소유권을 대조해 실제 미해결 사용자 결정, 접근 권한/설정 변경 또는 명시적 재시작이 필요하고 Manager가 자체 해결할 수 없다. draft 질문은 프로젝트별 현재 미해결 목록으로 묶는다. |
| PR 검토·Merge | verify·Review와 원격 게시가 완료된 신규 PR 또는 기존 PR의 새로운 검토 후보에 사용자가 검토·Merge할 일이 있다. 같은 후보와 동일 사용자 행동에는 중복 통지하지 않는다. |
| 실제 자동 복구 불가능한 최종 중단 | 동일 계획/프로젝트의 최신 원인에 재관측·재시도·자동 교정·조건 해소 대기·다음 실행 재개·안전한 복구 방법이 남지 않아 진행이 불가능하다. 사용자 행동이 없다면 가짜 행동을 요구하지 않고 복구 불가 사유·범위·보존을 안내한다. |
| 진전 없는 지속 운영 장애 | 같은 작업·단계·원인·유효 입력에서 재시도·대기·다음 실행 재개가 실제 복구 전이 없이 반복됨을 R-091의 이력으로 확인했다. 최종 차단이나 사용자 Git 수정 요구로 오인하지 않고 정체 원인·진단·보존·재평가 조건을 알린다. |

단순 `BLOCKED`·`PLAN_BLOCKED`·`PROJECT_BLOCKED`·`planning_error`, 실패 횟수나 교정/retry 묶음 소진, 시작 가능한 작업 없음은 사용자 조치·복구 불가·지속 장애 경고의 충분조건이 아니다. 안정적 작업 소진은 아래의 별도 정보성 사건으로 판단한다. Git OID/PR head 변경, lease 경쟁, 일시 원격 조회 실패, Git lock, CPU·verify/DB 자원 대기, 외부 CLI 오류, commit/push 기록 중단, rebase/cleanup 보류와 다음 runtime 실행의 자동 복구 가능성만으로는 해당 작업·자원만 보존/대기하고 Telegram을 보내지 않는다. 단, 동일 원인·입력의 실질적인 무진전 반복이 확정되면 위의 지속 운영 장애 기준을 적용한다. 실제 타인의 Git 이력 덮어쓰기 위험은 쓰기를 거부하되 자동 확인과 복구 여지가 남은 상태를 사용자 결정으로 위장하지 않는다.

### 진전 없는 지속 장애의 현재성

실행별 짧은 RETRY 묶음, 30초 등의 정상 조건 대기, 다음 외부 실행의 재개 가능성을 장애로 추정하지 않는다. R-091의 원인·작업/자원·단계·입력/진전 표식과 실제 재시도/재개 이력으로 같은 실패가 실질적 진전 없이 반복되는지를 판단한다. 한 실행 안에서 retry·대기만 되풀이하는 경우와 여러 외부 실행에서 같은 원인이 유지되는 경우를 모두 포함하며, 단순 시간 경과·타이머 만료·같은 OID 재조회는 진전으로 세지 않는다. 별개 원인·실제 새로운 입력·진행한 복구 단계와 정상 외부 조건 대기를 합쳐 허위 장애로 만들지 않는다.

지속 정체는 복구 분류 오류·안전한 다음 전이 부재·외부 조건 미해소 등을 현재 근거로 구분해 알린다. 같은 정체 사건은 대상·원인·입력/진전 identity로 한 번만 전송하고, 새로운 실제 진전·원인 해소·다른 후보로 전환 시 미전송 잔여분을 취소한다. 메시지에는 프로젝트/작업, 실제 반복 횟수와 확인 기간, 마지막 원인 상세, 보존한 Git 작업물·checkpoint, 영향 범위와 조건부 재평가 경로를 포함한다. 사용자 행동이 확인되지 않았으면 `recover`·reset·force push·문서 수정 등을 임의로 해결책으로 안내하지 않는다. 알림 자체가 기존 자동 복구를 중지·실행하거나 새로운 최종 차단을 만들지 않는다.

### planning·비오류 대기의 정체 진단

진전 없는 지속 장애의 수집 대상은 ExecPlan 실행 실패뿐 아니라 작업 ID가 없는 프로젝트 planning·게시 적용/자리 해제·복구·정리와, 후보가 있는데 오류 없이 WAITING·skip·조기 반환하는 경로를 포함한다. R-055의 원인 소유자·operation/intent·영향 대상·유효 입력·실제 진전 근거로 사건을 구분한다. `planning_error` 문자열의 반복만으로 장애를 확정하지 않지만, 복구 기록을 거치지 않거나 상위 결과가 정상 반환이라는 이유로 확인된 정체를 제외하지 않는다.

이력은 같은 실행 안의 반복과 여러 외부 실행의 반복을 연결한다. 새 run ID·같은 관측의 재저장·무관한 작업의 성공이나 원격 전진은 원인 해소가 아니다. 후보가 남은 비오류 반환만으로 미전송 진단을 취소하거나 사건을 초기화하지 않고, 실제 원인 해소 또는 해당 복구의 실질적 진전과 현재성을 확인한다. 정상 사용자 판단/PR 대기·실행 중인 소유자의 자원 대기를 정체로 추정하지 않으며, 이미 같은 원인의 현재 사용자 행동을 통지했으면 중복 발송하지 않는다.

### 확정된 진행·상태 정보 알림

| 사건 | 수준 | 확정 조건과 내용 |
|---|---|---|
| 신규 일반 ExecPlan 생성 | 일반 | 일반·유지보수 Planner가 **새 일반 작업 문서**를 원격 게시하고 catalog·DB 등록까지 확정한 뒤 새 ID·제목·확인한 링크와 실행 또는 dependency 대기를 알린다. 같은 게시 batch는 묶는다. 기존 계획의 개정·삭제, 미게시 초안·게시 실패, 신규 작업이 없는 Planner 결과는 제외한다. |
| 새 draft ExecPlan 생성 | 일반 | 실제 **새 draft 문서의 원격 게시·등록**을 확정하면 ID·제목·링크를 전달한다. 미해결 질문이 있는 경우 현재 판단 목록과 통합하고, 질문이 없는 신규 draft도 생성 사실을 알린다. 같은 draft 생성과 질문을 중복 발송하지 않고 후속 새 질문은 기존 판단 알림 기준을 따른다. |
| Worker 최초 작업 시작 | 무음 | 계획 선택·예약이 아니라 해당 계획의 실제 Worker 프로세스 시작을 확인한 뒤 ID·제목·작업 종류를 알린다. 같은 계획의 일반 retry·재호출·단계 변경에는 최초 시작 알림을 반복하지 않는다. |
| 차단 해제 뒤 실제 작업 시작 | 무음 | 계획 또는 프로젝트의 기록된 차단이 실제 해제된 뒤 **그 영향 대상의 정상 작업이 시작**됐을 때 이전 차단과 시작한 작업을 알린다. 차단 메시지의 과거 전송 여부에 종속되지 않으며 단순 해제·무관한 작업 시작은 제외한다. 같은 시작에 최초 시작 메시지를 추가하지 않는다. |
| 시작 가능한 작업 없음 | 일반 | 현재 원격·catalog·실행 상태에서 독립적으로 시작·재개 가능한 작업이 없고 미완료 목표가 남은 **안정적 작업 소진**만 알린다. draft와 PLAN_BLOCKED·PROJECT_BLOCKED의 ID·제목·확인된 원인·문서 링크를 먼저, PR Merge·dependency·기타 외부 조건 대기와 재평가 조건을 그다음에 제시한다. 확인되지 않은 사용자 조치를 요구하지 않는다. |
| 모든 작업 완료 | 무음 | 최신 입력의 프로젝트 최종 전문 확인과 모든 완료 gate가 충족된 **완료 주기**를 한 번 알린다. 개별 PR 생성/Merge, 유지보수 종료 또는 단순 작업 선택 결과를 전체 완료로 표시하지 않는다. |

이 표의 일반 알림은 주목할 만한 사실을 전달하는 정보성 통지이며, 오류 또는 사용자 개입 요청을 의미하지 않는다. 사용자 조치·복구 불가·무진전 지속 장애의 확정 기준은 앞 절을 그대로 사용한다. 외부 입력이 일시 불확실하거나 Agent·verify·복구가 실제 진행 중이면 작업 소진으로 확정하지 않는다. 정상 자원 순번 대기·짧은 retry·단순 재관측만으로 새 진행 사건이나 장애를 만들지 않는다. 프로젝트가 전체 완료된 경우에는 작업 소진이 아니라 완료 사건만 보낸다.

동일한 신규 게시 batch·draft 생성/판단·Worker 최초 시작·차단 뒤 실제 재개·안정적 대기 episode·완료 주기는 실행/재시작을 건너 중복 통지하지 않는다. 정상 시작과 차단 해제 후 재개가 겹치면 재개만 보낸다. 작업이 실제로 진행됐다가 다시 소진되거나 관련 입력·차단 원인·목록이 실질적으로 바뀌면 새로운 안정적 대기 episode를 한 번 통지할 수 있다. 다른 draft·차단·PR 개별 알림을 보냈어도 프로젝트 전체의 작업 소진 사건은 별개로 한 번 통지한다.

### 내부 진행과 별도 알림 제외

개별 Planner 호출 시작·종료, Reviewer 시작·종료, 유지보수 cycle 시작·종료, 기존 PR 충돌 수정의 중간 단계, 단순 단계 실패·targeted test/verify/Review 자동 교정, Git checkpoint·원격 전진, retry·조건 대기·내부 상태 갱신에는 별도의 일반·무음 알림을 생성하지 않는다. 실제 차단 해제만으로는 재개 알림을 만들지 않으며 해당 작업의 실제 시작을 기다린다. 기존 PR의 충돌 수정 완료는 새 검토 후보가 실제 게시되고 사용자에게 검토·Merge할 일이 생겼을 때만 기존 PR 행동 알림으로 통지한다.

진행·실패·재시도·복구·검증 이력은 운영 로그·DB·status에 보존한다. 실제 신규 ExecPlan 게시·Worker 시작·안정적 대기·전체 완료와는 구별하고, 정상적인 Git·CPU·verify·DB·외부 CLI 자원 대기를 자동 복구 불가로 오인하지 않는다.

### 현재 사건과 기존 outbox 재검사

새 draft 생성은 실제 게시된 문서 identity로, draft 사용자 판단은 미해결 질문의 ID·제목·identity/revision·확인한 원격 링크로 현재성을 검증한다. 생성 알림과 질문 목록은 중복 통지하지 않고 질문이 없어도 실제 신규 draft를 빠뜨리지 않는다. 질문 해소·문서 철회·링크 변경은 별개 원인으로 판단해 유효하지 않은 미전송 조각만 취소하며 단순 링크 변경으로 새 승인 요청을 만들지 않는다.

사건은 실제 원격 게시·catalog/DB 등록, 실제 프로세스 시작, 안정적 작업 선택 결과, 최종 완료 gate 또는 기존 사용자 행동/장애 판정의 소유 경계에서만 확정한다. 다음 장시간 작업 전에 발송을 시도하되 **실제 전송 직전과 각 미전송 조각 앞에서** 사용자 결정·PR head/검토 후보·차단 원인과 자동 복구 가능성·지속 장애의 동일 원인/진전 부재뿐 아니라 게시된 문서, 시작 대상/차단 이력, 대기 episode, 완료 주기의 현재성을 확인한다. 해소된 질문·사라진 문서·무효화된 대기·새 입력으로 더 이상 완료가 아닌 결과 등 오래되어 오해를 줄 사건의 미전송 조각은 취소한다. 실제 발생한 시작은 이후 단계 전환만으로 거짓 사건이 되지 않는다. 과거 정책에서 이미 취소된 사건을 무조건 다시 활성화하지 않으며, 정책 변경 전 일부 전송된 메시지도 현재성과 중복 기준을 적용한다. **이미 전송한 조각과 원래 사건·전송·실패·취소 감사는 보존**한다.

같은 게시·실제 시작·차단 뒤 재개·안정적 대기·완료 주기와 현재 필요한 결정·PR 검토/병합·복구 불가 중단·진전 없는 지속 장애는 관측·재시작·조각 전송 재시도에 중복 통지하지 않는다. 메시지는 프로젝트·대상·발생 시각과 사건별로 확인된 새 문서·시작·재개·대기·완료 상태, 관련 URL을 간결히 표시한다. 사용자 조치·차단·지속 장애에서는 현재 원인, 확인된 사용자 행동 또는 복구 불가능한 이유, 필요한 checkpoint·작업물 보존도 표시한다. 검증되지 않은 조치를 만들거나 비밀값을 노출하지 않는다.

기존 durable outbox·조각 전송·중복 제거·재시도·Telegram 설정은 재사용한다. 전송 실패는 작업·검증·복구·게시를 차단하지 않으며, 알림을 위해 추가 Agent 호출·사용자 승인이나 Git 쓰기를 만들지 않는다.

## Acceptance Criteria

- 작업 ID 없는 planning·게시 후 자리 해제 오류와 후보가 있는 비오류 WAITING·skip·조기 반환의 동일 원인 무진전 반복도 기존 지속 장애 기준에 따라 한 사건으로 진단된다. 원인 소유자와 영향 대상·operation/intent·반복 근거·남은 재평가 조건이 확인되며, 상세 없는 결과나 복구 기록 미생성만으로 누락되지 않는다.
- 같은 실행의 반복·Manager 재시작·다음 외부 실행·독립 작업의 성공 뒤에도 미해소 사건이 유지된다. 실제 복구 진전·원인 해소 뒤에는 현재성이 없는 미전송 조각이 취소되고, 정상 대기·확인된 기존 사용자 행동에는 중복 알림이 없다. 진단 생성이 실행을 차단하거나 성공·사용자 조치를 합성하지 않는다.

- 정상 Git HEAD/OID·PR 전진, lease/lock 경쟁, DB·CPU·verify slot 대기, CLI/네트워크 오류, retry/교정 예산 소진, 다음 외부 실행 재개와 Worker/verify/Review 자동 수정 자체에는 별도의 실패·차단 Telegram 알림이 없고 원래 실패·복구 근거는 보존된다. 이러한 상태만으로 무진전 장애를 추정하지 않으며 별도로 확정된 진행·대기/완료 사건의 알림은 방해하지 않는다.
- 일반·유지보수 Planner가 새 일반 ExecPlan을 원격 게시하고 catalog·DB 등록하면 신규 ID·제목·확인된 링크를 batch별 한 번 일반 통지한다. 기존 문서 개정·삭제, 미게시 초안·게시 실패·새 계획 없음은 생성 알림을 만들지 않는다.
- 새 draft ExecPlan 게시가 확정되면 질문 유무와 무관하게 일반 알림으로 전달한다. 미해결 질문과 한 목록으로 통합하고, 이미 확인된 질문·표시 링크 변경·철회 문서에서 중복·오발송하지 않는다.
- Worker 최초 실제 시작, 저장된 차단 해제 뒤 해당 대상의 실제 작업 시작은 각각 무음 통지한다. 차단 뒤 재개는 이전 차단 알림 전송 여부와 무관하고 최초 시작과 중복되지 않는다. READY 선택·단순 차단 해제·같은 작업의 일반 retry·무관한 작업 시작은 통지하지 않는다.
- 현재 원격/catalog·실행 근거로 모든 작업이 안정적으로 소진됐지만 미완료 목표가 있으면 draft·차단된 작업 목록의 ID·제목·원인과 PR/dependency 등 나머지 대기를 포함해 일반 알림 한 번을 보낸다. 정상 일시 대기·실행/복구 진행·완료를 작업 소진으로 오인하지 않고 같은 episode는 재실행 뒤 반복하지 않는다.
- 최종 전문 확인과 모든 완료 gate를 통과한 경우에만 완료 주기마다 무음 통지한다. 새 입력으로 무효화된 늦은 완료 메시지와 PR·개별 Merge만의 완료 합성을 방지한다.
- Planner·Reviewer 호출 시작/종료, maintenance cycle 시작/종료, PR 충돌 수정 중간 진행, 일반 실패·교정·재시도·내부 대기에는 독립적인 일반/무음 알림 0건이다.
- 사용자 조치·오류/장애 일반 경고는 실제 미해결 사용자 판단·승인/권한, 신규 또는 기존 PR의 새로운 검토/Merge 요청, Manager가 자동 복구할 수 없는 최종 중단과 확인된 무진전 지속 장애에 한한다. 정보성 상태 알림과 별도로 대상별 한 번 통지하며 상태 코드·실패 횟수만으로 조치를 추정하지 않고 행동이 없는 최종 중단에는 복구 불가와 보존 상태를 안내한다.
- 동일 작업의 고정된 `remote_snapshot_race` 등에서 여러 RETRY·조건 대기·외부 실행이 진행 없이 반복되면 기존 지속 진단을 사용해 사건 1건만 전송하고, 진전한 원격 통합·실제 새 입력·정상 대기·원인 해소에는 오발송 또는 오래된 후속 조각 전송이 없다. 진단은 확정하지 못한 사용자 조치를 꾸며내지 않으며 최종 차단·완료·작업 재시도를 알림 자체로 변경하지 않는다.
- 기존 outbox의 미전송·부분 전송 사건은 최신 상태와 새 정책에 따라 유효한 것만 이어 보내고, 철회·해소·무효화된 진행·대기·차단 사건의 잔여 조각은 취소한다. 정책에서 과거에 이미 취소한 사건을 일괄 부활시키지 않으며 전송된 조각과 감사는 보존한다.
- draft 목록은 현재 미해결 질문과 identity/revision·확인된 링크를 반영한다. 일부 해소·링크만 변경·전송 중단 후에도 불필요한 메시지가 재생성되거나 중복 발송되지 않는다.
- Telegram 비활성화·발송 지연·오류가 실행·원격 게시·검증 상태를 변경하지 않는다.

## Product Impact

- Telegram은 실제 사용자 개입·복구 불가·무진전 지속 장애를 일반 알림으로, 신규 작업·draft 게시 및 안정적 작업 소진을 일반 정보 알림으로, 최초 작업 시작·차단 후 실제 재개·전체 완료를 무음 알림으로 제공한다. 일시 실패와 내부 재시도 상세는 로그·상태 조회에 남긴다.

## Non-Goals

- 주기적 상태 방송·내부 단계별 진행/실패 메시지·새 알림 채널/대시보드를 만들지 않는다.
- 알림을 위해 사용자 결정·성공 결과·새 자동 실행 제어를 생성하지 않는다.
