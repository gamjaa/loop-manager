# [R-068] Planner 판단과 Manager의 Requirement 완료 이동

## Context

현재 Manager는 source로 연결된 ExecPlan의 Merge 상태만으로 Requirement archive 후보를 계산하고 Worker에게 구현 PR 안의 이동을 강제한다. Requirement 일부만 구현한 계획이 마지막 등록 계획이면 미구현 요구사항도 후보가 된다. G-142에서는 활성 유지라는 사용자 결정·Reviewer 지적과 archive 강제 지시가 충돌해 정상 구현의 완료를 막았다.

Requirement 전체 충족 여부는 관련 계획의 구현과 Merge가 끝난 뒤 Planner가 근거를 확인해 판단하고, 이동은 Manager가 기존 계획 게시 흐름에서 처리하도록 책임을 나눈다. 계획 수행 중에는 전체 충족 검사를 반복하지 않고, 유효한 최종 판단도 재사용한다.

## Requirement

### 전체 충족 판단과 역할

- 일반 Planner는 Requirement 전문과 현재 제품 규칙, 관련 계획·구현·검증 근거를 대조해 전체 충족, 미충족 또는 판단 불확실을 구분한다. 전체 충족에는 Acceptance Criteria별 근거가 있어야 하며 등록 계획 없음·모든 관련 계획 Merge·새 계획 없음만으로 확정하지 않는다.
- 필요한 ExecPlan을 모두 작성한 결과는 계획 수립 완료이며 Requirement 구현 완료가 아니다. 관련 미완료 계획·draft·Worker·검증·Review·PR Merge 대기·차단이 남아 있으면 Manager가 활성 문서를 유지하고, 그 Requirement의 전체 충족 확인을 위해 Planner를 추가 호출하지 않는다. 다른 Requirement와 독립 작업의 확인은 이 대기로 막지 않는다.
- 마지막 관련 구현 계획까지 실제 MERGED가 되면 일반 Planner가 최신 원격 구현을 기준으로 Requirement 전체를 최종 확인한다. 추가 미충족 작업을 발견해 후속 계획을 작성하면 그 계획들이 처리될 때까지 다음 전체 충족 확인을 미룬다. 취소·삭제·불확실한 source 관계를 Merge 완료로 간주하지 않는다.
- 미충족 작업은 허용된 계획 작성 권한으로 후속 ExecPlan에 연결하고 Requirement를 활성 위치에 보존한다. 명세 모순·목표 변경 또는 사용자 결정이 필요한 항목은 기존 판단 대기 방식으로 처리하며 임의로 요구사항을 축소하지 않는다.
- Reviewer는 현재 구현 PR의 목표·변경·검증과 사용자 결정을 검토한다. Requirement 전체 완료나 archive 이동을 그 PR의 필수 완료 조건으로 강제하지 않는다. 관련 archive 이동이 잘못 포함되면 그 문제를 지적할 수 있다.
- Planner와 Reviewer는 Requirement 파일을 직접 이동하거나 완료 표시를 본문·frontmatter에 쓰지 않는다. Manager가 판단 근거와 유효성을 관리하고 내용 보존 이동을 수행한다.

### 판단 재사용과 재확인 시점

- 판단은 Requirement의 안정적인 원래 경로와 내용, 관련 제품 근거·계획 관계, 구현 및 검증 근거에 결합해 보존한다. 충족·미충족 판단 모두 같은 유효 입력에서는 재사용한다.
- Requirement 내용 또는 관련 제품 명세의 의미가 바뀌면 계획 수행 중에도 일반 Planner가 기존 계획의 적합성과 남은 작업을 재평가한다. 계획 수행 중 완료·이동만을 위한 모델 호출은 추가하지 않는다.
- Requirement 완료 판정·기존 판정의 유지 확인·archive 이동 여부 결정에는 빠른 Planner를 호출하지 않는다. Manager가 기록된 근거와 입력의 동일성으로 유효한 판단을 재사용한다. 관련 구현·테스트·계획 관계가 바뀌어 판단이 무효화되면, 관련 미완료 작업이 없는 시점에 일반 Planner가 전체 충족을 다시 확인한다. 관련성·유효성을 확정하지 못하면 완료로 취급하지 않는다.
- 기존 ExecPlan의 변경 영향 점검은 이 완료 판정과 별개의 기존 흐름이다. 구현 변경에 따른 빠른 Planner의 기존 역할이나 인계 정책을 이 Requirement에서 확대·제거하지 않는다.
- 중간 Merge 상태 변화나 무관한 변경에는 전체 충족 확인을 호출하지 않는다. 마지막 관련 계획의 Merge로 최종 확인 후보가 된 경우에만 아직 유효한 판단이 없는 입력에 대해 일반 Planner를 한 번 호출한다. 원격 게시까지 대기 중인 유효한 최종 판단은 Manager가 재사용한다.
- 최종 판단은 이미 Merge된 최신 원격 구현과 검증 근거에 결합한다. 미반영 PR 후보에 대해 미리 전체 충족을 판정하거나 Merge 전후의 동등성 판정만으로 최종 확인을 대신하지 않는다. 취소·삭제·관계 불확실성은 별도 기존 복구·사용자 판단 절차로 먼저 처리한다.
- 재시작·중단·게시 경쟁에서 판단과 실패 입력을 보존한다. 판단 중 입력이 바뀌거나 결과 검증·게시가 실패하면 성공 기준을 전진시키지 않는다.

### Manager의 이동과 게시

- Manager는 유효한 전체 충족 판단, 관련 구현 계획의 Merge와 source 관계, 현재 문서 원문·목적지 및 원격 입력을 확인한 뒤 이동한다. 미완료 관련 계획·draft·미확인 구현·충돌·불확실한 source 관계가 남으면 활성 위치를 보존한다.
- 이동은 평소 ExecPlan 게시와 같은 관리 작업 공간·검증·fast-forward 게시 흐름에서 처리한다. 새 ExecPlan과 완료 Requirement 이동을 같은 planning commit으로 게시할 수 있고, 새 계획이 없어도 이동만 게시할 수 있다.
- 내용 보존 archive 이동에는 별도 PR이나 매번 사용자 확인을 요구하지 않는다. 명세 의미 변경·근거 부족·사용자 판단 필요와 기존 branch protection은 우회하지 않는다.
- 원격 게시 확인 전에는 활성 Planner 입력에서 제거됐다고 확정하지 않는다. 이동 후에도 ExecPlan의 원래 source 경로와 ID·실행 이력은 보존하고 기존 archive 조회를 유지한다.
- 후보 원격 입력이 바뀌면 기존 판단의 유효성과 이동 집합을 재확인한다. 중단·중복 실행·부분 게시 확인에서 동일 이동을 중복 적용하거나 unrelated 문서를 덮어쓰지 않는다. 이동 실패는 해당 정리 작업을 보존하며 독립 구현 PR을 실패로 되돌리지 않는다.

### 기존 문서의 일회성 점검

- 새 정책 적용 후 미완료 ExecPlan의 source 위치·관계와 기존 archive Requirement의 완료 근거를 일회성으로 점검한다. 모든 관련 계획이 Merge됐다는 사실만으로 실제 전체 충족을 추정하지 않는다.
- archived Requirement는 이 명시적인 일회성 감사의 대상 원본으로만 확인한다. 이를 평소 Planner의 활성 작업 입력으로 확대하거나 이미 대체·철회된 요구사항을 자동으로 새 목표로 되살리지 않는다.
- 확인된 조기 archive는 Manager가 원래 활성 위치로 내용 변경 없이 복원하고, 실제 미충족 작업은 활성 입력에서 후속 계획으로 연결한다. 유효한 완료·명시적 대체 또는 철회는 근거를 보존하며, 판정 불확실은 자동 이동하지 않고 이유와 사용자 판단 대상을 남긴다.
- 점검 대상 revision·파일 원문과 결과를 보존해 중단 뒤 이어가며 동일 원본을 매 cron 실행에서 다시 검사하지 않는다. 미완료 계획의 목표·dependency·session·branch·작업물·PR 및 과거 완료 이력을 감사라는 이유로 변경하거나 초기화하지 않는다.

## Acceptance Criteria

- 부분 구현만 있는 마지막 등록 계획도 정상 검증·Review·PR 흐름을 완료할 수 있고, 미충족 Requirement는 활성 위치에 남아 후속 계획 입력이 된다.
- 계획 수립 완료와 구현 충족 판단을 구분한다. 관련 계획이 미완료이거나 PR Merge 대기·차단이면 retirement 전용 모델 호출은 없고, 마지막 관련 계획의 Merge 뒤 일반 Planner가 한 번 최종 확인한다. 후속 계획이 생기면 같은 대기·최종 확인 흐름을 반복한다.
- 같은 Requirement·관련 구현 입력의 충족 또는 미충족 판단은 재시작과 반복 실행에서 모델 호출 없이 재사용된다. 중간 Merge, 이동 게시 대기와 무관한 변경만으로 재평가하지 않는다.
- 완료 판정 흐름에서는 빠른 Planner 호출이 없다. Manager가 유효한 판단을 재사용하고, 새 최종 판단이나 무효화된 판단의 재확인은 관련 계획 완료 뒤 일반 Planner가 담당한다. 명세 변경에 따른 일반 재계획과 별도 기존 변경 영향 점검은 유지된다.
- 검증되지 않은 로컬 후보·미반영 PR·오래된 판단으로 이동하지 않는다. 취소·삭제나 계획 번호 공백을 Merge 완료로 간주하지 않으며 관련 source·목표 불확실성은 활성 보존과 기존 복구로 처리한다.
- Planner·Reviewer는 판단과 검토만 하고, Manager가 최신 조건을 확인해 내용 보존 이동을 계획 게시와 함께 수행한다. 계획 없는 archive-only 게시에도 별도 PR·사용자 승인을 추가하지 않는다.
- 원격 경쟁·충돌·게시 중단·재시작에서 판단과 작업을 보존하고 source 경로·내용·ID와 실행 이력을 유지한다. 이동 실패가 독립 구현 작업의 실패로 전파되지 않는다.
- 기존 미완료 계획과 archive의 감사 결과·근거·미충족 또는 불확실 범위를 확인할 수 있다. 확인된 조기 archive만 복원하며 불확실·대체·철회 항목은 임의로 되살리지 않는다.
- G-142와 같은 사례에서 R-053·R-055 전체 완료를 주장하거나 archive 이동을 강제하지 않고, 남은 요구사항 보존과 해당 구현 PR의 완료를 양립시킨다.

## Product Impact

- Requirement 완료와 이동을 구현 PR의 완료에서 분리한다.
- Planner의 전체 충족 판단과 Manager의 Merge·게시 검증을 결합하고 유효한 판단을 재사용한다.
- 완료 이동과 확인된 조기 archive 복원을 기존 계획 게시 흐름에서 자동 처리한다.

## Non-Goals

- R-053·R-055 등의 남은 기능 자체를 이 정책 변경에서 구현하지 않는다.
- Reviewer의 테스트 재실행, 새 Agent 역할·외부 서비스·프로젝트 병렬 실행을 도입하지 않는다.
- 기존 빠른 Planner의 일반적인 ExecPlan 변경 영향 점검을 재설계하거나 제거하지 않는다.
- 모든 archive 문서를 일괄 복원하거나 사용자 결정·Merge·검증·게시 소유권을 생략하지 않는다.
- Requirement frontmatter 상태 추가, 기존 계획의 목표 변경 또는 운영 SQLite 사건의 수동 초기화를 수행하지 않는다.
