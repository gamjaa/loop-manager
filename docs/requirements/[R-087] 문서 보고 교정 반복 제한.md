# [R-087] 문서 보고 교정 반복 제한

## Context

같은 구현 후보가 검증과 Review를 통과해도 Worker가 변경 문서의 설명을 번갈아 누락하면 게시 교정이 반복된다. 검증 출력의 시각과 진단 경로 변화가 동일 오류의 반복 횟수를 초기화해 교정 한도도 적용되지 않는다.

## Requirement

최종 후보에서 변경된 모든 문서의 보고 누락·형식 오류·hash 불일치를 한 번에 전달한다. 교정 Worker는 최종 응답의 PR_SUMMARY에 변경 문서 전체의 DOCUMENT_CHANGE를 함께 제출한다. 후보와 base를 확정한 뒤 검증 실행·재사용 판단 전에 보고를 검사하고, 게시 직전 최종 diff/hash 검사도 유지한다.

동일 후보·명세 입력·base에서 같은 Worker 보고 오류는 검증 출력의 시각·진단 경로나 Agent 세션 변화와 무관하게 누적해 기존 교정 한도에서 차단한다. 실제 후보나 명세 입력·base 변경은 새 입력으로 구별한다. 보고만 수정해도 기존 입력 증명·receipt·검증 및 Review gate를 거치며 이전 PASS를 무조건 재사용하지 않는다.

## Acceptance Criteria

- PRODUCT와 ARCHITECTURE를 함께 변경한 후보는 두 문서의 유효한 보고가 함께 있으면 통과한다.
- 여러 보고 누락·hash 불일치·형식 오류는 한 응답에 전체 대상 경로와 현재 patch hash를 포함한다.
- 보고가 누락된 후보는 전체 verify와 Review를 실행하기 전에 Worker 교정으로 돌아간다.
- 시간·진단 경로만 바뀐 검증 출력과 세션 변화는 동일 오류 횟수를 초기화하지 않으며 기본 한도 3에서 차단한다.
- 실제 후보·명세 입력·base 변경은 새 반복 횟수로 시작한다.
- 게시 직전 검사와 기존 검증 입력 증명·성공 receipt·Review gate는 유지한다.

## Product Impact

문서 보고 교정이 전체 검증을 불필요하게 반복하거나 기존 교정 한도를 회피하지 않는다.

## Non-Goals

- 운영 상태 DB 수동 수정, 검증 gate 우회, 실행 중인 runtime 교체는 포함하지 않는다.
