# [R-085] Codex·Claude 인증 전용 자동 실행 환경

## Context

Loop Manager의 자동 실행에서는 사용자의 Codex·Claude Plugin·Hook을 사용하지 않으면서 기존 CLI 인증은 재사용해야 한다. 현재 Codex는 Linux·macOS의 별도 runtime home에도 사용자 `config.toml`을 연결하며 Windows에서는 기존 사용자 home을 사용한다. Claude도 사용자 설정 디렉터리를 상속한다. 따라서 cron에서 환경값을 지정하거나 개인 설정을 수정하는 방식만으로 이 경계를 관리하면 자동 호출이 개인 설정에 영향을 받는다.

Manager가 두 provider의 자동 실행 환경을 준비하고 인증만 재사용한다. 개인 설정 파일은 가져오지 않으며 설정 파일이 없는 상태에서 시작한다.

## Requirement

- Codex와 Claude 모두 Manager가 관리하는 별도 자동 실행 저장소를 사용한다. cron·작업 스케줄러에서 `CODEX_HOME`·`CLAUDE_CONFIG_DIR`을 별도로 주입하지 않아도 개인 설정과 분리된 환경을 준비한다. 부모 프로세스의 환경이나 사용자의 기존 CLI 저장소를 변경하지 않는다.
- 기존 CLI의 인증만 provider가 지원하는 방법으로 재사용한다. 명시된 기존 provider home이 있으면 그 인증을, 없으면 CLI의 기본 사용자 저장소 또는 OS 인증 저장소의 인증을 사용한다. 인증 원본을 자동으로 복사·이동·삭제하거나 새 로그인을 시작하지 않는다. 인증 내용을 prompt·명령행·로그·DB에 기록하지 않는다.
- 개인 `config.toml`·Claude settings 및 기타 개인 설정·Plugin·Hook·MCP·규칙·지침을 자동 실행 저장소에 연결하거나 복제하지 않는다. 인증이 아닌 사용자 설정 파일을 인증 재사용에 함께 가져오지 않는다.
- Manager는 Codex `config.toml`이나 Claude 사용자 설정 파일을 생성하지 않는다. 빈 설정은 파일이 없는 상태를 뜻하며 CLI가 원하는 최소 config를 자동 생성한다고 전제하지 않는다. Model·Effort·Fast 선택, 공통·역할별 지침 및 쓰기 제한·자동 승인 검토에 필요한 실행값은 기존 Manager 설정과 명시적인 호출 입력으로 제공한다. 기존 사용자 설정의 상속을 선택하는 항목은 분리된 호출에서의 CLI 기본 동작을 따른다.
- 인증 확인, 설정·권한 확인과 실제 Agent 호출은 같은 자동 실행 환경을 사용한다. 사용하지 않는 개인 설정의 Plugin·Hook을 이유로 호출을 차단하거나 개인 설정을 다시 읽지 않는다. 신규 session·재개·재시도·새 session fallback에 같은 분리를 적용한다.
- 기존 자동 실행 저장소의 개인 config 연결도 해소한다. Manager가 생성한 연결임을 확인할 수 있는 항목만 분리하며 인증 원본·개인 설정과 무관한 기존 작업물·session·로그는 보존한다. 소유권이나 입력 분리를 확인할 수 없으면 원인을 안내하고 해당 호출을 시작하지 않는다.
- Linux·macOS와 지원되는 native Windows 호출에 같은 원칙을 적용한다. provider·OS별 공식 인증 방식의 차이를 허용하되 개인 설정 전체를 다시 상속하는 대체 실행은 하지 않는다. 인증 재사용 실패는 해당 provider·프로젝트의 오류로 처리하며 다른 provider로 임의 전환하거나 독립 작업을 중단하지 않는다.
- 별도 home만으로 프로젝트·관리 설정의 Plugin·Hook까지 비활성화됐다고 간주하지 않는다. 기존 프로젝트 지침과 관리 정책의 적용·검증, 확장 기능 비활성화 및 충돌 거부를 유지한다. 이 변경으로 Agent의 쓰기 범위나 자동 승인 정책을 완화하지 않는다. 환경 변경으로 과거 호출 근거가 달라지면 기존 재검증·session 복구 규칙을 적용하며 작업·교정·실패 이력을 초기화하지 않는다.

## Acceptance Criteria

- `CODEX_HOME`·`CLAUDE_CONFIG_DIR`이 없는 scheduler 환경에서 두 provider의 관리 호출이 별도 저장소를 선택하고 기존 기본 인증을 재사용한다. 명시된 인증 원본 경로도 개인 설정 상속 없이 사용할 수 있다.
- 개인 설정에 Plugin·Hook이 있는 fixture에서 그 파일·디렉터리가 자동 실행 환경에 복사·연결되지 않고, 개인 Hook이 호출되거나 그 설정 때문에 사전 검사가 거부되지 않는다. 실제 사용자 Plugin·Hook을 실행하지 않는 모의 호출과 fixture로 확인한다.
- 새 자동 실행 저장소에 Codex `config.toml`·Claude 사용자 설정 파일이 없는 상태로 호출할 수 있다. 개인 설정을 읽는 링크와 Manager가 생성한 빈 config 파일이 없으며 필요한 Model·Effort·지침·권한 설정은 명시적인 호출 입력으로 전달된다.
- 인증 확인·설정 검사·신규 호출·재개·fallback이 동일한 저장소와 설정 범위를 사용한다. 개인 config 변경만으로 자동 호출의 유효 설정 지문이 달라지지 않으며 실제 사용하는 Manager·프로젝트·관리 설정의 변경은 계속 판정에 반영된다.
- 기존 Manager 소유 config 연결을 분리한 뒤에도 인증 원본·사용자 설정·기존 session·작업물·로그가 보존된다. 재개가 불가능하면 기존 문맥과 이력을 보존하는 새 session 복구를 사용한다. 소유권 미확인 항목은 임의 삭제하지 않고 해당 호출을 거부한다.
- 지원되는 provider·OS별 인증 재사용 성공·실패를 확인한다. 실패 시 개인 home 재사용·설정 일괄 복제·대화형 로그인·권한 확대가 발생하지 않으며 비밀값이 출력이나 저장 기록에 노출되지 않는다. 실제 CLI·계정이 없는 환경의 모의 검증을 실계정 호출 성공으로 기록하지 않는다.
- 기존 프로젝트·관리 설정의 확장 기능 충돌, 역할별 쓰기 제한·자동 승인 검토와 Reviewer 읽기 전용 계약을 유지한다. 원본 사용자 저장소와 부모 환경은 변경되지 않는다.

## Product Impact

- 개인 CLI의 Plugin·Hook 설정을 유지하면서 Codex·Claude 자동 실행에는 인증만 재사용한다.
- scheduler별 provider home 주입이나 개인 config 편집 없이 Manager가 분리된 실행 환경을 준비한다.
- 자동 실행의 모델·지침·권한은 Manager가 전달하는 실행 입력과 기존 프로젝트·관리 정책으로 결정된다.

## Non-Goals

- 사용자 Plugin·Hook의 설치·삭제·설정 변경 또는 자동 실행에서의 활성화.
- 새 인증 방식·계정 관리·대화형 로그인 기능과 인증 자료의 별도 복제 저장.
- 프로젝트 지침·조직 관리 정책의 일괄 무시나 기존 미지원 provider·OS의 지원 확대.
- 실제 cron·작업 스케줄러 설정의 자동 편집과 무관한 session·로그의 초기화.
