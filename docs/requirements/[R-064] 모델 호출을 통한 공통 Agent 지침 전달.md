# [R-064] 모델 호출을 통한 공통 Agent 지침 전달

## Context

지침 분리 전에는 등록 프로젝트가 각자의 `AGENTS.md`에 Loop Manager 공통 본문을 포함하거나 불일치를 승인해야 했다. 공통 규칙을 바꿔도 기존 프로젝트에는 자동 반영되지 않아 복사본을 따로 관리해야 하고, 프로젝트 전용 규칙과 자동 실행 규칙의 소유권도 섞인다. 같은 파일을 읽는 사용자와 대화형 Agent에게도 자동 실행의 ExecPlan 절차가 적용되는 것처럼 보일 수 있다.

프로젝트는 자신의 `AGENTS.md`를 유지하고, Loop Manager는 공통·역할별 실행 지침을 파일로 관리해 호출 역할에 맞게 합친 instruction을 전달해야 한다. 이 변경은 PRODUCT·ARCHITECTURE의 공통 본문 포함 검사, 루트 AGENTS를 공통 원본으로 사용하는 규칙과 공통 지침 배포 방식을 대체한다. R-033의 반복 없는 세션 입력과 관련 검증 책임은 유지한다. R-061의 AGENTS 사전 사용자 판단은 프로젝트 루트 `AGENTS.md`에만 적용하며 `docs/AGENTS.*.md`는 아래의 일반 수정·PR 보고 규칙을 따른다. 전달 방식 변경만으로 미구현 역할 정책을 구현된 것으로 취급하지 않는다.

## Requirement

### 공통·역할별 규칙과 프로젝트 규칙

- 실행 지침의 원본은 Loop Manager runtime의 `docs/AGENTS.common.md`와 역할별 `docs/AGENTS.planner.md`·`docs/AGENTS.planner_check.md`·`docs/AGENTS.worker.md`·`docs/AGENTS.reviewer.md`다. 공통에는 모든 자동 역할에 적용되는 기준만 남기고, 특정 역할의 권한·금지사항·작성·판단·검토·검증 절차는 해당 역할 파일에 둔다. 파일들은 이어붙일 실행 지침이므로 자신의 구성·합성·snapshot·버전 관리에 대한 설명을 넣지 않는다. 초기 분리는 기존 루트 AGENTS와 역할 prompt의 규칙을 기준으로 필요한 내용만 옮기며 기준 revision·분리 내용·이유를 구현 PR에서 설명한다. 루트에는 Loop Manager 개발에 필요한 작업 지침만 두며 docs의 규칙·스펙과 코드·문서로 쉽게 확인할 수 있는 설명을 반복하지 않는다.
- 게시된 공통·역할별 파일이 이후 실행 원본이다. 각 프로젝트에 복사하지 않고 프로그램이 선택한 게시된 runtime worktree의 내용을 사용한다. 매 호출마다 루트 `AGENTS.md`에서 원본을 재생성하지 않으며, source checkout의 로컬 편집이나 선택한 작업 worktree·등록 프로젝트의 동명 파일을 실행 지침의 원본으로 사용하지 않는다.
- Manager는 일반·유지보수·수동 제출 Planner에 common+planner, 읽기 전용 점검에 common+planner_check, Worker에 common+worker, Reviewer에 common+reviewer를 합쳐 전달한다. 다른 역할의 상세 지침을 한 호출에 함께 넣지 않는다. 합친 실행용 파일은 저장소 밖 Manager 상태 디렉터리에만 만들며 커밋하지 않는다. 고정된 원본 묶음에서 같은 내용을 재생성할 수 있어야 한다.
- 등록 프로젝트의 루트 `AGENTS.md`는 프로젝트 전용 규칙이다. 파일 존재·읽기·UTF-8 조건은 유지하되 공통 본문의 포함 여부, 내용 동일성 또는 불일치 승인을 등록 조건으로 요구하지 않는다. 다른 필수 문서와 `docs/PLANS.md` 검사는 유지한다.
- 모든 지원 역할·provider의 신규·재개·복구 호출에 common+해당 역할 내용을 Codex의 추가 developer instruction 또는 Claude의 append system prompt로 전달한다. provider의 기본 지침과 기존 추가 지침, 프로젝트 규칙을 보존한다. 정적 공통·역할 규칙은 사용자 메시지에 복사하지 않으며 작업별 목표·snapshot·승인 사실·피드백·결과 형식만 prompt에 둔다.
- 공통·역할별 instruction은 Loop Manager 자동 실행의 역할·권한·승인·검증·게시 책임에 적용한다. 프로젝트의 언어·코딩 규칙·빌드 방법은 프로젝트 지침을 따른다. 프로젝트 지침이나 작업별 사용자 prompt만으로 자동 실행 권한을 넓히거나 필요한 승인을 생략하지 않는다. 제품 목표의 의미를 바꿔야 해결되는 충돌은 사용자 판단을 기다린다.

### 로컬 직접 작업과 자동 실행의 경계

- ExecPlan 생성·계획 작성은 Loop Manager가 호출하는 Planner를 포함한 매니저의 자동 계획 흐름이 담당한다. 사용자가 직접 수행하거나 대화형 Agent에게 위임한 로컬 작업은 구현 전에 ExecPlan을 작성하지 않는다. SKILL·프로젝트 AGENTS에도 직접 작업의 ExecPlan 선작성 의무를 두지 않는다. 저장소가 등록돼 있거나 같은 AGENTS를 읽는다는 이유로 직접 작업을 자동 Worker 작업으로 취급하지 않는다.
- 프로젝트 `AGENTS.md`에는 구현 전 ExecPlan 선작성 의무를 추가하지 않는다. Loop Manager의 자동 작업은 기존 Planner·작업 선택 흐름에서 ExecPlan을 준비하고 실행 gate를 확인한다. 이 저장소 루트에서도 해당 의무 문장을 제거하며, 다른 프로젝트의 본문을 자동으로 삭제하지 않는다.
- 새로운 기능이나 정책 변경은 직접 작업과 자동 작업 모두 Requirement에서 시작한다. 대화형 Agent는 사용자 요청의 관련 활성 Requirement를 먼저 작성하거나 갱신하며 별도의 문서 작성 요청을 요구하지 않는다. 기존 활성 Requirement가 요청·Acceptance Criteria를 충분히 담으면 재사용하고 중복 파일을 만들지 않는다. 보관된 Requirement는 읽기만 하며 재사용·수정·삭제·활성 위치 복원을 하지 않는다. 보관 문서와 관련된 새 변경은 새로운 고유 ID·경로의 Requirement로 작성한다. 미결정 정책은 사용자 판단으로 해소하며 자동 Planner·Worker가 새 제품 목표를 임의로 추가할 권한으로 확대하지 않는다.
- 프로젝트로 복제하는 Specification Skill에는 PRODUCT·ARCHITECTURE·Requirement·FUTURE_IDEAS 작성·검토와 사용자가 알아야 할 문서 취급 기준만 둔다. Requirement 작성·갱신과 보관 문서의 읽기 전용 범위는 유지하며 계획 생성·역할별 실행·SQLite·runtime·게시·archive 판정 같은 Manager 동작은 설명하지 않는다. 프로젝트 루트 AGENTS와 새 프로젝트의 최소 AGENTS는 Skill을 참조하며 이미 설명된 문서 작성 규칙을 반복하지 않는다.
- 직접 작업에 Loop Manager의 SQLite 상태 전이·Worker와 Reviewer의 역할별 절차·ExecPlan 완료 판정을 요구하지 않는다. 자동 작업에는 기존 ExecPlan·dependency·targeted test·Manager 전체 verify·Review·사용자 Merge 조건을 그대로 적용한다. 직접 작업의 결과만으로 자동 작업의 상태나 검증 성공을 대신 기록하지 않는다.
- 로컬에서 구현한 결과와 활성 Requirement가 `origin/<base-branch>`에 반영되면, Loop Manager는 기존 입력 변경·작업 선택 정책에 따라 실제 코드·테스트와 요구사항의 정합성·미충족 작업을 재점검한다. 이미 충족된 구현은 중복 계획하지 않고 직접 작업에 소급해 ExecPlan을 요구하지 않는다. 남은 작업에 필요한 ExecPlan만 생성하거나 허용된 기존 계획을 개정한다. 미커밋 변경·로컬 전용 commit은 자동 입력으로 사용하지 않으며, Requirement의 유지·archive 조건과 동일 입력에서의 반복 호출 억제는 유지한다.

### 버전 보존과 실패

- 새 작업은 선택한 runtime의 공통·모든 역할 원본을 하나의 묶음으로 고정한다. 하나의 ExecPlan 작업에서 Worker와 Reviewer는 같은 원본 묶음 버전을 사용하되 실제 instruction은 common+각 역할로 구분한다. 독립 planning·점검·유지보수·수동 제출 작업도 각 작업의 버전을 보존한다.
- 원본 묶음의 내용 해시·source revision·snapshot과 작업·session 관계를 모델 실행 전에 보존하고, 역할별 실제 전달 내용과 해시를 호출에 결합한다. Worker와 Reviewer의 합친 내용 해시는 서로 다를 수 있다. 재개·재시도·압축 뒤 호출과 session-unavailable 또는 provider·Model 변경의 새 세션도 같은 원본 묶음을 사용한다. 공통·역할 규칙 업데이트는 새 작업부터 반영한다.
- 작업 worktree의 공통·역할별 파일을 수정하거나 Reviewer가 그 diff를 읽어도 현재 작업의 원본 묶음과 주입 내용은 바뀌지 않는다. Merge 뒤 새 runtime에서 선택한 원본만 이후 새 작업에 적용한다.
- 모든 역할 원본을 포함한 묶음 내용 해시는 planning 입력과 관련 Agent 성공 결과의 입력 동일성 판단에 포함한다. 역할 파일만 바뀐 새 작업도 옛 규칙을 전제로 한 판단을 그대로 재사용하지 않으며, 내용이 같으면 runtime revision이나 파일 위치만 달라졌다는 이유로 반복 재계획하지 않는다.
- 기존 단일 Markdown snapshot이 저장된 작업은 원래 내용으로 재개한다. 최신 역할 파일을 덧붙이거나 과거 전달 내용을 새로운 묶음으로 소급 변경하지 않는다. 합친 실행용 파일이 없으면 고정된 원본에서 재생성할 수 있지만 원본 snapshot의 누락·손상은 최신 지침으로 대체하지 않는다.
- 지침 버전 기록이 없는 기존 세션은 최신 규칙을 적용했다고 간주하지 않는다. 기존 세션·작업물·실패 이력을 보존하고, 지원되는 복구 절차로 필요한 최소 문맥을 가진 새 세션을 시작해 해당 작업의 원본 버전을 확정한다.
- 원본 파일 누락·빈 내용·읽기 또는 인코딩 오류, 알 수 없는 역할, 보존된 내용과 해시의 불일치, 필요한 전달 기능의 미지원·설정 충돌은 모델 실행 전에 해당 호출을 중단하고 원인을 보존한다. 손상된 버전을 최신 내용으로 대체하거나 사용자 메시지 반복, 권한 확대 또는 무조건적인 세션 교체로 우회하지 않는다. 무관한 작업의 중단 사유로 확대하지 않는다.

### 공통·역할별 파일 변경과 프로젝트 지침 승인

- 작업 worktree의 공통·역할별 `docs/AGENTS.*.md`는 현재 역할·목표의 일반 파일 수정 권한을 따른다. 파일 이름만으로 추가 수정 제한이나 guidance 제안·사전 승인·승인 대기 중단을 요구하지 않는다. Planner·Reviewer의 일반 쓰기 제한과 실행 중 runtime worktree 자체의 편집 금지는 유지하며, 작업 중 역할 파일 수정으로 현재 실행 권한을 확대하지 않는다.
- 공통·역할별 파일이 변경된 PR에는 해당 경로, 변경 사실·내용·이유·영향과 최종 diff 링크를 명시해 사용자가 확인할 수 있게 한다. Manager는 실제 diff와 보고를 대조해 누락을 보완하고 Reviewer는 일반 변경과 함께 검토한다. PR Merge·새 runtime 선택 전의 수정본은 현재 실행 지침으로 사용하지 않는다.
- 프로젝트 루트 `AGENTS.md`는 Loop Manager 자체 저장소에서도 `Scope: project`의 사전 사용자 판단 대상이다. Worker는 바로 수정하지 않고 ExecPlan의 `Decision Log`에 제안과 빈 `User Decision`을 기록한 뒤 승인·거절·대체 결정을 기다린다. 사전 승인 기능이 Merge된 이후에는 게시된 정확한 제안·patch·Baseline과 사용자 결정을 검증해 이미 받은 승인을 사용할 수 있다. Planner·Reviewer의 프로젝트 AGENTS 쓰기 금지와 정확한 대상·patch 대조는 유지한다.
- 기존 루트 `AGENTS.md`를 대상으로 한 공통 승인 기록·승인 대기는 원래 대상·baseline·결정·patch의 의미를 유지한다. 이를 새 파일의 승인으로 옮기거나 기존 승인을 일괄 적용하지 않는다. 원래 대상에 안전하게 적용할 수 없으면 해당 제안만 보존해 정확한 새 사용자 판단을 기다린다.

### 설치와 기존 파일 정리

- 준비 도구는 기존 프로젝트 `AGENTS.md`를 보존하고 그 파일이 있다는 이유만으로 나머지 준비를 거부하지 않는다. 파일이 없는 새 프로젝트에는 프로젝트 전용 개발 안내와 Specification Skill 참조를 담은 최소 파일을 준비하며 자동 실행 공통 본문·문서별 규칙·필수 문서 조건은 복사하지 않는다. Requirement 우선 규칙은 Skill에서, 필수 문서 조건은 기존 등록·계획 입력 검사에서 유지한다. 다른 기존 파일·폴더의 덮어쓰기 보호는 유지한다.
- 공통 주입이 적용된 runtime은 공통 본문이 남아 있는 기존 프로젝트와 프로젝트 전용 내용만 있는 프로젝트를 모두 처리한다. 등록 재승인이나 공통 본문 제거를 실행의 선행 조건으로 만들지 않는다. 기존 불일치 승인 기록은 감사 목적으로 보존한다.
- 이 저장소 루트의 선작성 의무 문장 제거 외에 나머지 공통 본문 제거는 주입 기능의 구현 PR Merge와 runtime 검증 후 수행하는 별도 작업이다. 이 저장소는 정확한 삭제 diff와 Baseline에 대한 사용자 사전 승인을 별도 ExecPlan에 기록·게시할 수 있다. 주입 기능과 사전 승인 기능의 Merge, runtime 주입 검증 통과를 확인한 뒤 작업 worktree에서 승인 patch를 적용하고 변경 내용을 명시한 PR을 남긴다. 승인 당시 내용이 달라지면 재승인을 받는다. Loop Manager는 각 프로젝트의 공통 부분을 추측해 제거하거나 기본 checkout을 편집하지 않는다. 본문 제거가 끝나지 않았다는 이유로 이 전달 기능을 미구현으로 취급하지 않는다.
- 위 후속 정리 조건은 Loop Manager 자동 Worker 작업에 적용한다. 사용자가 직접 요청한 로컬 본문 정리는 앞의 직접 작업 경계를 따르며, 자동 후속은 최신 Merge된 본문과 실제 주입 근거를 대조해 남은 변경만 수행한다. 이미 반영된 정리를 반복하거나 직접 요청을 자동 Worker의 승인·검증·완료 기록으로 이관하지 않는다.

## Acceptance Criteria

- 같은 등록 프로젝트에서 직접 작업은 관련 활성 Requirement 작성·갱신 또는 충분한 기존 활성 문서의 재사용으로 시작하고 ExecPlan을 만들지 않는다. 보관 Requirement는 읽기만 하며 새 변경은 신규 Requirement로 작성한다. 새 ExecPlan은 크기와 관계없이 매니저의 자동 계획 흐름에서 작성하며 직접 작업에 자동 역할·SQLite 상태·ExecPlan 완료 절차를 요구하지 않는다.
- runtime의 common에는 모든 역할의 공통 기준만, 역할 파일에는 해당 역할의 규칙만 남는다. 초기 분리의 기준 revision·내용·이유를 확인할 수 있고 이후 원본은 게시된 공통·역할별 파일이다. 루트 AGENTS나 작업별 사용자 prompt에서 원본을 재생성하지 않는다.
- 이 저장소 루트와 새 프로젝트의 최소 `AGENTS.md`에는 구현 전 ExecPlan 선작성 의무가 없다. 자동 작업의 ExecPlan 준비·dependency gate는 Planner·작업 선택 흐름에서 유지되며 다른 프로젝트의 기존 본문은 임의로 삭제하지 않는다.
- Specification Skill은 네 종류의 제품 명세 작성·검토와 보관 Requirement 취급 기준만 설명하며 Manager 내부 동작은 포함하지 않는다. 루트 AGENTS·새 프로젝트용 복사 스크립트는 같은 Skill을 참조하며 작성 절차·문서 역할을 중복하지 않는다. 별도 문서 작성 요청이 없다는 이유로 대화형 Agent의 사용자 요청에 따른 Requirement 작성을 거부하지 않는다.
- 루트 AGENTS에는 Loop Manager 개발에 필요한 작업 지침만 남고, 새 프로젝트의 최소 AGENTS는 프로젝트 전용 개발 안내와 Skill 참조만 담는다. 문서·코드에 있는 규칙·스펙·구조·실행 설명을 중복하지 않으며 필수 문서 조건은 등록·계획 입력 검사에서 유지한다.
- 공통·역할별 instruction에는 해당 역할의 행동 기준만 있고 지침 파일 자체의 구성·합성·snapshot·버전 관리 설명은 없다. 실행용 파일 생성과 원본 고정은 기존 Manager 코드와 제품·설계 명세에서 유지된다.
- 직접 구현과 활성 Requirement를 원격 base에 반영하면 기존 Planner 선택 정책에 따른 재점검이 이루어진다. 충족된 구현의 중복 계획·소급 ExecPlan 요구·자동 검증 성공 합성 없이 남은 작업만 계획하며, 로컬 전용 변경과 기존 archive·반복 호출 억제 조건을 보존한다.
- 프로젝트 전용 `AGENTS.md`로 불일치 승인 없이 등록·실행할 수 있고, 다른 필수 문서·원격 입력 조건은 유지된다.
- 모든 지원 provider·역할의 신규·재개·복구 호출이 common+해당 역할을 developer 또는 system instruction으로 전달하며 기본 지침·기존 추가 지침·프로젝트 규칙과 실행 경계를 보존한다. 작업별 사용자 prompt에는 정적 공통·역할 규칙이 중복되지 않는다.
- 같은 작업의 Worker·Reviewer·재시도·복구는 동일한 원본 묶음 해시를 사용하며 실제 전달 내용은 각 역할에 맞게 합성해 별도 해시로 기록한다. 새 작업만 최신 원본으로 시작하고 세션 압축 뒤에도 다른 원본 버전이 섞이지 않는다.
- 합친 파일은 저장소 밖 실행용으로만 생성하고 커밋하지 않는다. 파일이 없어도 고정된 원본으로 재생성하며 원본 누락·손상이나 알 수 없는 역할은 모델 실행 전에 거부한다. 기존 단일 Markdown snapshot은 최신 역할 지침을 섞지 않고 원래 내용으로 재개한다.
- 공통 또는 역할 파일만의 내용 변경도 관련 planning·성공 결과 재사용 판단에 반영되지만 동일 내용의 재실행·runtime 갱신은 불필요한 반복 재계획을 만들지 않는다.
- 버전 기록 없는 기존 세션의 복구는 원래 작업·세션·실패 이력을 보존한다. 손상된 snapshot, 파일 오류와 전달 기능 미지원은 모델 프로세스 시작 전에 확인되고 해당 호출의 진단으로 남는다.
- 작업 worktree의 공통·역할별 파일은 허용된 역할·목표의 일반 권한으로 수정·검토·게시할 수 있고, 파일 이름만으로 guidance 승인 대기나 특별한 범위 위반을 만들지 않는다. 수정본을 읽어도 Worker·Reviewer의 고정 원본 버전은 그대로다.
- 공통·역할별 파일 변경 PR에서 실제 최종 diff에 맞는 변경 사실·내용·이유·영향과 diff 링크를 확인할 수 있다. PR head·rebase 변경 후의 누락이나 오래된 보고도 보완된다.
- 자동 Worker의 프로젝트 루트 `AGENTS.md`만 ExecPlan 제안·사용자 판단 후 정확한 patch로 변경된다. 공통·역할별 `docs/AGENTS.*.md`를 이 승인 흐름에 넣지 않으며 과거 결정은 원래 루트 대상에만 유효하다.
- 준비 도구가 기존 `AGENTS.md`를 그대로 보존하며, 새 프로젝트에는 공통 본문 없는 최소 파일을 만든다. 기존 복사본이 남은 프로젝트도 실행 가능하다.
- 주입 기능 자체는 기존 공통 본문을 제거하거나 기본 checkout을 정리하지 않는다. 자동 후속의 남은 정리는 선행 Merge·runtime 검증·정확한 diff의 사용자 승인을 충족한 별도 작업 worktree와 PR로 수행한다. 직접 요청으로 이미 반영한 정리는 반복하지 않는다. 문서·설정 안내·등록·호출·PR 보고가 같은 공통·역할별 원본을 설명하고 프로젝트 AGENTS 승인은 별도 대상으로 유지된다.
- targeted test·Manager 전체 verify·읽기 전용 Review의 책임, dependency·게시·사용자 Merge 조건은 유지된다.

## Product Impact

- 프로젝트별 지침과 Loop Manager 공통·역할별 실행 규칙을 따로 관리할 수 있다.
- Requirement는 직접 작업과 자동 작업의 공통 변경 기준으로 유지하고, ExecPlan은 Loop Manager 자동 구현의 실행 계획으로 사용한다.
- 공통·역할 규칙은 프로젝트별 파일 배포 없이 새 작업에 반영되고, 진행 중인 작업의 규칙은 재현 가능하게 보존된다.
- 공통·역할별 파일 변경은 일반 작업·PR 검토로, 자동 Worker의 프로젝트 AGENTS 변경은 사전 사용자 판단과 정확한 patch 승인으로 처리한다.

## Non-Goals

- 기존 프로젝트의 공통 본문을 자동 판별·제거하거나 기본 checkout에 commit·push하지 않는다. 이 저장소의 정확한 diff로 승인된 별도 후속 정리는 위 조건을 따른다.
- 공통 파일 링크의 자동 추적, 원격 URL 지침 다운로드, 사용자 전역 설정 변경을 요구하지 않는다.
- 일반 역할 권한·검증·프로젝트 AGENTS 사전 승인·Git 소유권을 완화하거나 R-061의 다른 정책을 이 변경만으로 구현하지 않는다.
- provider transport, sandbox 또는 Model 선택 정책을 변경하지 않는다.
- 기존 session·승인·실패 이력을 삭제하거나 전체 대화를 재구성하지 않는다.
- 문서 작성만으로 운영 SQLite·기존 ExecPlan 상태·프로젝트 등록을 변경하지 않는다.
