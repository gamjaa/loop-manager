# [R-064] 모델 호출을 통한 공통 Agent 지침 전달

## Context

현재 등록 프로젝트는 각자의 `AGENTS.md`에 Loop Manager 공통 본문을 포함하거나 불일치를 승인해야 한다. 공통 규칙을 바꿔도 기존 프로젝트에는 자동 반영되지 않아 복사본을 따로 관리해야 하고, 프로젝트 전용 규칙과 자동 실행 규칙의 소유권도 섞인다.

프로젝트는 자신의 `AGENTS.md`를 유지하고, Loop Manager는 모델 호출 설정에 공통 실행 지침을 추가해야 한다. 이 변경은 PRODUCT·ARCHITECTURE의 공통 본문 포함 검사, 루트 AGENTS를 공통 원본으로 사용하는 규칙과 공통 지침 배포 방식을 대체한다. R-033의 반복 없는 세션 입력과 관련 검증 책임은 유지한다. R-061의 AGENTS 사전 사용자 판단은 프로젝트 `AGENTS.md`에만 적용하며 공통 파일은 아래의 일반 수정·PR 보고 규칙을 따른다. 전달 방식 변경만으로 미구현 역할 정책을 구현된 것으로 취급하지 않는다.

## Requirement

### 공통 규칙과 프로젝트 규칙

- 공통 원본은 Loop Manager 저장소의 `docs/AGENTS.common.md`다. 각 프로젝트에 복사하지 않고 프로그램이 선택한 게시된 runtime worktree의 내용을 모델 호출 설정으로 주입한다. source checkout의 로컬 편집이나 선택한 작업 worktree·등록 프로젝트의 동명 파일을 실행 지침의 원본으로 사용하지 않는다.
- 등록 프로젝트의 루트 `AGENTS.md`는 프로젝트 전용 규칙이다. 파일 존재·읽기·UTF-8 조건은 유지하되 공통 본문의 포함 여부, 내용 동일성 또는 불일치 승인을 등록 조건으로 요구하지 않는다. 다른 필수 문서와 `docs/PLANS.md` 검사는 유지한다.
- 일반 Planner, 읽기 전용 점검, Worker, Reviewer, 유지보수와 복구를 포함한 모든 모델 호출에 공통 지침을 전달한다. provider의 기본 지침과 기존 추가 지침, 프로젝트 규칙을 보존하며 같은 세션의 사용자 메시지에 공통 본문이나 반복 읽기 지시를 누적하지 않는다.
- 공통 지침은 Loop Manager 자동 실행의 역할·권한·승인·검증·게시 책임에 적용한다. 프로젝트의 언어·코딩 규칙·빌드 방법은 프로젝트 지침을 따른다. 프로젝트 지침으로 자동 실행 권한을 넓히거나 필요한 승인을 생략하지 않는다. 제품 목표의 의미를 바꿔야 해결되는 충돌은 사용자 판단을 기다린다.

### 버전 보존과 실패

- 새 작업은 선택한 runtime의 공통 지침을 사용한다. 하나의 ExecPlan 작업에서 Worker와 Reviewer는 같은 공통 버전을 사용하며, 독립 planning·점검·유지보수 작업도 각 작업의 버전을 보존한다.
- 실제 전달할 내용, 내용 해시, 원본 revision과 작업·session 관계를 모델 실행 전에 확정한다. 재개·재시도·압축 뒤 호출과 session-unavailable 또는 provider·Model 변경의 새 세션도 진행 중인 작업의 버전을 유지한다. 공통 규칙 업데이트는 새 작업부터 반영한다.
- 작업 worktree의 공통 파일을 수정하거나 Reviewer가 그 diff를 읽어도 이미 주입한 공통 버전은 바뀌지 않는다. Merge 뒤 새 runtime에서 선택한 원본만 이후 새 작업에 적용한다.
- 공통 내용 해시는 planning 입력과 관련 Agent 성공 결과의 입력 동일성 판단에 포함한다. 공통 내용이 바뀐 새 작업에서 옛 규칙을 전제로 한 판단을 그대로 재사용하지 않으며, 내용이 같으면 runtime revision이나 파일 위치만 달라졌다는 이유로 반복 재계획하지 않는다.
- 공통 버전 기록이 없는 기존 세션은 최신 규칙을 적용했다고 간주하지 않는다. 기존 세션·작업물·실패 이력을 보존하고, 지원되는 복구 절차로 필요한 최소 문맥을 가진 새 세션을 시작해 해당 작업의 공통 버전을 확정한다.
- 파일 누락·빈 내용·읽기 또는 인코딩 오류, 보존된 내용과 해시의 불일치, 필요한 전달 기능의 미지원·설정 충돌은 모델 실행 전에 해당 호출을 중단하고 원인을 보존한다. 손상된 버전을 최신 내용으로 대체하거나 사용자 메시지 반복, 권한 확대 또는 무조건적인 세션 교체로 우회하지 않는다. 무관한 작업의 중단 사유로 확대하지 않는다.

### 공통 파일 변경과 프로젝트 지침 승인

- 작업 worktree의 `AGENTS.common.md`는 일반 작업 파일로 직접 수정할 수 있다. 해당 파일만의 추가 수정 제한이나 guidance 제안·사전 승인·승인 대기 중단을 요구하지 않으며, 현재 작업의 일반 파일 수정 권한을 따른다. 실행 중인 runtime worktree 자체를 편집하는 권한으로 확대하지 않는다.
- 공통 파일이 변경된 PR에는 해당 경로, 변경 사실·내용·이유·영향과 최종 diff 링크를 명시해 사용자가 확인할 수 있게 한다. Manager는 실제 diff와 보고를 대조해 누락을 보완하고 Reviewer는 일반 변경과 함께 검토한다. PR Merge·새 runtime 선택 전의 수정본은 현재 실행 지침으로 사용하지 않는다.
- 프로젝트 루트 `AGENTS.md`는 Loop Manager 자체 저장소에서도 `Scope: project`의 사전 사용자 판단 대상이다. Worker는 바로 수정하지 않고 ExecPlan의 `Decision Log`에 제안과 빈 `User Decision`을 기록한 뒤 승인·거절·대체 결정을 기다린다. 사전 승인 기능이 Merge된 이후에는 게시된 정확한 제안·patch·Baseline과 사용자 결정을 검증해 이미 받은 승인을 사용할 수 있다. Planner·Reviewer의 프로젝트 AGENTS 쓰기 금지와 정확한 대상·patch 대조는 유지한다.
- 기존 루트 `AGENTS.md`를 대상으로 한 공통 승인 기록·승인 대기는 원래 대상·baseline·결정·patch의 의미를 유지한다. 이를 새 파일의 승인으로 옮기거나 기존 승인을 일괄 적용하지 않는다. 원래 대상에 안전하게 적용할 수 없으면 해당 제안만 보존해 정확한 새 사용자 판단을 기다린다.

### 설치와 기존 파일 정리

- 준비 도구는 기존 프로젝트 `AGENTS.md`를 보존하고 그 파일이 있다는 이유만으로 나머지 준비를 거부하지 않는다. 파일이 없는 새 프로젝트에는 프로젝트 규칙과 필수 문서 안내를 담은 최소 파일을 준비하며 공통 본문은 복사하지 않는다. 다른 기존 파일·폴더의 덮어쓰기 보호는 유지한다.
- 공통 주입이 적용된 runtime은 공통 본문이 남아 있는 기존 프로젝트와 프로젝트 전용 내용만 있는 프로젝트를 모두 처리한다. 등록 재승인이나 공통 본문 제거를 실행의 선행 조건으로 만들지 않는다. 기존 불일치 승인 기록은 감사 목적으로 보존한다.
- 기존 본문 제거는 주입 기능의 구현 PR Merge와 runtime 검증 후 수행하는 별도 작업이다. 이 저장소는 정확한 삭제 diff와 Baseline에 대한 사용자 사전 승인을 별도 ExecPlan에 기록·게시할 수 있다. 주입 기능과 사전 승인 기능의 Merge, runtime 주입 검증 통과를 확인한 뒤 작업 worktree에서 승인 patch를 적용하고 변경 내용을 명시한 PR을 남긴다. 승인 당시 내용이 달라지면 재승인을 받는다. Loop Manager는 각 프로젝트의 공통 부분을 추측해 제거하거나 기본 checkout을 편집하지 않는다. 본문 제거가 끝나지 않았다는 이유로 이 전달 기능을 미구현으로 취급하지 않는다.

## Acceptance Criteria

- 프로젝트 전용 `AGENTS.md`로 불일치 승인 없이 등록·실행할 수 있고, 다른 필수 문서·원격 입력 조건은 유지된다.
- 모든 지원 provider·역할의 신규·재개·복구 호출이 확정된 공통 내용을 전달하며 기본 지침·기존 추가 지침·프로젝트 규칙과 실행 경계를 보존한다.
- 같은 작업의 Worker·Reviewer·재시도·복구는 동일한 공통 내용 해시를 사용하고, 새 작업만 최신 내용으로 시작한다. 세션 압축 뒤에도 다른 공통 버전이 섞이지 않는다.
- 공통 내용 변경은 관련 planning·성공 결과 재사용 판단에 반영되지만 동일 내용의 재실행·runtime 갱신은 불필요한 반복 재계획을 만들지 않는다.
- 버전 기록 없는 기존 세션의 복구는 원래 작업·세션·실패 이력을 보존한다. 손상된 snapshot, 파일 오류와 전달 기능 미지원은 모델 프로세스 시작 전에 확인되고 해당 호출의 진단으로 남는다.
- 작업 worktree의 공통 파일은 별도 사전 승인 없이 일반 파일로 수정·검토·게시할 수 있고, 해당 수정만으로 guidance 승인 대기나 특별한 범위 위반을 만들지 않는다. 수정본을 읽어도 Worker·Reviewer의 실제 주입 버전은 그대로다.
- 공통 파일 변경 PR에서 실제 최종 diff에 맞는 변경 사실·내용·이유·영향과 diff 링크를 확인할 수 있다. PR head·rebase 변경 후의 누락이나 오래된 보고도 보완된다.
- 프로젝트 `AGENTS.md`만 ExecPlan 제안·사용자 판단 후 정확한 patch로 변경된다. 신규 공통 파일을 이 승인 흐름에 넣지 않으며 과거 결정은 원래 루트 대상에만 유효하다.
- 준비 도구가 기존 `AGENTS.md`를 그대로 보존하며, 새 프로젝트에는 공통 본문 없는 최소 파일을 만든다. 기존 복사본이 남은 프로젝트도 실행 가능하다.
- 주입 기능 자체는 기존 공통 본문을 제거하거나 기본 checkout을 정리하지 않는다. 이 저장소의 후속 정리는 선행 Merge·runtime 검증·정확한 diff의 사용자 승인을 충족한 별도 작업 worktree와 PR로 수행한다. 문서·설정 안내·등록·호출·PR 보고가 같은 공통 원본을 설명하고 프로젝트 AGENTS 승인은 별도 대상으로 유지된다.
- targeted test·Manager 전체 verify·읽기 전용 Review의 책임, dependency·게시·사용자 Merge 조건은 유지된다.

## Product Impact

- 프로젝트별 지침과 Loop Manager 공통 실행 규칙을 따로 관리할 수 있다.
- 공통 규칙은 프로젝트별 파일 배포 없이 새 작업에 반영되고, 진행 중인 작업의 규칙은 재현 가능하게 보존된다.
- 공통 파일 변경은 일반 작업·PR 검토로, 프로젝트 AGENTS 변경은 사전 사용자 판단과 정확한 patch 승인으로 처리한다.

## Non-Goals

- 기존 프로젝트의 공통 본문을 자동 판별·제거하거나 기본 checkout에 commit·push하지 않는다. 이 저장소의 정확한 diff로 승인된 별도 후속 정리는 위 조건을 따른다.
- 공통 파일 링크의 자동 추적, 원격 URL 지침 다운로드, 사용자 전역 설정 변경을 요구하지 않는다.
- 일반 역할 권한·검증·프로젝트 AGENTS 사전 승인·Git 소유권을 완화하거나 R-061의 다른 정책을 이 변경만으로 구현하지 않는다.
- provider transport, sandbox 또는 Model 선택 정책을 변경하지 않는다.
- 기존 session·승인·실패 이력을 삭제하거나 전체 대화를 재구성하지 않는다.
- 문서 작성만으로 운영 SQLite·기존 ExecPlan 상태·프로젝트 등록을 변경하지 않는다.
