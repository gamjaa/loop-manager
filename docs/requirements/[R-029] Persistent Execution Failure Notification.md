# [R-029] Persistent Execution Failure Notification

## Context

현재 Loop Manager는 verify·Review의 반복 실패를 계획 단위로 차단하고, 일시적 Agent·Git·서비스 오류는 기존 복구 분류에 따라 제한된 재시도 또는 다음 외부 실행에서 이어간다. G-041은 Worker session 교체·복구를, G-045는 rebase 충돌 교정을 구현 중이다. 이 경로들이 안전한 자동 복구를 시도하더라도 같은 오류가 여러 실행에서 남거나 자동 복구 불가능한 설정·권한 오류가 발생했을 때 사용자가 원인과 필요한 조치를 확인하는 별도 운영 알림은 충분하지 않다.

## Requirement

Loop Manager는 Planner·Worker·Reviewer 실행, verify, 계획 게시와 Git·PR 연동에서 오류가 발생하면 기존 구조화된 복구 분류와 해당 단계의 bounded 절차를 먼저 사용해야 한다. 이 Requirement는 G-041의 session 선택이나 G-045의 충돌 fingerprint·진전·차단 규칙을 변경하지 않는다. 복구 결과를 관찰해 동일 프로젝트의 같은 단계에서 진행 없는 동일 원인이 실제로 시도한 연속 세 번의 외부 실행에 걸쳐 남으면 프로젝트, 단계, 원인, 시도된 복구와 필요한 조치를 사용자에게 한 번 알린다. 진전이 확인된 교정이나 다른 단계의 실패를 같은 반복으로 합산하지 않는다.

설정·권한 오류처럼 기존 분류에서 자동 복구가 불가능하다고 확정된 원인은 반복 횟수를 기다리지 않고 즉시 알린다. 관련 계획이 이미 `PLAN_BLOCKED` 또는 `PROJECT_BLOCKED`로 전환돼 BLOCKED 알림이 생성되는 사건은 별도 오류 알림을 중복 생성하지 않는다. 원인이 해소되거나 단계·안정적인 원인이 바뀌면 연속 이력을 초기화하고 새 사건으로 취급한다. 일시 오류의 진행 상태와 작업 공간은 보존하며, 알림을 위해 새로운 Agent 호출, reset, 파일 삭제 또는 강제 게시를 수행하지 않는다.

알림은 기존 Telegram outbox를 사용하고, Telegram이 비활성화돼도 상태와 로그에서 같은 진단을 확인할 수 있어야 한다. 이 Requirement에서 만드는 구현 ExecPlan은 G-041과 G-045를 `depends_on`에 기록해 두 계획이 모두 `MERGED`된 뒤 결과 분류를 입력으로 연결한다. 진행 중인 문서·코드·ExecPlan을 개정하지 않는다.

## Acceptance Criteria

- 같은 구조화 원인이 해당 프로젝트의 같은 단계에서 실제로 시도한 연속 세 실행 동안 진전 없이 남으면 한 번만 장애 알림을 만든다.
- 한 실행 안의 기존 일시 오류 재시도, session fallback, 상태 재구성 및 rebase 교정을 다시 구현하거나 횟수를 변경하지 않는다.
- G-041의 session 전이에 진전이 있거나 G-045의 충돌 교정 marker가 진전하면 해당 오류를 진행 없는 반복으로 계산하지 않는다.
- 자동 복구 불가능하다고 확정된 설정·권한 오류는 즉시 원인과 필요한 사용자 조치를 알린다.
- 기존 BLOCKED 알림과 같은 사건의 별도 장애 알림을 만들지 않고, Telegram이 비활성화돼도 상태·로그에 진단을 남긴다.
- 성공 또는 원인 변경 뒤에는 이전 연속 횟수를 새 사건에 합산하지 않는다.
- 프로세스 중단·재시작 후에도 반복 원인, 시도 횟수와 알림 중복 방지 상태를 복구한다.
- 알림과 반복 이력 기록은 실행 상태, Worker session, 충돌 복구 기록 및 작업 공간을 변경하지 않는다.
- G-041·G-045와 근거인 R-018·R-019 문서를 수정하지 않고 별도 구현 계획으로 처리한다.
- 이 Requirement의 구현 계획은 G-041과 G-045가 모두 `MERGED`되기 전에 Worker를 시작하지 않는다.

## Product Impact

- 자동 복구가 계속 실패하거나 불가능하다고 확정되면 사용자가 원인과 조치를 알 수 있다.

## Non-Goals

- 기존 session·rebase 복구 절차나 차단 한도를 다시 설계하지 않는다.
- 일시적 외부 오류만으로 프로젝트 전체를 차단하지 않는다.
- 새 알림 서비스나 별도 감시 프로세스를 도입하지 않는다.
- 복구 범위를 증명하지 못한 오류에 임의의 저장소 변경을 시도하지 않는다.
