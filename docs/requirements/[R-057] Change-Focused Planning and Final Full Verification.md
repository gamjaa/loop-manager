# [R-057] 변경 중심 계획과 완료 전 문서 전문 확인

## Context

현재 일반 Planner는 PRODUCT·활성 Requirement·ARCHITECTURE와 현재 코드·테스트를 읽고 미충족 작업 전체를 계획하도록 요청받는다. R-049는 변경 입력에 따라 일반 Planner와 읽기 전용 빠른 점검을 구분하지만, 일반 Planner의 반복 호출에서 무엇을 우선 읽고 언제 문서 전체를 다시 점검할지는 충분히 구분하지 않는다.

평소에는 코드·문서의 변경이 기존 계획과 새 작업에 미치는 영향을 중심으로 검토하고, 남은 작업이 없는 완료 후보에서 문서 전문을 기준으로 누락을 최종 확인한다.

## Requirement

### 변경 중심 검토

- 비교 가능한 성공 기준이 있으면 마지막으로 적용된 계획 판단 이후의 코드·테스트·설정·제품 문서·active ExecPlan 변경을 우선 확인한다. 추가·수정뿐 아니라 삭제·이름 변경과 관련 dependency·계약의 영향도 포함한다. 기준과 변경 모두 최신 원격 입력으로 확인한다.
- 현재 비종료 compact catalog와 변경 내용을 대조해 기존 계획의 목표·범위·구현 방향·검증 조건·의존성에 변경이 필요한지 찾는다. 미착수 READY와 R-061의 사용자 판단 대기 draft는 허용된 무소유 snapshot 권한으로만 개정하며, 이미 실행한 계획과 snapshot 밖 계획을 바꾸지 않는다. draft의 개정·사용자 결정 확인을 작업 가능 전환과 혼동하지 않는다.
- 변경으로 새로 드러난 미충족 PRODUCT·활성 Requirement 작업은 기존 계획과 중복되지 않는 새 ExecPlan으로 작성한다. 아직 시작하지 않은 계획이 이미 충족됐거나 무효가 됐으면 기존 권한과 dependency 검증을 거쳐 조정한다.
- 영향 판단에 필요한 관련 코드·테스트·문서 절과 연결된 계획은 읽되, 비교 기준이 유효한 매 호출에서 PRODUCT·ARCHITECTURE 전문과 저장소 전체를 관례적으로 다시 읽도록 요구하지 않는다. 영향이 불확실하면 관련 범위를 넓혀 확인하며 불확실성을 수정 불필요로 처리하지 않는다.
- 최초 계획이나 비교 가능한 성공 기준이 없는 경우에는 현재 PRODUCT·활성 Requirement·ARCHITECTURE를 토대로 미충족 작업을 확인한다. 비교 자료가 없거나 손상됐다는 이유로 변경 없음·완료를 확정하지 않는다.
- 이 Requirement는 PRODUCT와 R-049의 일반 Planner 검토 범위를 위 방식으로 구체화한다. R-049의 역할 선택, 빠른 점검의 읽기 전용 판단·일회 인계와 Model·Effort는 유지하며, 작성 권한과 사용자 판단 대기 draft는 R-061을 따른다. 일반 Planner가 실행된다는 사실을 매번 전체 문서를 기본 입력으로 읽어야 한다는 뜻으로 사용하지 않는다.

### 완료 후보의 최종 확인

비종료 계획·실행·PR 대기·차단·미해결 planning 오류와 활성 또는 due 유지보수 작업이 없어 남은 작업이 없는 후보가 되면, 일반 Planner가 같은 최신 원격 revision의 PRODUCT와 ARCHITECTURE 전문을 기준으로 제품 목표·장기 규칙·Non-Goal·설계 제약의 충족과 작업 누락을 최종 점검한다. 활성 Requirement가 남아 있으면 그 전문과 충족 여부도 확인한다. 등록 조건상 PRODUCT가 없는 프로젝트에서는 존재하는 활성 Requirement와 ARCHITECTURE를 기준으로 한다.

최종 확인은 최근 diff 밖에 있는 미충족 작업도 찾아야 한다. 필요한 코드·테스트 근거를 확인하고, 작업이 남았으면 기존 권한으로 새 계획 또는 허용된 계획 조정을 수행한다. 문서 전문을 읽었다는 사실이나 catalog가 비었다는 사실만으로 완료를 확정하지 않는다. 명세의 모순·필수 결정 누락은 임의 구현으로 해소하지 않고 R-061의 draft에 질문을 기록해 사용자 판단을 기다린다. 그 draft는 프로젝트 차단을 만들지 않지만 미완료 계획이므로 완료로 처리하지 않는다.

같은 입력·작업 주기의 성공한 최종 확인은 재사용하며 외부 실행마다 반복하지 않는다. 코드·명세·관련 계획 입력이 달라지거나 새 작업 주기가 생기면 오래된 최종 확인으로 완료 처리하지 않는다. 최종 확인 중 입력이 바뀌었거나 필요한 검토·게시가 실패하면 성공 기준을 전진시키지 않고 최신 입력에서 재개한다.

변경 영향 확인과 문서 전문 최종 확인의 성공 근거를 구분한다. 빠른 점검의 수정 불필요나 변경 중심 Planner의 새 계획 없음은 최종 확인을 대신하지 않는다. 실제 프로젝트 완료와 알림은 활성 Requirement 없음 등을 포함한 기존 완료 gate와 최신 입력의 성공한 최종 확인을 모두 만족해야 한다. Reviewer의 구현 Review는 이 최종 확인과 별도로 유지한다.

유지보수는 [R-074](%5BR-074%5D%20Single-Pass%20Maintenance%20Cycle.md)에 따라 확정한 계획의 마지막 Merge와 필요한 게시·상태 반영을 마치면 별도 사후 재검증 없이 종료한다. 이 문서의 일반 Planner 검토를 유지보수 사후 재검증의 대체 단계나 cycle 종료 조건으로 추가하지 않는다. 일반 작업의 실제 입력 변경에 따른 계획 검토와 프로젝트 전체 완료 후보의 최종 확인은 기존 조건에 따라 수행한다.

## Acceptance Criteria

- 비교 기준이 있는 일반 계획에서 변경 파일·diff와 현재 catalog를 먼저 확인하고, 영향받은 계획·관련 코드·문서 범위를 근거로 계획을 유지·개정하거나 새 계획을 생성한다.
- 문서 삭제·이름 변경, 코드와 문서의 동시 변경 및 dependency 영향이 누락되지 않는다. 변경이 기존 계획과 무관하면 이유 없이 문서 전문 점검을 반복하지 않는다.
- 변경으로 작업이 이미 충족되거나 중복·무효가 된 경우 허용된 미착수 READY·draft만 조정한다. 실행 이력·소유권·snapshot·dependency와 사용자 판단 제한은 유지된다.
- R-049의 빠른 점검은 판단만 하고 필요한 수정 또는 불확실성을 일반 Planner에 한 번 인계한다. 인계받은 일반 Planner도 변경 영향부터 확인한다.
- 최초 계획과 비교 불가능한 입력에서는 현재 명세에 근거한 확인을 수행하며, diff 부재를 작업 없음의 증거로 사용하지 않는다.
- 남은 작업이 없는 후보에서는 최신 PRODUCT·ARCHITECTURE 및 남아 있는 활성 Requirement의 전문과 구현 근거를 확인한다. 최근 diff 밖의 미구현 규칙도 발견하면 계획으로 반영한다.
- 빠른 점검·변경 중심 검토의 추가 작업 없음만으로 완료 또는 완료 알림을 만들지 않는다. 미해결 계획·PR·차단·오류·due 유지보수와 활성 Requirement의 기존 완료 gate도 유지된다.
- 같은 입력·작업 주기의 성공한 최종 확인은 재시작 뒤 반복하지 않으며, 관련 입력 변경·최종 확인 실패·게시 실패·원격 경쟁에서는 오래된 성공 근거를 적용하지 않는다.
- 유지보수 종료 자체를 이유로 별도 재검증 또는 이를 대신하는 일반 Planner 검토를 추가하지 않는다. R-074의 종료 뒤 일반 작업 선택으로 돌아가며, 실제 입력 변경과 프로젝트 전체 완료 후보에 필요한 기존 검토는 유지된다.
- 로그와 저장된 판단 근거로 변경 영향 검토인지 문서 전문 최종 확인인지, 어떤 원격 입력과 계획에 대한 판단인지 구분할 수 있다.

## Product Impact

- 일반적인 Planner 호출은 변경의 영향을 중심으로 계획을 갱신한다.
- 프로젝트 완료 전에는 문서 전문에 근거해 최근 변경 밖의 작업 누락까지 확인한다.

## Non-Goals

- 새로운 Planner 역할·외부 서비스 또는 항상 실행하는 저장소 전체 개선 탐색을 추가하지 않는다.
- mutable READY 권한, Reviewer 책임·세션 정책 또는 현재 제품 범위를 확대하지 않는다.
- FUTURE_IDEAS와 archived Requirement·MERGED 계획을 새 미충족 작업의 입력으로 사용하지 않는다.
