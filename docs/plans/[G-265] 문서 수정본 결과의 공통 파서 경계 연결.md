## Purpose

문서 수정본 결과의 형식 해석을 기존 공통 결과 파서에 연결하고, 수정본의 의미·저장·사용자 승인 책임은 현재 경계에 남긴다. 저장된 모듈 평가의 발견 1에서 `loop_manager_internal/documents/document_drafts.py:603`의 `parse_generated_draft`가 자체 단일 줄 수집과 기본 `json.loads`를 사용함을 확인했다. 중복 status/content key의 마지막 값을 수용하면서 의미가 같은 표식·다중 줄 JSON은 거부하므로, 이미 중복 key를 거부하는 `application/result_normalization.py`와 계약이 갈라져 있다.

## Acceptance Criteria

- DOCUMENT_DRAFT_RESULT의 형식 해석은 기존 `tagged_json` 경계를 재사용한다. 현재 정상 단일 줄 결과와 의미가 같은 들여쓰기·구분자·표식·다중 줄 JSON을 같은 candidate 또는 uncertain으로 해석한다.
- 중복 marker·중복 JSON key·상충 status·잘못된 JSON·필드 집합·타입은 `DocumentDraftError`로 거부한다. 뒤의 key로 uncertain을 candidate로 바꾸거나 부족한 의미 근거를 보충하지 않는다.
- 기존 2,100,000-byte JSON 제한, candidate의 전체 UTF-8 문서 bytes와 meaning_evidence, uncertain의 비어 있지 않은 reason 및 반환 계약을 보존한다. 문자열 내부의 문서 내용·줄바꿈·코드·diff를 형식 정규화 대상으로 삼지 않는다.
- 사용자 동작과 공개 계약은 현재 문서 평가·수정본 조회·승인/거절·stale 판정·별도 PR/Merge 흐름을 보존한다. 형식 거부는 후보 저장이나 사용자 결정을 만들지 않으며 기존 실패·원문·진단을 보존한다.
- 저장 형식은 기존 수정본 row, 원본/제안 bytes·hash, decision revision, source 관계와 감사 원문을 보존한다. schema 변경, 기존 승인 자료 재해석·migration과 source 정책 변경은 포함하지 않는다.

## Implementation

`parse_generated_draft`에서 형식 수집·JSON decode 책임만 공유 helper로 넘기고, 문서 전용 필드·타입·uncertain 의미 검사는 현재 모듈에 남긴다. 공유 helper의 예외는 기존 오류 경계로 전달한다. 별도 parser·정규화 설정·전역 상태를 추가하지 않는다. `tests/test_maintenance_state.py`의 수정본 후보·uncertain fixture를 재사용한다.

G-222가 같은 테스트 모듈의 Git 관측·격리 경계를 먼저 정리한 뒤 그 결과 위에서 검증한다. G-242의 stage_documents DOCUMENT_RESULT와 이 수정본 결과는 서로 다른 소비 경계이며 해당 작업의 PR 경합·개정 권한 목표를 구현하지 않는다.

## Validation

- Worker targeted unit test는 수정본 결과 경계에서 정상 단일 줄/동등한 다중 줄·표식, candidate/uncertain, 중복 status/content·marker, malformed JSON, 필드/타입 오류와 byte 제한 경계값을 검사한다. 결과 파서·수정본 저장 판단은 실제 함수를 사용하고 Agent 실행은 mock으로 제공한다.
- 저장 연결의 최소 회귀로 형식 오류·uncertain에서 후보/승인 변경이 없고 원문·기존 결정이 보존되며, 정상 candidate의 문서 bytes·hash가 유지되는지 확인한다.
- Manager 전체 verify는 기존 문서 수정본 승인·거절·stale/CRLF·정확한 diff 적용, 실행 문서 gate 및 다른 역할의 결과 정규화 회귀를 유지해야 한다. 테스트 수집·필수 compile·verify adapter는 변경하지 않는다.
