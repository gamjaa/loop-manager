## Purpose

자동 실행 중에도 전체/프로젝트 pause를 접수해 새 작업을 막고 대상 프로세스 종료·작업 보존을 확인한다. 범위별 resume는 pause만 해제하며 자동 실행이나 독립 차단 해제를 수행하지 않는다.

## Acceptance Criteria

- R-055/R-094의 외부 완료 근거 수락·catalog/DB 복구에서도 pause는 관측·확정 전후의 실제 결과를 보존한다. PR Merge와 archive 기반 수락의 종류·관측 revision·원래 감사와 DB 적용 대기·cleanup/archive pending을 구분하고 pause/resume로 READY 복원·새 Agent/검증·중복 게시/완료 통지를 만들지 않는다. 현재 `external_completion` snapshot의 종류·관측 revision·`db_pending`과 원래 native checkpoint generation/operation·rebase intent를 함께 보존한다. 실제 Merge가 이미 저장돼도 프로젝트 차단·planning 투영과 같은 PR/worktree를 공유하는 수동 묶음 전체의 미종료 호출·예약은 정리 완료로 바꾸지 않는다. PLANNING 중 pinned archive 이력 복구에 pause가 겹치면 확정된 완료만 유지하고 미확정 복구와 Planner phase/session/worktree/publication/error·독립 row를 보존한다. resume 자체는 완료 재관측·DB 복구·정리/원격 쓰기를 실행하지 않는다.

- R-055 T40/R-076: 완료한 이전 게시의 intent/result·수용 근거와 현재 로컬/원격 HEAD·`publication_remote_oid`·`accepted_work_branch`를 보존한다. 다음 게시가 이전 성공을 `rebase_publication_history`로 옮기거나 원격 변경이 intent를 `retired_rebase_publications`에 보관해도 원래 성공 연결과 현재 미완료 intent·정확한 lease를 유지한다. 두 번째 intent 저장 전후·push 확인 뒤 DB 확정 전의 pause는 이력을 이동·삭제하거나 intent·실패 이력을 초기화하지 않는다. 다른 target의 새 rebase START에서도 이전 소유권 관측 뒤 차단 해제 확정 전 또는 새 rebase 시작 전 pause에는 새 rebase·push·요청 소비가 없다. 이미 원자 확정한 해제·게시만 유지하며 미확정 결과는 미확정으로 남긴다. resume 명령은 pause만 해제한다. 다음 자동 실행만 현재 원격·PR·자원·generation과 원래 성공을 재검사해, 게시 전 원격이면 같은 intent/lease의 남은 게시를, 이미 게시된 원격이면 중복 push 없는 누락 확정을 이어간다. 과거 checkpoint OID·새 target·저장 위치만으로 소유권 차단을 되살리거나 START·pause를 새 완료·검증 성공으로 기록하지 않는다.

- R-072/PRODUCT의 최종 승인 재연결과 철회 자원 정리에도 기존 pause 보존 계약을 적용한다. 최종 Review의 원래 approval·현재 binding·실제 invocation·전체 run/cycle·stage origin과 진행 중/무효 상태를 보존하며, pause나 resume가 새 PASS·receipt·호출·실패 초기화를 만들지 않는다. 철회 정리의 bundle·삭제 intent/result·취소 감사·파일 queue와 미정리 자원은 각 확정 지점 그대로 남긴다. pause 뒤 새 ref 삭제·worktree/보존본 제거·게시를 시작하지 않으며 resume 자체는 이 효과나 승인 재연결을 실행하지 않는다. 다음 자동 실행은 현재 입력·소유권·실제 자원과 기존 재사용/삭제 gate를 재확인한다. 특히 중단된 삭제 기록 뒤 ref가 살아 있으면 같은 OID도 재삭제하지 않고 보존한다.

- R-076/R-055: metadata `recover`의 요청 접수와 실제 재검사를 pause에서 구분한다. pause 전/중 접수한 pending 요청의 대상·원인·접수 snapshot과 `checkpoint_generation`, 미소비 기록을 보존하고, pause가 유지되면 자동 재검사·차단 해제·새 호출을 시작하지 않는다. 재검사 관측 뒤 적용 전 pause에는 요청 소비와 차단/checkpoint 전이 모두 미확정으로 남는다. 이미 같은 transaction에서 확정한 소비·해제는 되돌리거나 반복하지 않는다. 사용자 resume 자체는 metadata 재검사·소비·해제를 수행하지 않으며, 이후 실행은 접수 원인/generation·현재 소유권·writer·원격·dependency·관리 자리와 독립 차단을 다시 검사한다. R-053의 명시적 recover 미해결 통지는 실제 재검사가 종결된 요청에만 결합한다. pause로 보존한 pending·진행 중 요청을 completed/unresolved로 바꾸거나 통지하지 않으며, 이미 확정한 완료·outbox는 보존해 같은 요청의 결과를 중복 생성하지 않는다. 전체 pause의 새 알림 전송 금지도 유지한다.

- R-091의 명시적 수동 제출/unblock 수락·관리 보존 대기/인계 기록도 pause에서 보존한다. pause 중 유효 요청 접수·명시 해제 상태 반영은 가능하지만 자동 후속 배정은 시작하지 않는다. 현재 `worker_output_invalid`·`verify_retry_exhausted`의 명시 해제도 같은 계약을 따르며 원래 차단·실패 이력·checkpoint와 `validation_success: false` 감사를 유지한다. pause resume 자체는 독립 차단을 해제하거나 admission을 재정렬/소비하지 않고 다음 자동 실행만 현재 자격·자리·종료를 확인한다. 사용자 pause의 종료 요청과 관리 인계의 안전 반환 대기는 구별한다.

- R-061의 문서 보고 결합도 pause에서 보존한다. Worker 결과 원문·작업 base/후보와 작업별 `manager_metadata`의 `document-report:` 근거를 유지하며 저장 전·후의 pause를 결합 완료나 설명 승인으로 간주하지 않는다. resume 명령은 base 조회·보고 재결합/소비나 잘못된 base·과거 해시 오류 차단 해제를 수행하지 않는다. 다음 자동 실행만 기존 검증/게시 경계에서 같은 작업 base와 현재 후보의 문서별 patch를 대조한다. 원격 base 전진만으로 작업 base를 바꾸지 않고 rebase 완료 근거 뒤에만 통합된 target으로 전환한다. 작업 base 조회 실패·근거 부재는 후보·원문·진단을 보존해 기존 복구로 이어가며 실제 patch 변경·설명 결합 부재의 교정과 구별한다.

- pause [repo]는 먼저 요청을 저장하고 대상 Agent·verify·자식 종료를 유한 시간 안에 확인한다. 단계·session·작업물·진단·게시 intent를 보존하며 다른 프로젝트나 다른 기기의 수동 구현 종료를 주장하지 않는다.
- R-067/R-091의 신뢰된 통합 단계 실행 중 pause에도 상위와 소유 하위 runner/worker의 종료 근거를 함께 소비한다. 하위 생존·최종 `finish_child` 응답 거부/유실·시작 identity 불일치는 중단 완료·예약 회수·복사본 정리로 바꾸지 않는다. 공통 예산 오류의 원본·소유 누계와 child별 진단을 보존한다. 현재 Linux Codex supervisor의 종료 확인도 재사용하며 provider 본체 종료만으로 이탈 자식의 종료나 finished receipt를 추정하지 않는다.
- Git·게시 중단 결과는 현재 소유권·실제 원격·기존 복구 증거로 확인한다. 게시 전, 게시 후 DB 미적용, DB 적용 후 worktree 정리·최종 해제 대기를 구분한다. 적용된 catalog·목적별 성공 기준은 pause나 정리 실패로 되돌리지 않고, planning 소유권·결과·session·intent와 `publication_remote_oid`를 보존한다. worktree 제거 뒤 DB 해제 전에 중단돼도 제거된 경로를 재생성하거나 batch를 다시 적용하지 않는다. 별도 작업의 intent는 R-055의 실제 충돌 범위로 판단하고 pause가 그 intent·원인 차단을 정리하지 않는다. 종료·저장·게시 결과 미확인에서는 pause와 미완료 대상을 보존하고 완료·새 자원 사용을 허용하지 않는다. 재시작도 같은 요청을 이어간다.
- 전체 pause의 run은 bootstrap/runtime·원격·Agent·verify·알림 전에 안내·코드 0으로 종료한다. 프로젝트 pause는 해당 대상을 제외하며 명시 repo로 우회하지 않는다. 수락된 수동 제출·복구·유지보수의 자동 후속 처리도 pause를 준수한다.
- 전체/프로젝트 pause는 독립 저장하고 resume [repo]는 해당 범위만 해제한다. 기존 사용자 결정·차단·usage 제한·dependency·PR 대기는 유지하고 resume 자체는 작업을 시작하지 않는다. 프로젝트 차단의 정확한 활성 소유자가 기존 관리 자리에서 복구·중간 게시할 수 있어도 자동 후속 처리에는 같은 pause를 적용한다. pause는 소유자의 단계·원인·예약을 바꾸거나 계획 차단 해제의 대상 상태를 확대하지 않는다.
- pause 중 조회·설정·제어·기존 수동 준비와 요청 접수는 가능하다. 정상 무변경/완료 0, 안전 거부·종료 미확인 1, 인자 오류 2이며 요청 저장과 실제 중단을 구분한다.
- R-094의 PR 후속·연속 배정 중 archive도 자동 효과이므로 같은 사용자 pause를 적용한다. archive가 관리 자리를 소비하지 않는다는 이유로 pause를 우회하지 않는다. 준비 commit·정확한 게시 intent·실제 원격 결과·catalog/DB 확정과 관측을 보존하며, archive 대기만으로 MERGED·dependency·유지보수 종료·독립 작업의 상태를 바꾸지 않는다. resume 명령은 archive나 Requirement 교정을 실행하지 않고 다음 자동 경계만 현재 자원·게시 결과를 다시 확인한다.
- R-082의 일반 planning 전환 중에도 pause는 실제 Planner·verify·Agent와 자식만 대상으로 종료를 확인한다. `planning_resume_plan_id`로 보존한 원래 작업, 별도 planning worktree·결과·게시 intent·오류와 실행/실패 이력을 유지한다. 보존한 rebase의 HEAD·index·작업물·원래 target·checkpoint도 유지하며 Git 표식만으로 실행 중 자식이 있다고 판단하거나 임의 continue/abort하지 않는다. `plan_input_invalid`가 안전한 START 관측으로 이미 해제됐어도 미시작 rebase intent와 기존 단계만 보존하며, START 자체로 새 rebase 완료·새 게시·검증 성공을 만들지 않는다. 이전 게시의 소유권은 R-055 T40 조건으로 별도 확인한다. 사용자 resume는 pause만 해제하고 planning 성공·영향 확정·rebase 완료·원래 작업 재개를 합성하지 않는다. 다음 실행의 planning 게시·DB 적용과 같은 작업 재개는 기존 R-082 gate를 따른다.
- R-091의 프로젝트 planning 배정 중단과 R-076의 사용자 pause를 구별한다. 프로젝트 준비·planning이 작업 배정 중단 중 Git 자원을 사용할 수 있어도 사용자 pause·runtime handoff·실제 자원 잠금은 계속 적용한다. Git 자원 대기·관측 중 또는 자동 해제의 상태 확정 전에 pause를 접수하면 추가 효과 없이 보존 경계로 반환한다. 이번 관측 lease는 반환하되 원인 작업의 intent·checkpoint·차단과 다른 프로젝트의 자원·작업은 유지한다. pause 중 허용된 수동 준비·요청 접수와 자동 후속 처리의 중단을 구분한다.
- R-055/PRODUCT의 targeted 기록 수명도 pause·resume에서 보존한다. 호출별 JSONL·디렉터리 identity·process receipt·미소비 결합은 종료/수집·저장이 불확실해도 남긴다. 저장된 VERIFYING의 초기 gate와 verify slot 배정 뒤 재확인 사이에서도 사용자 pause는 새 검증을 막고 Worker 결과·session·후보·미소비 자료를 보존한다. 배정 후 preflight에서 시작을 보류한 검증은 기존 미시작 호출 자리만 반환하고 새 검증 실행·실패·성공 receipt를 만들지 않는다. 이미 시작했거나 종료 불명인 검증에는 기존 종료 확인을 적용한다. resume 자체는 기록을 소비하거나 도달 표식·실패 이력을 초기화하지 않는다. 다음 자동 실행은 기존 호출 재수집을 거치며 후속 성공은 실패 횟수·도달 표식을 초기화하며, 해소되지 않은 연속 다섯 번째 실패와 수집 대기는 해당 작업의 기존 차단/대기 경계로 이어진다. 다른 작업의 자료와 살아 있는 수동 writer는 변경하지 않는다.
- R-023/R-091의 코드 변경 handoff·비차단 재시도 대기와 사용자 pause를 구별한다. pause 요청은 대기 중에도 처리하며 전체 pause가 저장되면 새 원격 효과·runtime/단계 호출을 시작하지 않는다. pause는 진행 중 호출의 기존 종료/보존 경계를 적용하고, 정상 handoff는 안전 반환을 기다린다. 사용자 resume가 실패/교정/테스트 이력·재시도 대기·독립 조건을 초기화하거나 handoff 승인·자동 작업 시작을 뜻하지 않는다.
- R-023의 관리 Claude 호출에도 같은 pause 계약을 적용한다. 준비 전/후·launch 결합 후 spawn 전 pause는 모델 실행과 새 실패를 만들지 않고, 실행 중 pause는 실제 process group 종료를 확인한 뒤에만 finished receipt·자리 반환을 확정한다. `prepared` 구성·원래 session·attempt의 결과/targeted 원문·attempt 밖 receipt와 호출 소유 Bash 임시 경로의 연결을 보존한다. 종료 불명은 중단 완료나 수집 완료로 바꾸지 않으며 resume 자체로 재실행·수집·source 정책 변경을 하지 않는다.

- R-093의 Manager checkpoint 요청·commit·push·결과 저장 사이 pause에서도 요청/intent·이미 생성한 commit·실제 게시/종료 근거·session과 미확인 prompt 전달 cursor를 보존한다. 새 원격 통합 중에는 원래 `before`·현재 후보·`accepted_work_branch`·검증 무효화 상태와 미완료 request를 함께 보존하고, 낡은 push intent가 이미 폐기됐으면 `retired_worker_checkpoints`의 원래 intent·관측 원격·`confirmed: false` 감사도 유지한다. 수용된 rebase의 후속 checkpoint도 같은 계약을 따른다. 진행 중 rebase와 일반 checkpoint 요청이 함께 남으면 원래 target·충돌 처리·요청을 보존하고 rebase 해결·완료가 일반 요청 소비보다 먼저 이어지게 한다. 완료 게시의 intent/result·현재 acceptance는 과거 차단 checkpoint가 unpublished로 바뀌거나 다음 게시가 이전 intent를 `rebase_publication_history`에 보관하거나 원격 변경으로 `retired_rebase_publications`로 이동해도 같은 ID의 게시 결과와 함께 보존하며, 다음 자동 실행에서 현재 소유권·범위·실제 원격을 다시 확인한다. 폐기 감사의 `confirmed: false`는 별도로 확인된 같은 intent의 게시 성공을 취소하지 않는다. 요청 commit이 재작성됐으면 `rebase_operation_history`의 동일 요청·원래 commit intent와 실제 parent/tree/message, 현재 후보의 acceptance를 함께 보존한다. 현재 tree와 과거 tree의 동일성을 요구하지 않으며 완료 감사의 `head`·`original_head`와 요청/session/전달 identity를 유지한다. 현재 후보·정확한 lease를 고정한 `rebase_publication_intent`·원래 acceptance와 게시 확인/DB 확정을 보존한다. 게시 확정 transaction이 갱신한 실행 행의 게시 OID·checkpoint 관측 OID·게시 영수증·`accepted_work_branch`도 같은 intent HEAD로 보존하며, 원래 lease/수용 근거와 현재 포인터의 시점을 구분한다. pause나 resume가 낡은 수용 포인터를 되살려 다른 유효한 소유 근거를 무효화하거나 intent의 lease를 바꾸지 않는다. pause 뒤에도 과거 deferred 표시나 최종 PR 대기를 이유로 요청을 버리지 않는다. pause/재시작·입력 수용·intent 폐기 자체로 push 성공·요청 완료·문맥 전달 확인을 만들지 않으며, 미확정 게시가 해결되기 전 새 Worker는 시작하지 않는다. Worker의 직접 Git 쓰기 금지와 완료 후보/복구점 구분을 유지한다.
