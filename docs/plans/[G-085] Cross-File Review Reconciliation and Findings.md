## Purpose

파일을 읽은 순서에 따라 중복 구현이나 역참조를 놓치지 않도록 모든 선정 파일의 잠정 결과를 종합한다. 실제 근거가 있는 구조 문제만 기존 비종료 계획 또는 새 동작 보존 리팩터링 계획으로 연결할 수 있는 검증된 발견으로 만든다.

## Acceptance Criteria

- 모든 선정 파일을 실제로 검토한 뒤 새 코드맵과 유효한 기존 코드맵의 참조·역참조·유사 책임 후보를 종합한다. 오래된 코드맵의 경로·지문·mode를 현재 원격에서 확인하고, 없거나 참조가 불명확하면 현재 원본의 필요한 부분을 읽는다.
- 뒤에 읽은 파일이 앞서 읽은 파일과의 관계를 드러내면 해당 관계와 필요한 원본 부분을 재확인한다. 파일 읽기 순서가 달라도 같은 source와 대상 집합에서는 확인해야 할 관계와 완료 조건이 같다. 전체 선정 파일을 매번 다시 읽는 별도 전수 단계는 두지 않는다.
- 각 관계는 확인 결과 또는 제외 근거를 기록한다. 필요한 관계가 미확인, 상충 또는 오래된 source에 기반하면 완료로 판정하지 않는다. 종합 단계도 중단·재개 가능한 단위로 진행한다.
- 발견은 대상 경로·원본 지문, 구체적 코드 근거, 처리 상태, 책임 경계와 중복·관련 없는 후속 문맥 감소 이유를 포함한다. 분리의 추가 탐색·연동 비용도 검토한다. 문제가 없으면 근거 있는 없음 결과를 허용한다.
- 같은 문제를 해결하는 비종료 ExecPlan이 있으면 그 ID에 연결하고 새 계획을 중복 생성하지 않는다. 새 리팩터링 계획은 사용자 동작·공개 계약·저장 형식을 보존하고 독립 검증·Merge 가능해야 하며 targeted unit test와 전체 verify 회귀 조건을 갖춘다. 파일 수·길이·토큰 수만으로 계획을 요구하지 않는다.

## Implementation

- G-084의 잠정 기록을 소비하는 관계 graph와 종합 결과 검증기를 별도 유지보수 모듈에 둔다. 코드맵 후보를 현재 Git 원본과 대조하고 참조 미확인 목록 및 확인 근거를 durable하게 추적한다.
- 유지보수 Planner의 최종 결과에 검증된 관계·발견·기존 plan 연결 또는 새 plan 의도를 포함하고, 기존 catalog의 비종료 plan 범위와 대조한다. 새 계획 파일의 실제 게시 및 성공 확정은 G-086에서 수행한다.
- 코드 변경이 필요하지 않은 경우 리팩터링 계획을 형식적으로 요구하지 않는다. 문서·AGENTS.md 개선은 self 전용 G-059/G-078/G-079 경로로 남긴다.

## Validation

- 앞뒤 읽기 순서, 새·기존 코드맵 결합, 역참조, map 부재·무효화, 원본 참조 검증, 미확인 관계 차단, 중단·재개, 중복 plan 방지와 근거 있는 no-issue 결과를 검증한다.

## Decision Log

- G-085의 발견은 잠정 평가 결과다. 원격 계획 게시와 파일별 성공 기록의 동시 확정은 G-086이 맡는다.

- 관계별 검증 결과는 source revision과 cycle에 결합해 잠정 저장한다. 성공 코드맵의 조회 경계를 마련했지만 검토 기록·코드맵의 성공 전환은 G-086에서만 수행한다.

- 검토 피드백 보완: 최종 Planner에 모든 선정 파일의 검증된 잠정 결과를 전달한다. 발견은 모든 비종료 계획의 고정 revision 본문 인용·책임 경계 비교와 동일 문제 판단을 포함하며, 기존 연결 불일치와 같은 문제의 신규 계획을 거부한다. 문제 없음 결과도 모든 파일 검토와 완료된 관계의 근거 인용을 포함해야 한다.
- 추가 targeted 검증: 검증기·Planner 입력 9 tests OK(초기 Planner fixture의 revision 오류 수정 후 동일 명령 재실행), 계획 원문 전달 단일 test OK. 전체 verify와 게시 작업은 Worker에서 실행하지 않는다.

- Worker 결과 보고 보완: 이전 보고는 FAILED_COMMAND와 RERUN 사이에 최초 ERROR 결과가 없어 미해결 실패로 판정됐다. 코드의 Git revision fixture 수정은 유지돼 있으며, 동일 targeted 명령을 다시 실행해 추가 회귀 사례를 포함한 11 tests OK를 확인했다. 결과 보고에서 최초 ERROR와 최종 OK를 별도로 기록하며 검증기 동작은 변경하지 않는다.

- 추가 검토 피드백 보완: 유효한 기존 코드맵도 완전한 참조 목록으로 취급하지 않는다. 모든 비선정 문맥 원본에서 선정 파일의 공개 심벌·경로 역참조를 검색하고, 찾은 후보는 기존 관계 확인 절차를 거친다.
- 종합 입력은 파일별 검토·선정 source identity·관계 결과·제외 근거를 손실 없이 최대 12,000자 페이지로 나눈다. 큰 단일 파일의 구간 근거도 나누며, 호출당 한 페이지만 같은 Planner 세션에 전달한다. SQLite에 cycle·revision·전체 증거 digest, 페이지 위치·확인 결과·세션을 저장하고, 증거 변경 또는 세션 교체 시 다시 처리한다. 모든 페이지 확인 전 최종 결과 검증을 차단한다. 최종 프롬프트는 전체 증거를 다시 포함하지 않는다.
- targeted 검증: 역참조·페이지 저장/재개·최종 Planner 세션 연결·계획 원문 전달 12 tests OK. 짧은 마지막 조각·증거/cycle 변경·미완료 페이지 차단을 추가한 targeted 검증 4 tests OK. 전체 verify, commit, push 및 PR 생성은 실행하지 않았다.

- Worker 결과 보고 재확인: 이전 TARGETED_TESTS의 한국어 부정문을 검증기가 오류 키워드로 인식했다. 판정 함수를 통해 해당 문구와 명령·OK로만 구성한 대체 문구의 판정 차이를 확인했다. 검증기 코드는 변경하지 않았으며, 역참조·페이지 저장/재개·최종 세션 연결·미완료 결과 차단의 targeted unit tests 6개를 다시 실행해 OK를 확인했다.

- 추가 검토 보완: source revision을 매번 원격 ref와 대조하되 동일 revision의 inventory와 검증된 파일·관계 결과는 SQLite 지문으로 재사용한다. 역참조 검색은 최대 16개의 미확인 문맥 파일을 한 호출에서 처리하고 각 파일의 source identity·검색 입력에 결합된 신호만 즉시 저장한다. 검색 중단 뒤 완료 파일은 다시 읽지 않으며, 원본·mode·검색 입력이 달라지면 관련 결과를 무효화한다. 1~3자 공개 심벌도 검색한다.
- 앞선 동일 세션 누적 방식은 독립 페이지 세션과 영속 증거 snapshot으로 대체했다. 검증된 원문 조각과 SQLite 페이지 판단을 관리 경로에 손실 없이 제공하고, 최종 Planner는 새 세션에서도 manifest를 통해 필요한 조각과 저장 판단을 재조회한다. 모든 페이지의 정확한 판단 인용과 발견 연결·명시적 제외·문제 없음 상태를 검증하며, 저장된 문제 후보를 문제 없음으로 덮거나 페이지를 누락하면 거부한다. 증거 파일은 최초 생성 후 새 판단만 갱신하며 성공 기록의 원본은 SQLite다.
- targeted unit 검증: 원본 캐시·짧은 심벌·독립 세션·영속 근거 조회·계획 연결 18 tests OK, 관계 지문 및 source별 무효화·페이지 회귀 6 tests OK, 최종 영속 판단 연결 2 tests OK. 전체 verify와 Git 게시 작업은 실행하지 않았다.

- 추가 경계 검증: 검색 도중 중단 후 저장된 파일 단위 결과 재사용 및 미확인 검색의 Agent 진입 차단 2 tests OK. 짧은 공개 심벌과 긴 식별자의 부분 문자열 구분 2 tests OK. 페이지 증거 snapshot은 새 판단만 갱신하는 방식에서도 최종 조회·처리 검증 2 tests OK를 확인했다.

- 최종 출력 크기 보완: 최종 Planner에서 모든 페이지의 SYNTHESIS_RESOLUTIONS 배열을 반환하는 계약을 제거했다. 최종 발견·요약을 저장한 뒤 페이지별 연결·제외 검증을 별도 단위로 호출하고, 각 결과를 source/증거 digest와 최종 판단 digest에 결합해 SQLite에 저장한다. 중단 시 미완료 단위의 세션·오류를 복구하고 최종 판단이 바뀌면 이전 처리 결과를 재사용하지 않는다. 각 응답은 한 페이지·24,000 bytes 이하이며 완료 여부와 모든 페이지의 처리 근거는 프로그램이 저장된 결과로 검사한다.
- 문제 없음 최종 응답도 파일·관계 배열 대신 synthesis_digest와 제한된 summary를 사용한다. 이 요약만으로 완료하지 않으며 모든 페이지의 저장된 판단 연결 또는 제외 검증이 갖춰져야 최종 검증을 통과한다.
- targeted unit 검증: 10,000페이지에서 개별 응답 600 bytes 미만 및 1페이지와 동일한 최종 응답 크기를 확인했다. 저장 결과 누락·중복·오래된 source/판단·응답 크기 초과의 차단, 누락된 단위만 재개, Planner 최종 판단 보존 등 관련 7 tests OK. 전체 verify, commit, push 및 PR 생성은 실행하지 않았다.
