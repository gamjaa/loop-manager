## Purpose

prerequisite 후 재평가와 마지막 리팩터링 뒤 post-revalidation을 없애고 확정 범위의 실제 Merge 뒤 종료하는 R-074 정책을 구현한다.

## Acceptance Criteria

- 한 cycle의 모듈 검토·필요한 종합/계획 작성으로 prerequisite·리팩터링·필요한 dependency closure를 확정한다. prerequisite Merge나 개선 결과 때문에 새 전체 평가로 범위를 계속 늘리지 않는다.
- 확정 범위의 모든 계획이 실제 MERGED이고 미확정 게시·catalog 반영이 끝나면 장벽을 해제하고 일반 선택으로 돌아간다. 계획 없음/기존 계획 연결/근거 있는 제외도 검증·게시 뒤 종료하며 post-revalidation Planner나 대체 일반 Planner를 추가 호출하지 않는다.
- 정상 종료 시 마지막 유지보수 Merge까지 포함한 수를 다음 주기의 기준으로 저장한다. 최초 평가와 새 명시 요청을 제외하고 이후에는 양의 interval(기본 20)만으로 시작한다. 코드 영향·평가 receipt 차이·완료 후보만으로 새 cycle을 시작하지 않는다.
- 평가 성공 원본과 종료 cadence를 분리한다. 명시 요청은 한 번 소비하고 평가/게시 중단은 같은 cycle에서 필요한 관련 범위만 재검증한다. 최신 코드에 가짜 평가 receipt를 만들지 않는다.
- 기존 prerequisite/refactoring/post 단계·미게시 자료·이력을 보존해 정책을 전환한다. 실제 Merge와 게시 확인 없이 종료하거나 주기 기준을 전진시키지 않는다. 불확실한 종료 경계는 기존 복구로 남긴다.
- due 평가는 현재 작업/실제 Open PR이 없을 때 일반 READY·변경 입력보다 먼저 한다. 실제 PR 동기화 실패·안전 차단·필요 dependency는 유지하고 시작/범위/종료/다음 대기 사유를 로그와 진행 사건에서 확인할 수 있다.

## Implementation

- maintenance/cycle_service.py·planning/tiered_assessment.py·planning/selection_service.py·storage/maintenance_state.py의 cycle 전이를 정리한다. 현재 모듈 receipt 재사용·PR preflight·게시 reconciliation을 재사용한다.
- 처리 범위와 cadence 기준의 durable identity를 분리하고 기존 활성/유휴 cycle의 전환을 관측 가능한 실제 이력에 결합한다. 구조 참조 개정은 필요할 때 기존 의미 판단 역할에 남기고 종료 gate로 재도입하지 않는다.
- 공통 경계는 AGENTS.md, docs/ARCHITECTURE.md와 docs/PLANS.md를 참조한다. 기존 helper·관련 테스트를 재사용하고 지정 루트 경로를 보존한다.

## Validation
