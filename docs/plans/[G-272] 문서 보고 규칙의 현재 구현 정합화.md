## Purpose

직접 Merge된 R-087의 보고 검사·교정 한도·PR 렌더링을 재구현하지 않고 남아 있는 제품·설계와 활성 문서의 상충 설명만 정합하게 만든다. PRODUCT의 공통 지침 변경 보고 절과 R-061/R-064에는 diff 링크·실제 변경 내용 보고 의무가 남아 있고 ARCHITECTURE의 검증 절은 이미 구현된 조기 검사를 구현 목표로 설명한다.

## Acceptance Criteria

- PRODUCT의 `### PRODUCT, Requirement와 ExecPlan`과 `### 공통 Agent 지침과 직접 작업`은 모든 문서의 PR 보고를 파일명·변경 요약·이유·영향으로 동일하게 설명한다. 실제 변경 내용·patch·diff 링크·검증용 hash를 본문에 요구하는 상충 문구를 남기지 않는다.
- ARCHITECTURE의 `## AI Agent 실행` 및 `## 검증과 재시도`는 후보 commit·최신 base 조정 뒤 부분/전체 verify와 성공 receipt 재사용 판단 전에 전체 문서 보고를 검사하는 현재 경계, 게시 직전 재검사와 안정된 교정 입력을 구현과 일치하게 설명한다. 검증 출력·session 변화는 진전이 아니며 실제 후보·명세·base 변화는 새 입력이다.
- 활성 R-061의 문서 수정/보고·Reviewer/Acceptance Criteria와 R-064의 공통·역할별 파일 변경/Acceptance Criteria에서 R-087이 대체한 보고 표현을 같은 계약으로 연결한다. 문서별 의미 있는 요약·이유·영향·최종 diff 결합·rename·rebase·기존 PR 갱신·Reviewer 대조 조건을 보존한다. 다른 목표·사용자 결정·필수 검증은 변경하지 않는다.
- Worker 결과의 DOCUMENT_CHANGE에는 실제 최종 patch SHA-256이 계속 필요하며 PR 렌더링에서만 제외한다. immutable ExecPlan/source 링크, 사용자 PR 본문 보존, 실행 snapshot 고정·일반 문서 수정 권한 및 verify 입력 증명·receipt·Review·게시 gate를 유지한다.
- 코드·테스트를 문서에 맞추어 바꾸거나 직접 구현에 소급 ExecPlan·검증 성공을 만들지 않는다. archive 문서와 기존 수행 기록을 수정하지 않는다.

## Implementation

`documents/pr_description.py`, `execution_verify_handler.py`, `execution_recovery_handler.py`와 publication 호출·현재 회귀를 기준으로 관련 절을 재작성하거나 소유 설명에 연결한다. R-087의 명시적 변경을 반영하는 문서 교정으로 한정하며 R-061/R-064의 다른 미완료 작업·권한·draft 정책을 이 계획으로 구현하지 않는다. 정적 지침의 현재 DOCUMENT_CHANGE 결과 계약도 대조하되 불필요한 원본·template·사용 안내 변경은 추가하지 않는다.

## Validation

- 문서만 변경하므로 prose 일관성을 검사하는 새 테스트나 문서 원본을 자체 verify 입력에 추가하지 않는다. 실행 가능한 동작을 변경하지 않아 Worker targeted unit test를 실행하지 않는 사유와 읽은 구현·회귀 경로를 기록한다.
- 관련 회귀는 `tests/test_execution_documents.py`의 전체 문서 동시 보고·누락/hash/형식 오류 일괄 전달·조기 교정/no verify·반복 한도·입력 변경·최종 PR 보고 및 기존 PR 보존 case다. Manager 전체 verify/재사용 판단의 기존 경계와 최종 Review는 유지하며, Reviewer는 문서 설명과 실제 검사 순서·결과·보고를 읽기 전용으로 대조한다.
