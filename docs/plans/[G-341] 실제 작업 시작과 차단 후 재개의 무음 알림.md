## Purpose

Worker의 최초 실제 프로세스 시작과 기록된 계획/프로젝트 차단 해제 뒤 그 영향 대상의 실제 작업 시작을 무음 통지한다. 기존 물리 시작 callback·작업별 호출 identity·차단 해제 기록과 outbox를 재사용하고, 차단 메시지 전송 여부에 의존하던 재개 기록을 실제 차단/시작 근거로 분리한다. 선택·예약·단순 해제를 시작으로 간주하지 않는다.

## Acceptance Criteria

- 최신 R-053의 `blocked_selection` 정보성 일반 알림을 보존한다. 진행 불가 로그·draft 질문/차단/선행의 한 메시지·episode 중복 제거·전송 직전 현재성 취소는 현재 직접 구현을 소비한다. 이 알림의 생성/전송·과거 프로젝트 오류·MERGED 감사는 차단 해제나 실제 시작의 증거가 아니며, 실제 진행 뒤 episode를 재평가하는 기존 경계도 유지한다.
- R-053: 같은 계획의 최초 Worker 프로세스 시작을 확인하면 ID·제목·작업 종류·발생 시각을 무음으로 한 번 통지한다. 일반 retry·재호출·session fallback·단계 변경·재시작에서 최초 시작을 반복하지 않는다. spawn 전 실패·선택/예약·준비만의 사건은 0건이다.
- 계획 또는 프로젝트의 기록된 차단이 실제 해제된 뒤 그 영향 대상의 정상 작업이 시작되면 이전 차단·대상·실제 시작을 무음 통지한다. 과거 차단 메시지의 생성/전송·확인 조각 수를 전제하지 않는다. 프로젝트 차단의 영향 대상과 무관한 계획의 시작을 구분하고, 재차단·별도 차단·미해결 질문·미Merge dependency·pause를 우회하지 않는다.
- 같은 실제 시작에 최초 시작과 차단 후 재개가 겹치면 재개만 보낸다. 동일 차단/해제/실제 시작은 실행·재시작을 건너 중복되지 않고 새로운 차단 episode의 실제 재개는 별개로 식별한다. 일반 Planner/Reviewer 호출·유지보수 단계·PR 충돌 수정의 내부 진행에는 별도 시작 알림을 만들지 않는다. 차단 후 실제 재개는 역할명만이 아니라 영향 대상과 정상 재개 전이로 판단한다.
- 기록된 실제 시작은 이후 단계 전환이나 프로세스의 정상 종료만으로 거짓 사건이 되지 않는다. 전송 직전·각 조각에서 시작 identity와 차단/해제 연결·현재 유효성을 대조하고 잘못 연결된 잔여 조각은 취소한다. 이미 취소한 과거 사건을 일괄 재생하지 않으며 원래 payload·cursor·전송/실패·차단 감사는 보존한다.
- 생성·전송 실패는 실제 호출을 재시도하거나 실패로 바꾸지 않는다. 기존 실제 시작·usage/receipt·종료 확인·session·실패/교정 이력과 R-091의 자리 수명을 유지하며 비활성화에서도 실행 판단은 동일하다. 알림을 위한 Agent·Git·외부 조회를 추가하지 않는다. R-076의 pause 해제 자체는 독립 차단 해제나 작업 시작 사건이 아니다. G-345의 명시 요청 수락·`pending`/`parked`/`handoff` 변경·RETRY 순번 복원/소비도 시작 근거가 아니다. 안전 반환 후 실제 영향 대상의 시작이 확인될 때만 기존 차단 해제 기록과 연결하고 task 재생성·Manager 재시작은 최초 시작을 반복시키지 않는다.

- 기록 전후 중단·재연결·재차단·다른 대상 시작·단계 전환과 늦은 전송 확인을 주입한다. 진짜 과거 시작의 유효성, 무효 잔여 조각 취소와 원문/cursor/감사 보존을 확인한다. 송신 실패/비활성 상태가 invocation·session·실패/자리 반환을 바꾸지 않아야 한다.
- 구정책의 모든 시작/재개 무통지 assertion은 허용 사건과 내부 retry/Planner/Reviewer 무통지로 나누고 기존 사용자 행동·PR·현재 조각/전송 감사 검증을 유지한다. 원격의 `tests/test_notification_delivery.py:TimelyProgressDeliveryTest`·`DraftListNotificationTest`와 `test_planning_publication.py`·`test_maintenance_publication.py`가 담당하는 게시 batch 무음, draft 일반 알림, 생성/질문별 중복 제거·철회 후 미확인 항목·늦은 확인·rename 보존 및 commit 후 flush 회귀도 유지한다. 공유 claim을 바꾸면 영향받는 기존 최소 case를 실행하고 같은 게시 행렬을 새 시작 테스트에 복제하지 않는다. `RecoveryResultNoticeTests`의 request별 미해결 통지 1건·일반 수준·원인 해소 후 취소를 유지한다. 같은 SQLite fixture에 실제 시작과 종결 미해결 요청이 공존하는 최소 case를 연결해 사건 identity·일반/무음 수준과 현재성 취소가 서로 섞이지 않는지 확인한다. 알림 결과만으로 block/release나 process 시작 기록을 만들면 실패해야 한다.
