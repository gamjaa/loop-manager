## Purpose

확인된 실행 작업 철회를 현재 취소·보존 감사·예약/요청 수명에 끝까지 반영한다. 완료된 writer 결과와 실제 PR 부재를 확인한 원격 삭제 및 Requirement 철회의 활성 row 제거는 직접 구현됐다. 검증된 archive의 과거 참조 제외·기존 hold 재평가와 draft/피드백 이행 표식의 비소유 판정·orphan ID 예약도 현재 구현으로 소비한다. 남은 단계별 요청·checkpoint/게시·알림·수동 조율과 오래된 문서/결과 재생 방지를 완결한다.

## Acceptance Criteria

- R-055: 삭제 증명과 현재 소유권을 안전한 단계 경계에서 재확인하고 다음 Worker·verify·Review·checkpoint/PR 게시와 저장 결과 소비를 중단한다. session/과거 결과 존재만으로 writer 종료를 추정하지 않으며 살아 있는 writer·Git operation·소유권 미확인은 row/claim을 보존한 채 해당 전이를 보류한다.
- R-055/R-082: 안전한 최종 철회와 원격 문서 반영이 확인되면 활성 row 제거·현재 선택/대기/관계 적용·취소/ID 감사가 같은 transaction에 결합한다. 실제 MERGED는 완료로 보존한다. 마지막 선언·미게시 작업·session·실패/level·PR·최초 게시/완료·checkpoint/게시 및 자원 소유 근거는 활성 row 밖에서도 복구 가능하다. 검증된 Merge 근거의 archive 과거 참조는 활성 복구 대상이 아니며 보관 문서·완료 이력을 다시 쓰거나 실행하지 않는다. draft 판단 대기·피드백 이행 표식만으로 미착수·무소유 작업의 확인된 삭제를 보류하지 않고 row 제거 후 남은 감사는 ID 재사용 방지에 계속 사용한다. 실제 writer·수동 소유권·미확인 Merge는 표식과 별도로 확인한다.
- 취소 작업을 현재 실행·draft 판단·수동 준비·완료 대기·일반/유지보수 대상에서 제외한다. 예약·미완료 checkpoint/게시 요청·미전송 알림을 현재 수명에 맞추고 과거 확정 결과·전송 감사·독립 사건은 보존한다. R-053의 신규 문서/draft·시작/재개·안정적 소진/완료도 사건별 현재성으로 판단한다. 철회 문서·해소된 질문·무효 대기/완료의 잔여 조각만 취소하고 이미 발생한 실제 시작을 단계 전환만으로 거짓 사건으로 만들지 않는다. 수동 묶음/준비는 기존 소유 조율을 따르며 문서 삭제를 manual stop/reset 권한으로 쓰지 않는다.
- R-091: 호출/관리 배정 대기 중 취소·row 제거·소유권 변경으로 자격이 사라지면 오래된 준비로 새 Worker·Reviewer·verify를 시작하지 않는다. 현재 scheduler의 예약 전후 재검사를 소비하고 미시작 호출의 cursor·RETRY 순서·실패/성공을 소비하지 않는다. 실제 실행 중/종료 불명 예약은 취소 문서만으로 회수하지 않고 기존 종료 근거와 취소 감사를 보존한다.
- R-067의 현재 통합 하위 runner/worker도 종료/보존 판단에 포함한다. 상위 process 결과만으로 소유 하위 예약·복사본·예산 오류 근거를 정리하지 않고 최종 종료 응답·시작 identity를 확인한다. 종료 불명에서는 row/claim과 진단을 보존해 기존 취소 확정을 보류하며 독립 run 자원은 유지한다. 삭제를 실행 중 프로세스의 강제 종료 권한으로 확대하지 않는다.
- 취소 전 Worker/Planner/Review 결과·publication/recovery snapshot을 재시작 뒤 소비해 작업 재개·게시·문서 복원을 하지 않는다. 이미 확인된 원격 게시는 감사로 보존하고 미확정 요청과 구분한다. 같은 ID 재등장은 새 READY 등록이나 취소 해제 근거가 아니다.
- 유지 작업의 branch/planning 결과에는 최신 삭제·개정을 기존 stage_documents·G-256의 안전한 rebase/최신 조건 재평가로 반영한다. 코드·index·사용자 작업을 reset하지 않으며 오래된 결과/브랜치로 원문이 재생되지 않는다. 필요한 Worker 교정·검증·Review는 남은 목표에 따른다.
- writer 종료·원격 확인·DB 취소·요청 무효화·문서 반영 사이 중단과 PR/수동/원격 경쟁은 실제 확정 지점부터 멱등 재개한다. 독립 READY·PR 관측은 계속한다. 자원 정리 pending은 별도 보존 근거로 이어가며 확인된 취소/문서 적용을 되돌리지 않는다.

## Validation

- `tests/test_incremental_planning.py`, `tests/test_scoped_blocking.py`에서 기존 완료 writer 삭제 회귀를 재사용한다. 살아 있는 writer·원격 조회 불명·실제 MERGED·Open/Closed PR·수동 준비/소유와 안전한 취소를 구분하고 실제 SQLite/파일/감사 보존을 확인한다. Git·PR·Agent 관측만 mock한다.
- `tests/test_execution_checkpoint_state.py`, `tests/test_published_checkpoint_resume.py`, `tests/test_planning_publication.py`, `tests/test_stage_documents.py`에 삭제 직전/직후와 row 제거 후 저장 결과·checkpoint/게시 intent 재시작을 연결한다. 미확정 요청은 실행/게시를 만들지 않고 확정 게시/실패/session/level·복구 자료는 조회 가능해야 한다.
- `tests/test_verify_receipts.py:StageResultProvenanceTest`와 `tests/test_runtime_state.py:CurrentRebaseRuntimeTests`의 원래 결과/receipt 보존 fixture를 위 취소 회귀에 재사용한다. 단계 origin 보존 뒤 취소, Worker 연결 뒤 취소와 각 저장 사이 중단에서 원래 원문·실패/receipt·session 감사는 보존되고 취소 작업의 Worker·verify·Reviewer·게시 호출과 현재 승인 token 생성은 0회여야 한다. 현재 유효 작업의 정상 재연결은 유지하며 원문 보존 자체의 기존 unit·실제 Git lifecycle을 복제하지 않는다.
- `tests/test_manual_concurrency.py`, `tests/test_notification_incidents.py`, `tests/test_notification_delivery.py`에서 묶음/준비·claim·draft·미전송 사건 정리와 독립 예약/전송 감사 보존을 검사한다. 이미 제거된 작업의 동일 입력 재처리·같은 ID 재등장과 자원 cleanup pending에서도 중복 취소/알림이나 자동 재등록이 없어야 한다.

- `tests/test_task_scheduling.py:test_waiting_calls_recheck_current_gates_and_candidate_before_start`·`test_prepared_call_input_change_releases_unstarted_slot_and_reprepares`와 `tests/test_execution_verify_phase.py`의 미시작 verify cursor/RETRY 보존을 현재 배정 gate 회귀로 재사용한다. 대기 후 취소된 대상의 저장 요청/결과 재소비와 독립 예약·종료 불명 보존의 연결만 보완하며 같은 gate 행렬을 반복하지 않는다.
- `tests/test_verify_integration.py:ChildCoordinatorTests`·`TrustedRunnerPortTests`와 기존 취소 SQLite/파일 fixture를 재사용해 하위 종료 미확정 뒤 취소 확정 보류·row/claim/예약·예산/child 진단 보존과 확인된 종료 뒤 한 번의 취소 반영만 검사한다. 일반 자식에 조율 인증값을 넘기거나 고정 suite를 unit에서 실제 재실행하지 않으며 독립 run 불변·취소 작업의 새 호출/성공 token 0회를 유지한다. 하위 프로세스 종료 자체의 공통 오류 행렬은 기존 회귀에 남긴다.
- 기존 managed rebase 통합 fixture의 최소 사례로 삭제 문서 반영과 미게시 코드/index 보존을 확인한다. 부분/전체 verify 회귀는 R-055 D01/D05/D08/D12의 수명·실제 Merge/사용자 판단·source/dependency gate와 독립 진행이다. 삭제/정리를 검증 성공으로 사용하지 않는다.

- `tests/test_execplan_drafts.py:ExecPlanDraftCatalogTest`의 `test_remote_draft_deletion_preserves_audit_and_independent_work`, `test_deleted_draft_does_not_reopen_archived_reference_or_legacy_hold`, `test_orphan_feedback_migration_keeps_plan_id_reserved`를 기존 catalog 회귀로 재사용한다. 이 작업은 후속 요청·checkpoint·수동/알림 소비가 활성 대기를 되살리지 않고 취소/완료 감사·ID 예약과 독립 작업을 보존하는지 확인한다. 직접 구현된 정책 조합을 다시 작성하거나 테스트 존재를 실행 PASS로 기록하지 않는다.
