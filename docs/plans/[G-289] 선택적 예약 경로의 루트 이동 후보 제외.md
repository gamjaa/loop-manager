## Purpose

이미 존재하는 선택적 예약 경로도 루트 조사에서 이동 후보가 되지 않게 한다. 현재 `validate_root_reviews()`는 `.agents`·`docs`·`scripts`의 이동을 명시적으로 거부하지만 `.gitignore`와 `.codex`·`.claude` 아래 예약 설정·규칙의 위치 보존은 검사하지 않는다. 해당 루트가 원문 인용을 갖춘 `internal_implementation`으로 잘못 분류되면 `root_move_candidates()`와 tiered 계획 연결에 수용될 수 있다. 현재 예약 경로 계약을 이 공유 검증 경계에서 지키는 작업이며 파일을 이동하거나 CLI 지침 관리 기능을 추가하지 않는다.

## Acceptance Criteria

- R-028/R-064: `.agents`·`docs`·`scripts`의 기존 보호와 함께 원격 조사 inventory에 있는 루트 `.gitignore`, `.codex/config.toml`, `.codex/rules/` 아래 파일, `.claude/settings.json`·`.claude/settings.local.json`의 경로를 바꾸는 루트 이동 후보를 거부한다. 보호 대상의 부모 루트 디렉터리를 통째로 다른 위치로 옮기는 후보도 같은 조건으로 거부한다.
- 선택적 파일·폴더의 부재를 검사 실패·등록 조건·자동 생성 사유로 삼지 않는다. `.codex`·`.claude`라는 이름만으로 예약 원본이 없는 다른 내용의 위치를 임의로 필수화하지 않으며 실제 원격 inventory와 명시된 예약 경로의 관계를 사용한다. manifest·launcher·그 밖의 항목은 기존 실제 사용·소유권 조사 기준을 유지한다.
- 루트 inventory의 배치 안내와 `validate_root_reviews()`의 결과 검증이 같은 보호 범위를 따른다. 잘못된 모델 분류·인용이 있는 결과도 보호 경로의 이동 계획 연결이나 평가 성공으로 이어지지 않는다. legacy 파일별 평가와 tiered 평가는 기존 공유 validator를 사용한다.
- R-066: 프로젝트 루트 `AGENTS.md`는 예약 경로에 새로 포함하지 않는다. 등록·계획 입력에서 해당 파일을 읽거나 승인·hash·patch 관리하지 않으며 CLI 해석과 일반 파일 보존 경계를 유지한다. 설정 파일의 내용이나 자격 증명을 새 prompt·로그에 넣지 않는다.
- PRODUCT의 선택적 예약 경로·ARCHITECTURE의 root 검증 설명과 실제 구현이 일치한다. G-206의 조사·계획/게시 연결과 G-287의 mode 교정은 재구현하지 않는다.

## Implementation

- [ ] 확인한 `loop_manager_internal/maintenance/maintenance_file_inventory.py`의 `_ROOT_TOOL_PATHS`·`_ROOT_EXECUTION_PATHS`와 `root_placement_inventory()`를 대조한다. `SourceInventory.classifications`의 추적 경로만으로 존재하는 예약 파일·디렉터리를 포함한 보호 루트를 계산하고 기존 배치 안내와 공유한다. 경로 비교는 정확한 파일과 디렉터리 prefix를 구분하며 새 전역 설정·Markdown 파서·provider 초기화에 의존하지 않는다.
- [ ] 확인한 `loop_manager_internal/storage/maintenance_file_ledger.py:validate_root_reviews()`에서 이 보호 근거를 재사용한다. `.gitignore`가 기존 실행/설정 분류로 남더라도 이동 목적지는 허용하지 않으며, 보호된 설정을 포함한 `.codex`·`.claude` 전체 이동도 거부한다. 기존 인용·중복·원격 identity·불확실성 검증은 유지한다.
- [ ] 확인한 `maintenance/maintenance_file_review.py:review_prompt()`와 `maintenance/tiered_review.py:parse_root_review_result()`가 공유 inventory·validator를 사용하도록 유지한다. 확인한 `agents/agent_write_isolation.py`의 프로젝트 설정/규칙 소비 경로는 위치 보존의 근거로만 사용하고 이 평가에서 isolation 검사·설정 읽기·인증 준비를 호출하지 않는다.
- [ ] 확인한 `tests/test_maintenance_file_inventory.py`·`tests/test_file_review_protocol.py`의 inventory/순수 root protocol fixture와 `tests/test_tiered_review.py`의 protected root 거부 사례를 필요한 최소 범위로 확장한다. PRODUCT의 `### 프로젝트 예약 경로`와 ARCHITECTURE의 `### 유지보수 분석과 성공 근거`에는 실제 보호 조건만 통합한다.

## Validation

- Worker는 변경한 inventory·validator의 최소 targeted unit case만 실행한다. 기존 `SourceInventory`·모의 Git 원문·protocol fixture를 사용하며 설정 조합마다 실제 Git 저장소·게시·Agent 호출을 반복하지 않는다.
- 각각의 선택적 예약 파일과 `.codex/rules/` 하위 추적 파일이 있을 때 올바른 원문 인용을 갖춘 부모 루트 이동 결과도 거부되는지 확인한다. `.gitignore` 자체 이동과 기존 세 고정 루트 이동도 거부돼야 한다. 유효한 유지 결과는 기존 분류 의미를 보존한다.
- 선택적 경로 부재, `.codex/config.toml.backup`·`.codex/rules-notes/` 등 비예약 유사 이름과 예약 경로 없는 폴더를 대조해 새 필수 생성·과잉 보호가 없어야 한다. 기존 launcher·manifest의 근거 있는 유지와 일반 내부 항목의 안전한 이동 후보는 유지한다.
- tiered 결과 수용에서도 공유 validator가 실행되는 기존 `tests/test_tiered_review.py`의 최소 사례로 보호 우회가 없는지 확인한다. 원격 source·예약 경로 근거가 바뀌면 기존 identity 재확인을 따르며 오래된 성공 근거를 만들지 않는다. 실제 이동·PR 생성을 검증의 대용으로 실행하지 않는다.
- `tests/test_origin_registration.py`의 AGENTS 유무·내용·인코딩 무관 계약과 `tests/test_managed_configuration.py`의 기존 파일 보존은 변경하지 않는다. 선택된 unittest 수집·Agent guard·필수 compile과 Manager 검증 범위는 유지한다.

## Decision Log

- 선택적 예약은 존재하는 경로의 위치 보호다. 파일의 존재를 강제하거나 프로젝트 AGENTS를 Manager가 관리하는 과거 정책을 복원하지 않는다. R-028·R-064의 프로젝트별 신규 루트 배치 기준과 구분해 이미 명시된 예약 경로를 보호하며, 이 보호에 별도 정책 선택의 dependency를 추가하지 않는다.
- complexity low: 기존 inventory와 공유 root validator의 국소 조건을 확장한다. risk medium: 누락하면 CLI 설정/규칙·ignore 탐색 위치가 깨지는 계획을 수용할 수 있고 과잉 보호는 불필요한 이동 금지를 만들 수 있다. 정확한 예약 경로·부재·유사 prefix·부모 이동 조합으로 양쪽을 검증하며 새 Git 쓰기나 데이터 삭제는 없다. priority normal은 현재 필수 경로 보장의 누락 보완이다. Model·Effort는 Manager 설정을 따른다.
- 구현·테스트·verify를 실행하거나 기존 계획·Requirement·사용자 결정·G-242 작업 공간을 수정하지 않았다. 기존 G-206의 수행 기록을 현재 작업의 성공으로 소급 사용하지 않는다.
