## Purpose

등록된 PR의 충돌 수정을 실제 시작하고 검증된 수정이 기존 PR에 반영됐을 때 각각 알린다. 기존 Worker 최초 시작·차단 후 재개·PR 생성 사건과 수정 사건을 연결해 누락과 중복을 막는다.

## Acceptance Criteria

- 기존 PR 충돌 관측·선택·preflight만으로 시작 알림을 만들지 않는다. 소유권 확인 뒤 실제 수정 작업을 시작하면 계획·기존 PR 링크·발생 시점·수정 중 상태를 담은 무음 알림을 한 번 만든다. Worker 최초 호출이 이미 있었거나 Agent 호출 없이 관리 rebase로 시작해도 같은 실제 시작 기준을 적용한다.
- 같은 수정의 내부 교정·재시도·일시 중단 뒤 자동 재개는 새 시작이 아니다. 통지된 차단 후 실제 재개와 같은 시작이면 이전 차단과 PR 충돌 수정 내용을 하나의 무음 알림으로 통합하고 일반 Worker 시작을 추가하지 않는다. 부분 차단 전송 확인과 시작의 경합에도 기존 incident 조건을 유지한다.
- 필요한 targeted unit test·전체 verify·Review를 통과한 수정 결과가 기존 소유 PR branch에 원격 반영되고 검토·Merge 대기 상태로 확정된 뒤 기존 PR 링크를 담은 일반 완료 알림을 한 번 만든다. 로컬 충돌 해소·중간 checkpoint·검증/Review/게시 실패·일시 중단은 완료가 아니다.
- push 뒤 상태 반영 중단과 재시작 복구에서도 같은 수정의 시작/완료 identity를 유지한다. 완료 뒤 실제 새 충돌의 별도 수정은 새 사건으로 구분하며 SHA 변화·반복 관측만으로 새 수정 사건을 만들지 않는다. PR 생성·실제 Merge 및 프로젝트 완료와 구분한다.
- 확정 사건은 owning transaction commit 뒤 다음 장시간 실행 전에 전송을 시도한다. 실패·비활성화는 실행·검증·게시를 바꾸지 않으며 기존 outbox 내용·cursor·감사와 긴 메시지의 PR/차단 근거를 보존한다.
- PRODUCT의 Telegram 사건과 ARCHITECTURE의 실제 시작·기존 PR 게시/복구·알림 책임 설명을 최종 동작에 맞춘다. 실행 및 Merge gate를 알림 목적으로 변경하지 않는다.

## Implementation

recovery/pull_request_recovery.py의 충돌 수정 진입, 실제 rebase/Worker 시작, execution/execution_publication_handler.py의 기존 PR 완료와 git/publication_service.py의 확인된 push 복구를 기존 notifications incident·outbox에 연결한다. 이미 저장하는 PR identity·충돌 원격/목표 base·checkpoint와 단일 사건 키를 재사용해 수정 lifecycle을 추적한다. 일반 record_process_start의 계획 최초 시작 여부를 수정 사건 기준으로 대신하지 않는다. notifications/rendering.py와 차단 재개 materialization이 같은 사건 정보로 단일 메시지를 만들도록 하며 새 저장소·범용 이벤트 체계를 도입하지 않는다.

## Validation

- Worker는 test_pr_conflict_corrections.py·test_notification_events.py의 최소 unit case로 관측/선택/소유권 거부 무통지, 기존 Worker 시작 뒤 실제 수정, rebase만의 수정 시작, 내부 교정·재개 무중복을 확인한다. 실제 판단·SQLite/outbox를 사용하고 Git/Agent/Telegram 관측은 mock으로 제공한다.
- test_notification_incidents.py·test_pr_conflict_publication.py의 기존 회귀로 차단 재개 중복 제거·부분 전송 경합, 검증/Review/게시 실패의 완료 부재, push 후 상태 저장 중단·재시작·완료 후 새 충돌을 검사한다. 기존 실제 lease/index 효과 회귀를 재사용하며 알림만을 위해 실제 게시를 반복하지 않는다.
- Manager 전체 verify는 같은 PR·session/작업물·검증·ownership·lease와 중단 복구를 유지한다. Reviewer는 시작/완료가 실제 효과·최종 gate에 연결되고 새 PR/실제 Merge로 표시되지 않는지 확인한다.

## Decision Log

- 충돌 진입은 operation_print를 사용하고 기존 PR 완료는 open_pull_request로 돌아간다. 현재 record_process_start는 이미 시작한 계획의 일반 시작을 억제하며 별도 수정 시작/완료 사건을 만들지 않는다. 기존 push 복구도 같은 알림 완료 경계에 연결해야 한다.
- complexity medium: 기존 PR/복구 identity·transaction·outbox와 실제 시작/완료 책임을 연결한다. risk low: 실패 영향은 알림 누락·중복·상태 표시이며 실행·원격 소유·검증 정책은 보존한다. 감사와 코드 교정으로 후속 표시를 복구할 수 있어 priority normal이다.
- G-225·G-226의 알림 목표와 G-246의 지속 실패 제외를 중복 구현하지 않는다. 같은 helper를 써도 선행 Merge가 필요한 제품 조건은 없으며 독립적으로 검증한다.
