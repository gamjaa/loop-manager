## Purpose

기존 PR의 충돌 수정 시작·진행·자동 재개 알림을 제거한다. 검증·Review를 통과한 새로운 수정 후보가 기존 PR에 게시되고 사용자가 다시 검토·Merge해야 하는 경우에만 한 번 알린다. 원래 충돌 처리·중단·검증·Git 게시/감사는 유지한다.

## Acceptance Criteria

- PR 충돌 관측·수정 시작·rebase/Worker 호출·내부 교정·재시도·검증 실패·일시 중단·자동 재개·차단 해제에는 일반/무음 Telegram을 전송하지 않는다. 실제 과정은 운영 로그·checkpoint·DB에 보존한다.
- 필요한 targeted test·전체 verify·Review를 통과하고 기존 PR branch에 새로운 수정 후보가 원격 반영돼 사용자가 재검토·Merge해야 할 때만 PR 링크와 현재 검토 대상을 한 번 알린다. 단순 rebase·동일 후보 재게시·반복 관측은 제외한다.
- 새 PR 생성과 기존 PR 수정 후 재검토 알림은 실제 하나의 사용자 행동을 중복 안내하지 않는다. Merge·검토 후보 소멸·해소를 발송 직전에 재확인해 오래된 미전송 조각을 취소한다.
- 원격 push 뒤 상태 저장 중단·재시작·부분 전송 실패에도 기존 PR identity·검증 근거·작업물·전송 감사는 보존한다. 알림을 위해 원격 게시를 반복하지 않는다.

## Implementation

- [ ] `recovery/pull_request_recovery.py`·`execution/execution_publication_handler.py`와 `notifications/events.py`의 기존 PR 충돌 시작/진행 메시지를 생성하지 않는다. 내부 수정 lifecycle 근거는 보존하고 별도 통지 엔진을 도입하지 않는다.
- [ ] 기존 `notifications/incidents.py`·`delivery.py`·`rendering.py`에서 PR의 검증된 새로운 원격 후보·사용자 검토 필요 여부만 통지하고 동일 PR/후보 중복·최신 Merge·조치 해소를 재검사한다. R-053의 일반 알림 gate는 G-189가 통합하며 PRODUCT·ARCHITECTURE는 구현 결과에 맞춰 갱신한다.
