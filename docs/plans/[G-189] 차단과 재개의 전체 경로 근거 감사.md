## Purpose

코드의 차단·중단 생성과 재개 경로를 빠짐없이 추적해 R-055가 요구하는 코드/테스트 근거와 책임별 감사 기록을 남긴다.

## Acceptance Criteria

- 실제 코드의 모든 block/pause/error 생성·해제 경로를 조건·scope·보호 규칙·자동 복구·사용자 조치·관련 테스트와 담당 ExecPlan에 연결한 목록을 관련 계획의 Implementation/Decision Log에서 확인할 수 있다.
- 문제가 없는 경로에도 검토 근거가 있고 오탐/과도한 중단에는 재현 가능한 코드·테스트·필요한 수정과 유지할 실제 위반의 회귀를 연결한다. 선행 구현이 바꾼 경로와 남은 불확실 범위를 구분한다.
- 일시 실패·실행별 한도·계획별 실패·공유 안전·승인·PR 종료·cleanup 보존을 구분한다. 동일 입력의 무한 호출/Git 쓰기/알림, 단순 지문 변경을 요구하는 이미 해소된 오탐과 독립 차단 일괄 해제를 감사한다.
- 로컬 base·Python 캐시는 R-056·R-059의 담당 계획을 참조한다. 운영 SQLite 사건의 수정/삭제나 빈도 주장을 하지 않으며 archive 감사에서만 발견한 후속은 원문 복원·원격 확인 전 새 구현 범위로 승격하지 않는다.

## Implementation

- scoped_blocking·recovery state·catalog/planning/maintenance/execution와 cleanup 소비자를 코드 검색/직접 읽기로 감사한다. 목록은 현재 선택 ExecPlan 및 실제 관련 계획의 허용 기록 경계에 남기고 새 운영 상태 원본을 만들지 않는다.
- 기존 재현/회귀를 재사용해 목록의 각 판정을 뒷받침한다. 활성 R-055 선행 계획으로 해결된 항목, 실제 사용자 판단 항목과 archive 원문 복원 대기를 명시해 미충족을 완료로 숨기지 않는다.
- 자동 역할·권한·검증은 docs/AGENTS.common.md와 해당 역할의 docs/AGENTS.*.md를, 프로젝트 규칙·설계·계획 작성은 AGENTS.md·docs/ARCHITECTURE.md·docs/PLANS.md를 참조한다. 기존 helper·관련 테스트를 재사용하고 지정 루트 경로를 보존한다.

## Validation

- 감사 중 실제로 추가/변경한 판정 unit case의 최소 범위만 실행한다. 코드 변경 없이 기존 근거만 연결했다면 그 이유와 사용한 테스트 경로를 남긴다.
- Manager 전체 verify는 독립 계획/프로젝트 지속, 실제 안전·승인 차단, session/작업물·실패 피드백·PR 복구와 후보 재검증을 유지한다. 감사 문서만으로 전체 R-055 충족을 추정하지 않는다.
