## Purpose

기존 원인별 복구 정책을 사용하는 recover 명령을 추가해 로컬 환경 문제를 수동 SQLite 수정 없이 재검사한다.

## Acceptance Criteria

- recover <repository>와 선택적 --plan, 기존 state-dir·전역 잠금으로 등록 프로젝트의 현재 원인을 재검사한다. 미등록 repository·없는 계획·잘못된 조합은 실패하고 새 빈 DB를 만들지 않는다.
- 로컬 환경 개선의 bounded 재검사 요청을 감사 기록으로 남긴다. 기존 원인·진전 지문·실패/승격 이력을 임의 초기화하지 않으며 필요한 timeout 단계만 기존 경로에서 다시 실행한다.
- 해결된 원인만 해제하고 기존 session·worktree를 이어간다. 독립 차단·승인·dependency·닫힌 PR·실제 범위 위반은 남긴다. 일반 run과 재시작도 기존 자동 복구를 계속한다.
- 대상·재검사 결과·남은 사용자 조치와 종료 코드를 확인할 수 있으며 같은 요청의 중복/경쟁에서 작업물과 잠금 정책이 유지된다.

## Implementation

- loop_manager.py의 기존 CLI·등록 조회·잠금과 recovery 서비스에 얇은 명령 경계를 추가한다. 원인 해소 판단은 기존 복구 책임에서 수행하고 새 범용 unblock 정책을 만들지 않는다.
- 요청 identity와 소비 상태를 기존 복구 저장소에 최소 연결한다. 운영 SQLite 사건을 개별 수정·삭제하는 기능은 추가하지 않는다.
- 문서·권한·게시와 검증의 공통 경계는 AGENTS.md, docs/ARCHITECTURE.md, docs/PLANS.md를 따른다. 필요한 기존 helper와 관련 테스트를 우선 재사용하고 새 루트 항목을 만들지 않는다.

## Validation

- CLI·scoped recovery 테스트에서 정상/미등록/없는 계획, 실행 잠금, 해소/미해소 원인, timeout 제한, 다른 승인과 재시작의 최소 unit case를 실행한다.
- Manager 전체 verify는 기본 run 호환성, 실패 이력 보존·독립 차단과 registered scheduler의 복구 지속을 검증한다.
