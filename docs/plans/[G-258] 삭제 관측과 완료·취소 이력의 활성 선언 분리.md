## Purpose

검증한 원격 문서 삭제와 완료·취소·예약 이력을 구분해 현재 선언/조회에 반영한다. 현재 Requirement 삭제 원문을 catalog hold에 저장하고 실제 source 부재를 rename/archive와 구별하는 좁은 관측은 직접 구현됐다. 실행 row 밖의 삭제·역사 자료와 확정 교정 게시의 수명 구분을 완결한다.

## Acceptance Criteria

- 한 원격 revision의 실제 문서·마지막 선언·최초 게시·Merge·취소·예약/보류 근거로 삭제를 관측한다. 일괄 삭제·등록 전 삭제·실행 row 없이 남은 예약/보류도 원문·revision·identity와 미확인 사유를 제공한다. 번호 공백·삭제/추가 동시 관측·로컬 삭제·조회 실패로 identity 변경이나 철회를 추정하지 않는다.
- 실제 Merge·완료·취소·ID 예약 감사는 문서 부재 뒤에도 보존한다. 역사 자료만의 source/링크 부재가 활성 오류·unknown-plan-id 예약 충돌·새 등록을 만들지 않고 검증된 MERGED 선행 충족은 유지된다. 파일 부재만으로 Merge하거나 완료를 취소로 바꾸지 않는다.
- 확정 Requirement 교정의 commit·원문·배정 감사와 현재 결과 경로 존재를 구분한다. 확정 뒤 실제 삭제는 같은 관측/영향 관계로 전달하며 독립 입력을 교정 실패로 막거나 문서를 복원하지 않는다. 미확정 후보의 제거·변조, 원격 이력 재작성·조회 실패는 정상 삭제가 아니다. 살아 있는 작업의 source 부재는 보류·의미 판단 대상이다.
- 계속 실행하는 작업의 source/dependency·identity 충돌 검사는 유지한다. 같은 ID 재등장을 취소 해제/READY 재등록 근거로 쓰지 않고 역사 경로만으로 활성 검사를 생략하지 않는다. R-055의 현재 관계와 보존 감사를 모든 소비자에서 일치시킨다.
- catalog·일반/유지보수 입력·source 조회·Requirement 충족 판단/archive·dependency/우선순위 선택과 기존 조회가 같은 현재 자격을 소비한다. 종료 감사만의 항목을 활성 작업/완료 대기에 재추가하지 않고 실제 미충족 목표·독립 hold·수동 예약은 보존한다.
- 과거 원문 조회 실패는 해당 미확인 근거로 남기며 확인 가능한 독립 입력 검토를 막지 않는다. 원격/저장 snapshot 경쟁·재시작에서 검증되지 않은 관계 해제·삭제/완료 성공·반복 등록을 만들지 않는다.

- [x] `loop_manager_internal/catalog/execplan_catalog.py`, `requirement_sources.py`와 `loop_manager_internal/storage/execplan_catalog_state.py`의 현재 선언/역사·Merge proof·ID 예약 경계를 공통 소비자에 전달한다. 실제 활성 source 오류·역사 문서 부재·같은 identity rename/archive를 구별하고 운영 DB 직접 교정·비가역 migration은 하지 않는다.

## Validation

- 실제 parser·resolver·SQLite에 모의 Git/PR 관측을 제공해 완료 Requirement와 MERGED 문서 동시 삭제, 완료 선행이 필요한 활성 작업, row 없는 취소/예약·일괄/등록 전 삭제·원문 부재·같은 ID 재등장을 구분한다. Merge/취소/예약 증거는 유지되고 감사만의 항목은 선택되지 않아야 한다.
- `tests/test_project_catalog_refresh.py`, `tests/test_catalog_scheduling.py`, `tests/test_requirement_retirement.py`의 관련 fixture에서 현재 source 오류·rename/archive·조회 실패와 미확인 관계 보존을 확인한다. 역사적 source 부재는 독립 검토를 막지 않고 활성 source 부재는 실행 보류로 남아야 한다.
- `tests/test_requirement_correction_publication.py`에서 교정 확정 뒤 실제 삭제·활성 후속 source 부재·재시작은 감사 보존/영향 전달로, 미확정 후보 제거·변조·원격 commit 유실은 거부로 확인한다. 삭제된 원문 복원·중복 게시가 없어야 한다.
- snapshot 경쟁·transaction 중단·반복 관측에 부분 관계 적용/성공이 없어야 한다. 부분/전체 verify의 회귀 조건은 실제 identity 재사용 거부·Merge proof·독립 READY·현재 source/dependency gate·미충족/draft 대기다.

## Progress

## Decision Log

- Requirement 삭제의 관측이 없다는 이전 설명은 직접 구현 이후에 사용하지 않는다. 현재 조회는 exec_plans와 hold의 보존 원문을 중심으로 하므로 row 없는 예약/종료 감사와 전체 소비자 일치는 별도 잔여 목표다.
- confirmed 교정 결과의 현재 경로가 사라진 경우 resolver의 missing을 곧바로 게시 실패로 처리하는 경계를 보완한다. 기존 확정 원문·commit 감사는 유지하고 미확정 결과 제거의 거부를 완화하지 않는다.
- G-189의 전체 감사와 별도 복구/취소/자원 정리 범위를 대체하지 않는다. deleted_goals가 없는 이번 호출에서 실제 삭제나 DEPENDENCY_RECOVERY 성공을 만들지 않으며 기존 source 문자열을 rename만으로 교체하지 않는다.
- complexity medium: 원격 관측·resolver·현재 선언/역사·기존 소비자 경계에서 판단 기준이 명확하다. risk high: 잘못된 자격은 필요한 선행을 충족으로 선택하거나 취소 ID를 재실행시킨다. 원문·Merge proof·예약·관측 감사를 보존해 수동 재평가하며 row 없는 기록·재등장·미확정 유실·독립 진행을 검증한다.
