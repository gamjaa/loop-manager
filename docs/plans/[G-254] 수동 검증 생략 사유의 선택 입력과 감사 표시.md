## Purpose

manual complete/submit의 --skip-reason을 선택 입력으로 바꾸고 사유 미입력을 감사·Reviewer 입력·PR 설명에서 명확히 표시한다. 정확한 후보 SHA와 단계별 생략의 유효 범위·실제 실패/성공 구분은 유지한다.

## Acceptance Criteria

- complete/submit에서 --skip-verify 또는 --skip-review를 쓰면 전체 --expected-head를 계속 요구하고 --skip-reason 생략·빈 문자열·공백·유효 문자열을 허용한다. 미입력/빈/공백은 동일한 사유 미입력으로 정규화한다. 생략 옵션 없는 reason 지정은 거부한다.
- 원격 expected HEAD 불일치·짧은 SHA/이동 ref·소유권/구성/dependency/일반 사용자 결정은 기존처럼 거부/보류한다. 사유 선택성으로 생략 옵션을 자동 선택하거나 새로운 성공 근거를 만들지 않는다.
- 실제 PASS·FAIL·NOT_RUN과 SKIPPED_BY_USER를 구분한다. 사유 미입력/제공 여부가 저장 감사·Reviewer 입력·최종 PR 설명에서 같고 미입력에는 확인되지 않은 사유나 수행 결과를 채우지 않는다. 기존 제공된 reason·원문/실패/요청 감사는 덮어쓰지 않는다.
- SHA·base·전체 G 정의·명세/지침·환경·단계 입력 변화와 같은 후보의 실제 실패에서 기존 생략 무효화·기본 재실행을 유지한다. 재시작·새 무옵션 요청이 과거 생략을 상속하지 않으며 생략은 실제 성공 cache·Worker/invocation 결과·Merge 완료가 아니다.
- CLI 도움말과 수동 제출의 현재 제품/설계 설명을 선택 입력과 일치시킨다. Skill·복사용 프롬프트/별도 완료 안내의 R-076 목표는 기존 G-239에 남기며 그 작업이나 수동 소유 계획을 변경하지 않는다.

## Implementation

application/manual_work.py의 validate_options와 complete/submit 수락, storage/manual_work_state.py의 기존 reason 기록, execution/manual_candidate.py의 waiver/Reviewer 표시와 최종 PR 보고 소비자를 대조한다. 기존 schema에 허용된 빈 문자열을 사용해 수락 시 새 입력을 정규화하고, legacy 기록은 읽기 표시에서 사유 유무를 구분한다. 같은 formatter/보고 책임을 재사용하고 사용자 면제와 실제 실행 결과의 의미를 유지한다. 운영 설정 지문 결합은 G-200에 남기며 이 변경에서 검증 유효성을 확대하지 않는다.

## Validation

- Worker는 test_manual_work.py의 최소 옵션 unit case로 complete/submit·생략 네 조합, expected HEAD 필수/불일치, 사유 생략/빈/공백/제공과 reason 단독 거부를 검사한다. 저장/후속 판단은 실제 SQLite와 handler를 사용하고 Git/Agent 관측은 기존 fixture mock으로 제공한다.
- 분리된 `tests/test_manual_work_waivers.py`의 waiver·Reviewer 표시와 `tests/test_manual_work_validation.py`의 실제 실패·설정 변경 회귀, 공통 `tests/support/manual_work_case.py`를 재사용해 수락→waiver 기록→Reviewer/PR 출력과 재시작에서 사유 미입력/제공 여부·SKIPPED_BY_USER/실제 PASS·FAIL이 일치하는지 확인한다. 기존 실제 실패 무생략·입력 변경 기본 실행·새 무옵션 요청·묶음 identity/소유 보호와 비밀값 비노출 회귀를 유지한다. 옵션·표시 조합은 해당 판단까지만 검사하고 후속 실제 게시를 반복하지 않는다.
- Manager 전체 verify는 complete/submit 자동 후속 교정·재검증·PR/실제 Merge·기존 요청/생략 감사와 일반 자동 Worker 경로를 유지한다. Reviewer는 사유 미입력이 실제 성공으로 표현되거나 후보/입력 gate가 약화되지 않았는지 확인한다.

## Decision Log

- validate_options는 생략에 비어 있지 않은 reason을 요구한다. 저장은 이미 빈 문자열을 허용하지만 waiver/Reviewer는 빈 reason을 단순 빈 꼬리로 표시한다. 새 R-077의 사유 미입력 수락·명시 표시가 남아 있다.
- complexity medium: 두 수락 경로와 기존 감사/waiver/Reviewer·PR 소비자의 입력/표시를 연결한다. risk medium: 표시 오류가 면제와 수행 결과를 혼동하거나 과거 감사를 덮어쓸 수 있어 실제 단계 상태·후보 gate·legacy 기록을 유지한다. 보존 감사와 후속 표시 교정으로 복구하며 priority normal이다.
- G-200의 실제 운영 설정 결합과 G-239의 명령 Skill/수동 구현 안내는 다른 남은 목표다. 이 계획은 새 선택 사유 계약만 구현하고 그 계획·dependency·수동 G-207 및 실제 실행 결과를 수정하지 않는다.
