## Purpose

R-028의 신규 루트 파일 필요성·Reviewer 차단 기준과 R-064의 프로젝트별 구조 규칙 경계 사이에 남은 적용 범위를 사용자 판단으로 확정한다. 이미 구현된 모든 루트 항목 조사·안전한 이동 계획 연결과 예약 경로 보호는 유지한다. 사용자 소유 Requirement를 자동 수정하거나 Loop Manager 자체의 구조 제한을 다른 프로젝트에 임의 주입하지 않는다.

## Draft Decision

Question: R-028의 신규 루트 파일 필요성·Reviewer 차단 기준을 모든 등록 프로젝트의 공통 규칙으로 유지할 것인가, 아니면 Loop Manager 자체와 각 프로젝트 지침이 정한 범위로 한정할 것인가?
Facts: 활성 R-028은 모든 대상 프로젝트에서 필요한 루트 파일만 유지하고 신규 Worker 변경·Reviewer가 실행·도구 계약으로 필요성을 확인하도록 하며 AC 1·10에 이를 둔다. 활성 R-064는 각 프로젝트의 개발·구조 규칙을 프로젝트 지침에 맡기고 Loop Manager 전용 신규 루트 제한을 다른 프로젝트에 주입하지 않도록 한다. PRODUCT의 공통 Agent 지침과 ARCHITECTURE의 AI Agent 실행도 이 경계를 따른다. 현재 신규 루트 필요성·blocking issue 문구는 이 저장소의 AGENTS.md에 있고 runtime common/worker/reviewer에는 예약 경로 보호와 일반 정합성 검토가 있다. R-028의 일반 기준과 Loop Manager 전용 제한을 어디서 구분해 보장할지 현재 명세만으로 확정할 수 없다. G-206의 루트 조사 구현은 이미 반영됐지만 신규 변경의 적용 범위 질문을 해소하지 않는다.
Options: (A) 모든 등록 프로젝트에 적용할 최소 신규 루트 필요성·검토 기준과 프로젝트별 예외·구조 규칙의 관계를 사용자가 R-028·R-064에 명확히 한다. (B) 신규 루트 제한을 Loop Manager 자체 또는 해당 프로젝트 지침이 정한 범위로 한정하도록 사용자가 R-028의 Requirement·AC 1·10을 정합화한다. 기존 예약 경로 보호·정상 유지보수 조사·소유권과 참조가 불명확한 항목의 이동 금지는 두 선택 모두 보존한다.
Impact: A는 명세 확정 뒤 필요한 범위의 지침·전달·Review 보완만 같은 ID에서 재평가한다. B는 이미 반영된 프로젝트별 구조 지침과 실제 동작을 대조해 남은 정합화만 판단한다. 결정 전에는 Worker·workspace·branch·구현 PR을 시작하지 않으며 R-028 전체 충족·archive를 확정하지 않는다. 독립적인 G-287과 다른 작업은 계속한다.

## Acceptance Criteria

- 사용자가 R-028·R-064의 적용 대상과 두 규칙의 관계를 명확히 한 원문·출처를 질문과 대조한다. 무관한 사용자 변경·Agent 추론·기존 계획 Merge만으로 어느 정책을 선택한 것으로 보지 않는다.
- R-028의 신규 파일 필요성 기준과 Reviewer blocking issue 권한에 대해 모든 프로젝트의 공통 보장, 프로젝트 지침의 역할, Loop Manager 자체의 제한을 구분할 수 있다. 예약 경로·등록/계획 입력·CLI 지침 독립성·기존 사용자 변경 보존은 유지한다.
- 확정한 정책과 현재 `AGENTS.md`·runtime 지침·호출·Review 경계를 대조해 실제 미충족 작업만 같은 ID에 남긴다. 사용자 문서의 직접 정합화로 충족된 부분에 중복 Worker 구현·소급 테스트 성공을 만들지 않는다. 실행이 필요하면 사용자 선택을 반영한 구현·검증 범위를 Manager의 안전한 개정 경계에서 확정한 뒤 진행한다.
- Planner·Worker가 사용자 Requirement를 편집하거나 draft·User Decision을 직접 해제하지 않는다. 질문별 해소 근거와 기존 문서·기술 결정·독립 작업을 보존하고 대기 전환은 Manager가 검증한다.
