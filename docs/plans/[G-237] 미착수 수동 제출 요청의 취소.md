## Purpose

manual cancel과 수동 작업 reset에서 자동 후속 처리에 착수하지 않은 유효 제출 요청만 취소한다. 작업물과 수동 대기를 유지하며 후속 시작과 취소를 원자적으로 조율한다.

## Acceptance Criteria

- `manual cancel <repo> <id>`와 수동 `reset <repo> <id>`는 같은 취소 자격·결과를 사용한다. 유효한 미착수 요청을 취소해 수동 구현 대기로 돌아가고 branch·후보·session·단계 결과·실패·과거 감사는 보존한다. READY로 초기화하지 않는다.
- 이미 취소/유효 요청 부재는 정상 무변경이다. 검증·Review·교정·게시에 착수한 요청은 거부하고 필요한 pause 안내를 제공한다. pause는 착수 이력을 되돌리지 않는다.
- PR 생성·연결 뒤에는 취소/reset을 거부하고 Requirement 변경·새 계획 경로를 안내한다. 실제 PR·Merge 추적은 유지한다. 구성 G 하나를 지정해도 저장된 묶음 전체를 확인하고 하나라도 거부 조건이면 전체를 보존한다.
- 취소와 자동 후속 시작은 하나의 소유권/저장 경계에서 승자를 확정한다. 취소 뒤 run·원격 push·재시작이 같은 요청을 자동 복구하지 않으며 명시적 새 complete/submit만 수락한다.
- 결과는 전체 대상·적용 여부·보존 상태를 알리고 정상 완료/무변경 0, 거부 1, 인자 오류 2다. 자동 작업 reset과 manual stop의 실제 초기화는 G-238에서 제공한다.

## Implementation

기존 manual_work_state·수락 요청·묶음·자원 예약과 재개 선택을 확장한다. 현재 유효성·착수·취소를 감사와 구분하고 기존 단계 결과를 삭제하지 않는다. reset parser는 수동 분기를 명확히 연결하며 자동 대상은 G-238 구현 전 미지원으로 거부한다. PRODUCT·ARCHITECTURE와 사용자 안내를 같은 PR에 반영한다.

## Validation

- 실제 SQLite/수동 서비스 targeted unit test로 미착수·착수·이미 취소·PR·pause 뒤 자격·묶음 일부 거부·취소/시작 경쟁을 검사한다. 취소 뒤 자동 재개 부재와 명시적 재제출을 확인한다.
- 전체 verify는 branch·원격·session·후보·감사 불변, 원자 취소와 재시작, 기존 수동 수락/후속 처리 순서·독립 작업 진행을 유지한다. Git/PR 관측만 mock한다.
