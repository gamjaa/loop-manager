## Purpose

최초 호출을 시작한 관리 작업이 다음 단계·교정·임시 대기에서 돌아오면 같은 작업의 이어하기로 배정한다. 현재 수동 제출 → 명시적 해제 → RETRY → 기존 재개 → 신규 분류와 신규 프로젝트 순환을 유지하며, 정상 단계 전환에도 이어하기 자격이 보존되도록 보완한다.

`Task.rank()`의 category와 `requeue()`의 durable RETRY는 이미 구현돼 있다. 그러나 `TaskScheduler.task()`는 저장된 `resumed=False`를 COALESCE로 유지하며 정상 후속 단계는 같은 task를 사용하므로, 최초 작업이 후속 호출에서도 신규 category에 남을 수 있다. 이 작업은 그 실제 미충족 연결만 담당한다.

## Acceptance Criteria

- R-091: 실제 시작한 A가 Review 뒤 Worker 교정 등 같은 실행 종류의 후속 호출을 기다리면 신규 B보다 먼저 선택한다. 정상 Worker→verify→Review→게시, 자원 대기·재연결·재시작에도 관리 단위·원래 순서·기존 단계/결과를 보존한다. 예약·미시작만의 후보를 이미 실행한 작업으로 합성하지 않는다.
- 수락 수동 제출과 명시적 차단 해제, RETRY의 특별 순서를 유지한다. 신규끼리의 프로젝트 기본/추가 순환과 유효 priority·숫자 G 순서를 기존 작업을 추월하는 근거로 쓰지 않는다. 실행 중 호출은 선점하지 않는다.
- 실행 불가능한 A는 조건 보류하고 다른 기존 작업·B·독립 프로젝트를 확인한다. A가 verify만 기다릴 때 독립 B의 Worker 자리가 있으면 실행할 수 있다. 반복 재등록한 A가 다른 실행 가능한 기존 작업을 무한히 밀어내지 않는다.
- 실행 우선순위는 Git FIFO·DB 접수 순서를 바꾸지 않는다. 새 자원 요청은 뒤에 서고 기존 요청의 identity/순번은 재확인으로 초기화하지 않는다. 기존 관리/호출 상한·필수 gate·중복 실행 거부를 유지한다.

## Implementation

- [ ] 확인한 `application/task_scheduling.py:Task.rank()`·`TaskScheduler.task()`·`slot()`과 `run_project_tasks()`의 최초/후속 호출 연결에서 실제 시작과 이어하기 전이를 구분한다. `storage/management_admission.py`의 기존 resumed/retry_order·sequence를 재사용하고 필요한 호환 정보만 보완한다. 새 전역 우선순위 설정·별도 관리 원본을 추가하지 않는다.
- [ ] `storage/task_calls.py`의 예약·실제 시작/종료·결과 확정과 단계 전환에서 이어하기 근거를 보존한다. DB 반영 실패 뒤 실제 완료 효과를 반복하거나 미시작 호출의 순서를 소비하지 않는다. 기존 durable RETRY 등록/소비와 명시 요청의 인계는 재구현하지 않는다.
- [ ] 확인한 `tests/test_task_scheduling.py`의 기존 우선순위·cursor·재연결·관리 자리 회귀와 `tests/test_manual_work.py`의 교정 단계 보존을 확장한다. PRODUCT·ARCHITECTURE의 배정 순서에 정상 후속 단계까지 포함되는 실제 계약을 통합한다.

## Validation

- Worker targeted unit은 `TaskSchedulingTests`의 변경 case다. 기존 `test_manual_precedes_retry_then_resumed_and_new_calls_without_preemption`을 유지하고, 최초 `resumed=False`로 실제 시작한 A의 정상 단계 전환 뒤 신규 B와 경쟁하는 경로를 실제 SQLite·제어된 호출로 검사한다. rank 값만 설정하는 테스트로 대체하지 않는다.
- A의 verify 대기와 B Worker 동시 진행, A의 사용 한도/미종료/dependency/planning 보류에서 다른 적격 작업 선택, 여러 기존 작업의 재등록 공정성, 재연결/재시작 뒤 순서 보존을 확인한다. 중복 관리·중복 호출·상한 초과는 없어야 한다.
- 기존 인계·RETRY·미시작·완료 효과 저장 재시도와 Git FIFO 회귀를 재사용한다. 순번 변경·실패 이력 초기화·실제 호출 없는 성공 기록은 거부한다. 수동 교정의 현재 활성 단계 보존은 기존 테스트를 소비하며 다시 구현하지 않는다.

## Progress

- [x] 검토 revision의 rank·task 저장과 기존 재배정 회귀를 정적으로 대조했다. 실행·테스트는 수행하지 않았다.
- [x] 현재 `slot()`은 예약 뒤 호출 본문에 진입하기 전에 `resumed=1`과 RETRY 소비를 저장한다. 따라서 단순히 `task()`의 COALESCE를 바꾸는 것으로는 실제 시작과 미시작을 구별할 수 없다. Agent의 실제 시작 콜백과 verify의 프로세스 receipt, 종료·관측 복구를 함께 연결해야 한다.
- [x] Agent 시작 관측과 verify receipt에서 재개 자격·RETRY 소비를 예약별로 확정하고 저장 실패 시 원래 근거로 복구한다.
- [x] 후속 호출 우선·미시작·재연결·공정 대기와 기존 인계·호출 한도 회귀를 targeted unit으로 확인하고 제품·설계 문서를 갱신했다. 전체 verify와 Review는 Manager가 수행한다.
