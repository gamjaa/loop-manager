## Purpose

등록·해제 명령을 add/remove로 옮기고 `run [--skip-if-running] [repo...]`에서 지정한 등록 프로젝트만 처리한다. 기존 등록 조건·직렬/병렬 실행·잠금·복구 정책을 유지한다.

## Acceptance Criteria

- add/remove는 기존 config add/remove의 인자·등록 검증·해제 gate를 그대로 사용한다. config init과 유지 대상 명령은 보존하고 config add/remove 호환 별칭은 제공하지 않는다. config list의 제거와 새 list는 G-194가 맡는다.
- run의 경로를 정규화·중복 제거하고 지정한 전체의 등록 여부를 작업 시작 전에 검증한다. 하나라도 미등록이면 어느 프로젝트도 처리하지 않는다. 생략하면 기존 전체 범위이며 공백 경로를 지원한다.
- 선택 범위에서도 max_workers·프로젝트별 단일 변경 자리·dependency·복구·self handoff·skip-if-running을 유지한다. 한 프로젝트 실패는 독립 대상을 막지 않고 범위 밖 프로젝트는 실행하지 않는다.
- 도움말·README/운영 안내를 새 이름·범위로 갱신하고 PRODUCT·ARCHITECTURE의 해당 진입 책임을 반영한다. 기능 이름 변경을 등록 gate 완화로 사용하지 않는다.

## Implementation

기존 build_parser·application/commands.py·등록 프로젝트 scheduler와 bootstrap 인자 전달을 확장한다. 범위 확인은 등록 상태 원본으로 수행하고 실제 프로젝트 판단은 기존 runner에 맡긴다. 설정·Agent profile을 새 기본값으로 바꾸지 않는다.

## Validation

- parser/registry/scheduler targeted unit test로 새 이름과 옛 이름 거부, 경로 중복·미등록 사전 거부·범위 선택·독립 실패 지속을 확인한다. 등록·실행 판단 자체를 성공 mock으로 대체하지 않는다.
- 전체 verify는 기존 등록/해제·전체 실행·잠금·동시 상한·self handoff·인자 전달을 유지한다. 필요 없는 전체 CLI/Git 연결 조합은 mock으로 검사한다.
