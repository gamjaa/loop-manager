## Purpose

이미 Merge된 사건 시점 알림을 PRODUCT와 ARCHITECTURE의 현재 계약에 반영한다. 현재 PRODUCT는 R-053 링크와 기존 PR·차단·재개·대기·완료 규칙만 설명하며, ARCHITECTURE에는 실제 시작·즉시 전송·주의 수준·새 사건의 저장 경계가 빠져 있다. 알림 구현을 다시 만들지 않는다.

## Acceptance Criteria

- PRODUCT의 Current Goals·관련 불변식과 Telegram 조건이 작성 완료/미게시·새 계획 없음·게시/catalog 반영·물리적 Worker 시작·단계 실패·PR Merge 대기를 구분한다. READY 선택·실패한 게시·PR 등록을 실행 또는 Merge 완료로 표현하지 않는다.
- 사건 확정 뒤 같은 실행에서 가능한 즉시 전송을 시도하며 시작·계획 생성은 다음 긴 Agent/verify 전에 시도하는 조건을 기록한다. 참고·자동 재시도 실패의 무음과 PR 검토/Merge·승인·최종 조치의 일반 알림, draft의 링크·필요한 결정·중복 억제를 설명한다.
- ARCHITECTURE에서 owning state transaction의 사건 저장, 실제 process 시작 callback, 프로젝트별 commit 후 flush와 다음 실행의 실패 전송 재시도, 원래 발생 시각·처리 상태·silent의 payload/transport 연결을 확인할 수 있다.
- 사건 identity·부분 전송 cursor·재시작, 해제된 차단의 전송 중 조각과 재개/일반 시작 중복 방지, 독립 계획 재개 중 planning 오류 보존을 설명한다. 비활성화·일부 설정 오류·비밀값 가림·긴 메시지 보존·checkpoint·완료 gate는 유지한다.
- 관련 절을 통합하며 코드·Requirement·사용자 결정·완료 판정은 변경하지 않는다. 실행 로그나 수행하지 않은 검증 성공을 문서에 추가하지 않는다.

## Implementation

- `notifications/{events,repository,incidents,delivery,transport,rendering}.py`, planning state/publication, invocation service, execution 실패와 scheduler의 실제 wiring을 근거로 두 명세의 관련 절을 재작성한다. PRODUCT에는 관찰 가능한 동작을, ARCHITECTURE에는 저장·전송·중복 방지 경계를 둔다.
- 기존 차단/재개/대기/완료 설명을 새 사건 계약과 통합하고 R-053 및 관련 소유 절로 연결한다. scope·실행 선택·사용자 승인·게시 정책을 문서 보완으로 바꾸지 않는다. AGENTS.md·Specification Skill·docs/PLANS.md의 문서 역할과 현재 Worker 권한을 따른다.

## Validation

- 두 명세를 `tests/test_notification_events.py`의 TimelyProgressEventTest, `test_notification_delivery.py`의 TimelyProgressDeliveryTest, `test_notification_incidents.py`의 독립 계획/전송 중 재개, `test_provider_runtime.py`의 launch-before-prompt와 Worker/Reviewer 실패 회귀에 정적으로 대조한다. 문서만 바꾸므로 Worker targeted unit 실행은 해당 없음으로 사유를 기록한다.
- Manager 전체 verify는 기존 사건·물리적 시작·rollback·부분 전송·비밀값 제거·완료 조건 회귀를 그대로 수집하고 통과해야 한다. 문서 수정만으로 Requirement 충족·Merge·전체 검증 성공을 기록하지 않는다.
