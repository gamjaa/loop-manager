## Purpose

현재 모듈 유지보수 평가에서도 첫 구조 평가의 모든 루트 항목을 실제 참조·사용자 경로·소유권과 안전한 목적지로 조사하고, 확인된 이동 후보를 동작 보존 ExecPlan에 연결한다. R-028의 기존 공통 지침과 파일별 평가 구현을 반복 구현하지 않고 새 평가 경로에 빠진 근거·검증·게시 경계만 보완한다.

## Acceptance Criteria

- 최초 정상 구조 평가에서 소스 분류로 제외된 문서·자산·언어별 manifest·설정도 포함해 모든 추적 루트 항목의 실제 참조, 사용자 이용 경로, 소유권, 유지 또는 이동 이유와 안전한 목적지를 확인한다. 소스 모듈이 없는 tree도 미조사 루트가 있으면 평가 완료·no-change·전체 성공으로 확정하지 않는다.
- 조사 결과는 실제 원격 원본·mode·참조 내용과 평가 범위에 결합된다. 누락·중복·위조 인용·낡은 근거를 거부하고, 정적 경로·분류나 모듈 receipt만으로 루트 조사 성공을 만들지 않는다.
- `.agents/`, `docs/`, `scripts/`와 지정 문서·현재 OS verify 경로는 이동 후보가 되지 않는다. 언어별 manifest·launcher·설정은 프로젝트별 실행·도구 근거로 유지할 수 있으며, 파일명·확장자만으로 유지나 이동을 확정하지 않는다. 소유권·참조가 불확실하거나 사용자 변경과 충돌하는 항목은 이동·삭제 대신 구체적인 보존 이유를 남긴다.
- 확인된 모든 이동 후보를 새 계획 또는 해당 목표를 이미 포함한 비종료 계획에 연결한다. 연결을 생략한 no-change 결과를 거부하며 근거 있는 제외는 그 조사 결과로 설명한다. 위치 변경 계획에는 import, 실행 명령, 빌드·배포, 설정 탐색, 상대 경로와 문서 링크 및 사용자 동작·공개 계약·저장 형식의 보존과 targeted test·전체 verify·읽기 전용 Review 조건이 있다.
- 조사와 계획 연결의 미완료 결과·session·게시 intent는 중단 뒤 보존하고, 원격 게시·catalog 반영과 현재 입력 대조 뒤에만 성공으로 확정한다. 원본이나 조사 참조가 바뀌면 관련 근거만 재확인하며 이전 조사 성공을 새 원본에 합성하지 않는다.
- 기존 검증된 루트 조사와 동일 입력의 모듈 검토를 재사용한다. 루트 확인을 기존 평가 안에 포함하고 별도 중복 전체 스캔, 새로운 유지보수 cycle, prerequisite Merge 뒤 평가 또는 종료용 사후 재검증을 추가하지 않는다. 이미 종료된 cycle·과거 receipt는 그대로 보존하고, 조사 없는 과거 모듈 성공을 이후 평가의 루트 조사 증거로 사용하지 않는다.

## Implementation

- `maintenance_file_inventory`의 전체 루트 목록과 `storage/maintenance_file_ledger`의 `validate_root_reviews`·`root_move_candidates`, 기존 원본 인용·필수 경로 보호·조사 재사용 경계를 먼저 재사용한다. 새 모듈 평가의 입력·결과에 제외된 루트 항목과 그 참조를 확인할 수 있는 경계를 연결한다.
- `maintenance/tiered_review`·`tiered_ports`와 `planning/tiered_assessment`에서 루트 조사 누락을 모듈 검토 완료와 구분한다. 조사 범위·결과·재사용 identity를 명시하고, 소스 없는 tree 및 findings가 없는 경우에도 필요한 루트 조사·후보 처리를 완료 gate에 포함한다. 모든 파일을 소스 모듈로 강제 편입하거나 파일별 평가 전체를 다시 실행하지 않는다.
- 기존 후보 처리·계획 검증에 루트 조사 증거와 목적지를 연결한다. `maintenance_file_publication`의 collect·intent 복구·promote가 루트 근거와 계획 처리 결과도 대조하도록 하고 기존 파일별 결과의 의미·감사와 단일 평가 정책을 보존한다.
- 관련 설계 설명은 현재 구현 경계에 맞춰 정합하게 갱신한다. 역할 권한·공통 검증·문서 작성 기준은 AGENTS.md, docs/PLANS.md, docs/ARCHITECTURE.md와 공통·역할별 instruction을 참조하며 프로젝트 AGENTS 변경이나 실제 파일 이동을 이 계획에 포함하지 않는다.

## Validation

- `tests/test_tiered_review.py`·`test_tiered_assessment.py`에 소스 없는 문서·자산·manifest tree, 소스와 제외 항목이 섞인 tree, 모든 루트 조사 누락·중복·위조, 필수 경로 이동 거부와 근거 있는 launcher 유지의 최소 unit case를 추가·실행한다. 기존 `test_maintenance_file_inventory.py`·`test_maintenance_file_review.py`의 루트 fixture·검증 사례를 재사용한다.
- `tests/test_tiered_assessment.py`·`test_tiered_publication.py`에서 루트 이동 후보의 계획 연결 누락, 근거 있는 제외·기존 계획 연결, 조사·계획·게시 중단 복구, 참조 원본 변경, 검증 실패·게시 미확정 시 성공 기준 미전진과 동일 입력 재사용을 확인한다.
- Manager 전체 verify는 기존 파일별 평가 복구, 모듈 receipt 재사용, 근거 없는 no-change 거부, R-074의 주기·한 번 평가·마지막 Merge 종료 및 Worker targeted test→전체 verify→읽기 전용 Review→PR gate를 보존한다. 이번 Planner는 테스트를 실행하지 않았다.

## Decision Log

- R-028 AC 5의 첫 전수 루트 조사·후보 계획 연결은 기존 파일별 평가에 구현돼 있다. 현재 `TieredReviewRepository.select`는 루트 path/category만 보존하고 `units`·`complete`는 소스 모듈 판단만 요구한다. 모듈 publication은 `root_reviews=()`로 collect·promote하며, `prepare_turn`은 findings가 없으면 no-change를 만든다. 따라서 소스 분류에서 제외된 루트 항목과 소스 없는 tree의 실제 조사·계획 연결 근거가 빠진다. 과거 완료 작업에 소급 계획을 만들지 않고 이 차이만 보완한다.
- complexity medium: 기존 조사 validator와 모듈 평가·후보 처리·게시의 책임 경계가 명확하며, 동일 평가 안에서 근거와 완료 gate를 연결하는 설계다. risk medium: 누락되면 평가가 조기에 완료되거나 이동 후보가 잘못 계획될 수 있다. 실제 이동은 후속 계획의 검증·Review·사용자 Merge로 보호하고, 근거·intent 보존 및 게시 전 재검증으로 복구한다.
- R-074의 모듈 평가 도입은 첫 루트 조사 목표를 철회하지 않았다. 해당 평가 안의 근거를 보완하며 자동 시작 주기·종료 정책을 바꾸거나 별도 평가를 강제하지 않는다. 기존 G-189의 전체 차단·재개 감사는 이 검증 경로의 Merge 뒤 대조한다.
