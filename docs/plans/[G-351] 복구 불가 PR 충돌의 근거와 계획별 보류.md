## Purpose

PR 충돌의 자동 교정·제한적 파일 복원/재작업으로 안전하게 진행할 수 없다는 근거가 확인된 경우에만 연결 계획을 차단하고 현재 원인을 한 번 알린다. 기존 `MANAGED_WORKTREE_CONFLICT`의 계획 scope와 outbox를 재사용하며 최종 판정·상위 결과 소비·조건별 재평가의 남은 연결을 보완한다.

시작 시 `recovery_runtime.decide()`의 횟수 기반 최종 분기와 `waiting_pr_service.select_waiting_pull_request_conflict()`의 프로젝트 결과 전파가 남아 있었다. 아래 보존 단위에서 횟수 소진 대기·계획별 반환 소비·같은 입력의 Worker 반복 억제를 분리했으며, 복구 불가 근거 생산·현재성 검사와 최종 차단의 원인별 재평가까지 연결했다. 전체 verify·Review·완료 판정은 Manager 인계 후 수행한다. scope enum의 존재만으로 R-055의 복구 불가 입증과 독립 진행이 충족된 것으로 보지 않는다.

## Acceptance Criteria

- R-055: 현재 PR URL·head/base OID·실제 operation·소유 작업/checkpoint를 확인하고 허가된 충돌 교정 Worker·파일별 원본 복원/재작업·필요한 재검증을 먼저 적용한다. 안전한 자동 경로가 남지 않았다는 현재 근거가 있어야 해당 ExecPlan만 `PLAN_BLOCKED`로 기록한다.
- 단순 `conflicting`, 짧은 retry/교정 묶음 소진, 사용 한도·외부 조회 실패·잠금·종료 불명은 복구 불가의 충분조건이 아니다. 원인별 대기·현재 상태 재관측 또는 보존된 복구로 연결한다. 실제 공유 자원/소유권 안전 차단은 별도로 유지한다.
- 최종 기록에는 PR identity·충돌 파일/operation·원인·시도한 경로와 불가능 사유·남은 판단/해제 조건·보존한 branch/worktree/session/checkpoint가 연결된다. 해당 계획의 새 일반 실행·게시만 막고 독립 계획·다른 프로젝트의 Worker·verify·Review·게시를 계속한다.
- R-053: 확인된 최종 중단/사용자 대응 사건을 기존 outbox에 일반 알림 하나로 확정한다. 재관측·재시작·전송 재시도는 중복되지 않고 해소된 미전송 잔여분만 취소한다. 실제 사용자 행동이 확인되지 않으면 임의 reset·force push·타 작업 삭제를 안내하지 않는다.
- 새 관련 PR/base 입력·사용자 결정·복구 자원 반환·명시적 해제 요청에서 해당 원인만 재평가한다. 같은 입력의 무변화 Worker/rebase 반복, 독립 차단 해제, 가짜 Merge·성공·작업물 삭제가 없다. Merge·Close는 별도 원격 전이로 계속 관측한다.
