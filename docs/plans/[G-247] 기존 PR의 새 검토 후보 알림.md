## Purpose

기존 PR 충돌 교정 뒤 실제 새 검토 후보가 정상 게시되어 사용자의 검토/Merge 행동이 필요할 때 알린다. 수정 시작·진행·단순 재개는 통지하지 않는다. G-226의 공통 현재 조치 판정을 사용하며 기존 PR/outbox와 게시 완료 복구를 재사용한다.

현재 `enqueue_current_project_events()`의 PR 사건 identity는 PR URL에 고정되어 같은 PR의 새 검토 후보를 구별하지 못한다. 반대로 모든 head 전진을 새 행동으로 처리하면 rebase·동일 검토 후보의 복구 확인이 중복 통지가 된다. 실제 게시/검토 입력과 기존 승인 근거로 두 경우를 구별한다.

## Acceptance Criteria

- 새 PR 또는 기존 PR에 유효한 새 검토 후보가 게시되고 현재 OPEN 상태로 사용자 행동이 남았을 때만 통지한다. 충돌 진입·Worker 시작/실패·checkpoint push·동일 검토 후보의 rebase/재확인에는 무음 메시지도 보내지 않는다.
- 사건 identity는 repository·PR·실제 검토 후보와 남은 행동에 결합한다. URL만으로 새 후보를 누락하거나 head SHA 전진만으로 동일 후보를 재통지하지 않는다. 검토/승인 입력의 동일성을 확인하지 못한 경우 기존 Review/게시 경계에서 처리하며 통지 코드가 승인을 추정하지 않는다.
- 게시 완료와 DB 저장 사이 중단 뒤 실제 원격 효과를 확인한 복구도 같은 사건으로 연결한다. 이미 통지한 같은 후보는 재시작/재확인으로 중복 전송하지 않는다.
- 각 조각 전송 전 현재 PR identity·상태·후보·남은 조치를 확인한다. Merge/Close·새 후보 대체·요청 해소로 오래된 미전송분은 취소하며 기존 payload·cursor·attempt/오류 감사와 PR/commit은 보존한다.

## Implementation

- [ ] 확인한 `loop_manager_internal/recovery/pull_request_recovery.py`·`execution/execution_publication_handler.py`·`git/publication_service.py`의 기존 PR 게시/복구 완료와 검토 입력 근거를 `notifications/events.py`의 PR 사건 선택에 연결한다. 실제 새 사용자 검토 후보의 최소 identity를 기존 기록에 결합하고 별도 PR 작업/승인 엔진을 만들지 않는다.
- [ ] 확인한 `notifications/repository.py`·`delivery.py`의 중복 제거·claim/confirm에 G-226의 공통 판정과 PR 현재성 검사를 적용한다. 외부 조회 동안 DB 접근을 반환하고 적용 때 같은 PR/후보인지 확인한다. 일반 알림 정책·구정책 큐 정리는 G-226, draft 링크는 G-294에 남긴다.
- [ ] 확인한 `tests/test_notification_events.py`·`test_notification_delivery.py`·`test_pr_source_synchronization.py`의 기존 PR/원격 게시/중단 fixture를 재사용한다. PRODUCT·ARCHITECTURE의 PR 알림 소유 절을 실제 새 검토 요청 기준으로 정합화한다.

## Validation

- Worker는 위 테스트의 변경 관련 최소 unit case를 실행한다. 실제 사건 선택·SQLite/outbox·검토 입력 비교를 사용하고 PR/전송 관측만 mock한다. 새 후보 게시 1회, 동일 후보의 재확인/재시작/rebase 0회, 기존 PR의 다른 검토 후보 1회를 구분한다.
- push 완료 뒤 DB 적용 중단·이미 반영된 PR 복구·중복 callback에서 같은 사건을 한 번만 만들고 commit·push·Review를 재실행하지 않는지 확인한다. 기존 원격 게시의 실제 Git 회귀는 재사용하며 알림 조합별로 반복하지 않는다.
- 첫 조각 이후 Merge/Close·후보 대체·조회 실패를 주입해 남은 전송 취소/보류와 전송 감사 보존을 확인한다. 기존 시작/완료 쌍 알림만을 요구한 assertion은 폐기하되 실제 게시·PR identity·lease·복구/파일 보존 assertion은 유지한다.
