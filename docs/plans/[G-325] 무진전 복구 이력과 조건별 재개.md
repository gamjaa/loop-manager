## Purpose

동일 원인·입력에서 retry와 대기만 반복하는 작업과 작업 ID 없는 planning·게시 해제/정리의 정체를 지속 이력으로 구분한다. 해당 자원만 보존 대기하고 실제 새 입력·복구 전이·조건 해소 뒤 이어간다. `recovery_records`와 `persistent_execution_failures`를 재사용하며 session/token 변화·정상 반환을 실질 진전과 구분한다. 현재 `wait_retry()`의 `pending_action=pause`·`occurrence>=3` 타이머 억제와 새 지문 묶음 허용, Git 입력 불확실성의 조건 대기는 직접 구현으로 소비한다. 남은 범위는 그 관측의 의미 있는 입력/진전 결합·실행 간 이력과 실제 해소에 따른 재개다. G-297의 재배정과 G-338의 원인 복구 결과를 소비하고 Git 이력 재구성은 G-313, fetch 격리는 G-324, 진단 전송은 G-326에 남긴다.

## Acceptance Criteria

- R-091/R-055: 작업/자원·단계·원인·유효 입력·실질 진전으로 반복을 식별한다. 짧은 retry 묶음의 실제 시도와 외부 실행 간 이력을 구분해 횟수·확인 기간·상세 원인·보존 자료·다음 유효 재평가 조건을 유지한다. 다른 원인·자원·후보를 같은 장애로 합치지 않는다.
- 타이머 만료·로그/진단 생성·같은 checkpoint 재관측·session/runtime 재시작이나 관측 횟수만으로 진전 또는 해소를 만들지 않는다. 실제 새 원격/파일/검증 입력·안전한 복구 단계·외부 조건 해소를 확인한 경우에만 그 원인에 필요한 처리를 재개한다.
- 정상적인 짧은 retry, 슬롯/CPU/DB/Git 순번 대기·사용 한도·종료 확인 대기는 무진전 장애로 추정하지 않는다. 복구 전이 없이 동일 실패가 반복됐다는 현재 근거가 있을 때 같은 실행의 반복 배정과 다음 외부 실행의 동일 실패 재생을 억제한다. 횟수 소진만으로 FINAL_BLOCK·사용자 결정·성공을 만들지 않는다.
- 보존 대기는 해당 작업/자원에 한정하고 독립 작업·결과 수집·운영 요청·pause/취소·확정된 runtime 종료 결정은 계속 처리한다. 대기 중 runtime 원격 조회·유료 probe·새 writer는 만들지 않고 종료 불명 예약과 필수 검증·dependency는 유지한다.
- 새 입력·상태 변화·유효 복구 요청은 현재 원인·소유권·generation·조건을 재검사하는 계기다. 확인된 해소만 같은 작업의 저장 단계로 연결하며 실패·교정·targeted 이력·checkpoint·session·양쪽 Git 작업물은 초기화하지 않는다. 중단/재시작·경쟁 저장에서 관측·외부 효과 중복이나 다른 작업 상태 덮어쓰기가 없다.
- R-055의 metadata 차단은 원인 관련 입력 변화 또는 유효한 명시 요청을 계기로 재검사한다. 코드/검사 정책 변경·과거 정책 표시 부재와 같은 관측 재저장을 실질 진전이나 새 재개 권한으로 세지 않는다. G-343이 제공하는 대상/원인·요청 소비·현재 검사 결과를 기존 조건 재평가에 연결하며 해당 요청 엔진은 여기서 구현하지 않는다. R-053의 확정 진행·소진·완료 통지는 정체 해소나 진전의 원본이 아니다.
- R-053 소비자가 읽을 현재 정체 identity·근거·기간·횟수·재평가 조건을 기존 저장 경계에서 제공한다. 알림 설정·전송 여부와 실행 판단을 분리하고, 기존 legacy 실패 감사의 부재·불완전성을 새 장애 확인으로 소급 변환하지 않는다.
- R-055 B05–B07/R-053/R-082: 작업 ID 없는 planning·게시 적용/해제·잔여 정리와 후보가 있는 WAITING·skip·조기 반환도 원인 publication/operation·소유자·영향 대상·유효 입력/진전으로 연결한다. `planning_error` 문구·상위 error flag·recovery row 존재만으로 사건 포함/해소를 판정하지 않는다. 정상 사용자 판단·PR/실행 중 소유자의 자원 대기는 장애로 추정하지 않는다.
- 독립 작업 성공·정상 반환 코드·새 run·부분 DB 적용과 같은 관측 재저장은 미해소 사건을 지우지 않는다. 실제 해당 원인 해소/실질 복구 진전이 확인된 사건만 해소하고 허가된 미완료 복구의 다음 단계는 중복 억제로 막지 않는다. writer 종료·자원 반환·원인 교정이 바뀌면 문서 지문이 같아도 원인별 재평가를 허용한다.
