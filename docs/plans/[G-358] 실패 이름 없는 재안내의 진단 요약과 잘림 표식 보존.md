## Purpose

같은 Worker session에 재안내하는 active 실패에서 인식된 실패 이름이 없을 때 첫 진단 줄의 최대 200자 요약과 잘림·누락 표식을 함께 보존한다. 직접 반영된 전체 작업 완료 안내·실패 재안내는 유지하고, 표식을 실패 이름으로 세어 요약을 생략하는 `render_reminders()`의 남은 국소 누락만 교정한다.

## Acceptance Criteria

- `FAILED:` 이름이 있으면 기존처럼 이름과 잘림/누락 표식을 전달한다. 이름이 없으면 비어 있지 않은 첫 진단 줄의 최대 200자와 원래 잘림/누락 표식을 함께 전달한다. 표식만 존재한다는 이유로 비어 있지 않은 요약을 생략하지 않으며 marker만 있는 입력에 진단 내용을 만들어 넣지 않는다.
- identity·occurrence·revision, 비밀값 제거, traceback/이전 결과 원문 미반복과 기존 이름 있는 요약을 유지한다. 저장된 원문·피드백/전달 cursor·active·실패 횟수·checkpoint·session을 바꾸지 않는다. 해결 확인 뒤 재안내 제거와 신규/교체 session의 기존 delta 전달은 그대로다.
- 전체 완료 안내·checkpoint 요청·최소 session 문맥과 active 피드백 선택은 직접 구현을 재사용한다. 새 실패 관측·재발 횟수·사용자 승인·검증 성공을 재안내 과정에서 생성하지 않는다.

## Implementation

- [ ] 확인한 `loop_manager_internal/execution/validation_feedback.py:render_reminders()`에서 실패 이름 선택과 `_TRUNCATED`/`recognizable failures omitted]` 표식 보존을 구분한다. 현재 `names`에는 표식도 들어가므로 이름 없는 잘린 진단에서 fallback 첫 줄이 선택되지 않는다. 기존 renderer 안에서 결과를 조립하고 새 parser·저장 형식·설정은 추가하지 않는다.
- [ ] 확인한 `tests/test_validation_feedback.py:ValidationFeedbackTests.test_reminder_keeps_failure_names_and_omissions_without_tracebacks()`를 확장해 이름 없는 긴 진단+잘림, 누락 표식, marker-only 입력을 기존 이름 있는 경우와 대조한다. 200자 경계·비밀값 제거·원문 미반복을 같은 국소 검증에 연결한다.
- [ ] 확인한 `loop_manager_internal/storage/validation_feedback_state.py:ValidationFeedbackRepository.prepare()`의 reminders/delta 구분과 `loop_manager_internal/execution/execution_worker_handler.py`의 재안내 소비는 유지한다. `tests/test_validation_feedback_state.py:test_delivered_failures_remain_reminders_until_new_stage_observation`와 `tests/test_execution_worker_phase.py:test_worker_prompt_keeps_delivered_failure_reminders_and_other_errors`의 기존 보존/해결 제거 근거를 사용하고 동일 정책 조합을 복제하지 않는다.

## Validation

- Worker targeted unit은 변경한 `ValidationFeedbackTests`의 재안내 case다. 이름 없는 진단에 표식이 추가돼도 첫 줄 요약이 남고, 이름 있는 진단의 traceback은 빠지며 각 표식·identity·occurrence·revision과 비밀값 제거가 유지돼야 한다.
- renderer 교정이 저장/소비 경계를 바꾸지 않는지 기존 feedback state·Worker prompt case로 필요한 최소 연결을 확인한다. 반복 재안내는 실패 횟수/전달 상태를 바꾸지 않고 해당 단계의 새 성공 관측 뒤 목록에서 제거돼야 한다. 실제 Agent·verify 실행이나 새로운 전체 lifecycle을 추가하지 않는다.
