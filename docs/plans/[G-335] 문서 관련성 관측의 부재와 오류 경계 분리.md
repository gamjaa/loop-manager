## Purpose

문서 관련성 판정의 Git 관측 경계에서 확인된 경로 부재와 조회 오류를 구분한다. R-082가 정한 내용 보존 archive/rename·무관한 문서 변경 판단은 유지하고, 비교 불가를 변경 없음이나 성공 재사용 근거로 축약하지 않게 한다.

revision `f5a9d4ea510c62cea769eacd32c604f32bf25425`의 저장된 발견 5는 `planning/planning_document_relevance.py:_blob()`이 `rev-parse --verify` 비정상 종료를 모두 `None`으로 반환하고, 이전/현재 모두 실패하면 `_content_changed()`가 `False`를 반환하는 구조를 확인했다. `command_adapter.git(check=False)`도 실패를 그대로 반환하므로 이 경계에서 부재·오류를 구분해야 한다. 새로운 관련성 정책이나 일반 기능을 추가하는 작업이 아니다.

## Acceptance Criteria

- 유효한 revision/tree의 성공한 조회로 경로 부재를 증명한 경우에만 absent로 판정한다. revision 부재·잘못된 객체·명령/권한/I/O 실패와 비교 불가는 관측 오류로 전달한다.
- 양쪽 조회 오류 또는 absent/error 조합을 동일 blob/변경 없음으로 판정하지 않는다. 현재 작업·원인·기존 자료를 보존하고 기존 재시도/보류로 연결한다.
- 실제 동일 blob·확인된 양쪽 부재, 실제 내용 변경·관련 dependency/source 변화, 내용 보존 archive/rename의 기존 판단과 호출 생략 조건을 유지한다. 관련성만으로 verify/Review/게시 gate를 면제하지 않는다.
- 사용자 동작과 공개 계약인 관련성 호출 시그니처·정상 반환 의미·기존 오류 복구, DB/receipt/문서의 저장 형식을 보존한다. 실패를 성공으로 취급하던 구현 불일치는 상위 계약에 맞추며 새 차단 정책·사용자 선택·성공 cache를 추가하지 않는다.

## Implementation

- [ ] 확인한 `loop_manager_internal/planning/planning_document_relevance.py`의 `_blob` 관측과 `_content_changed`의 순수 비교 책임을 나눈다. 기존 성공 tree 관측/원문 조회 helper와 source 해석 경계를 먼저 재사용하고, 내부 반환 값에서 found/확인된 absent/error를 명확히 구별한다. 기존 `check=False` 종료 코드만으로 부재를 확정하지 않는다.
- [ ] 확인한 `planning/workspace_service.py`의 관련 입력 재검토 소비자에 관측 오류를 기존 실패/보류 경계로 전달한다. 다른 문서의 독립 판단·보존 rebase·원래 단계/session/실패 이력은 유지하며 오래된 완료 결과를 비교 불가 후보에 연결하지 않는다. G-183의 최종 승인 재사용이나 G-331의 게시 transaction 분리는 구현하지 않는다.
- [ ] 확인한 `tests/test_planning_rebase.py`의 관측 fixture에 성공 tree의 absent와 명령 실패를 별도 입력으로 제공한다. 실제 관련성 판정을 실행하고 archive/rename/dependency 기존 assertion을 남긴다. 같은 오류 행렬마다 실제 Git 저장소를 새로 만들지 않는다.
- [ ] 실제 변경이 설명을 필요로 하면 ARCHITECTURE의 단계별 원격 문서 반영/관련 입력 절에 실패·부재 경계만 통합한다. 활성 Requirement·다른 ExecPlan·사용자 판단은 수정하지 않는다.

## Validation

- Worker targeted unit은 `tests.test_planning_rebase`의 변경한 관련성 관측 case다. old/new 각각 found/확인된 absent/error 조합과 실패 종류를 관측 double로 제공하고 실제 비교·재검토 분기를 검사한다.
- 특히 error/error, error/absent, found/error와 잘못된 revision은 변경 없음/완료 재사용을 반환하지 않아야 한다. 기존 작업/session/실패 근거와 원래 오류를 보존하며 관측 실패만으로 새 성공·PR 게시를 만들지 않는다.
- 전체 verify는 내용 보존 archive/rename·dependency/source 관련성, 성공 원문 불변의 호출 생략, 실제 변경/비교 불가의 재검토와 rebase 중단 복구를 유지한다. 실제 Git 통합 회귀의 blob/mode·후보 보존 assertion을 삭제하지 않는다.
- 읽기 전용 Review는 성공한 tree 조회를 부재 근거로 사용하는지, 하위 consumer에서 예외를 삼켜 무변경으로 바꾸지 않는지와 공개/저장 계약 보존을 확인한다.

## Progress

## Decision Log

- complexity medium: 기존 helper와 관련성 호출을 재사용하되 absent와 오류를 소비자까지 보존해야 한다. risk medium: 오류 축약은 재검토 누락을, 과도한 실패 전파는 불필요한 보류를 만들 수 있어 정상/오류 조합과 기존 복구를 함께 확인한다. 최초 level은 3이다.
- R-082의 “원격 확인·갱신·rebase·관련성 판단에 실패하거나 적용 조건을 확정할 수 없으면 무관한 변경 또는 반영 완료로 간주하지 않는다”를 보존한다. G-183의 최종 Review identity 비교와 별개로 이 관측 helper의 책임을 한정하므로 중복 구현이 아니다.
- 현재 발견의 범위만 독립적으로 Merge하며 선행 Merge 뒤 새 평가·마지막 Merge 뒤 사후 재검증을 요구하지 않는다.
