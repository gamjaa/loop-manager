## Purpose

같은 운영 SQLite 파일의 자동 작업 요청을 공통 순번으로 처리하고, 차례·잠금을 기다리는 요청은 thread·cursor·transaction을 붙잡지 않고 반환한다. 현재 공통 접근·프로세스 FIFO·짧은 원자 callback을 재사용하며 외부 CLI의 동기식 접수와 자동 조율을 구분한다.

`db_access._Gate.acquire()`와 `CoordinatedConnection.run_request()`는 현재 condition/sleep 재시도를 수행한다. 기존 DB 파일 정규화·중첩 접근·transaction 원자성은 보존하고 G-353의 완료 확정/조건 재등록에 대기 결과를 연결한다.

## Acceptance Criteria

- R-091: 같은 DB 파일의 프로젝트·테이블·row와 무관하게 공통 순번을 사용한다. 자동 요청의 차례 미도래·일시 잠금은 예약/재확인만 남기고 반환한다. 경로 별칭으로 큐가 나뉘거나 한 요청이 반복 재등록으로 앞선 유효 요청을 추월하지 않는다. 서로 다른 DB·독립 읽기 snapshot 후속 처리는 별도로 진행한다.
- 하나의 조회/상태 확정은 짧은 원자 처리 단위로 수행하고 중첩 요청은 같은 연결·transaction에 참여한다. cursor·미확정 transaction을 요청 밖으로 넘기거나 SQL마다 순번을 반납해 원자성을 깨지 않는다. 동시 공유 연결 하나를 모든 작업에 강제하지 않는다.
- 외부 Git·Agent·verify·Telegram과 다른 자원 대기는 DB 밖에서 수행한다. 완료 외부 효과의 DB 확정만 재등록하고 현재 소유권·generation/CAS를 재검사한다. DB 경합 때문에 효과 재실행·실패/교정 횟수 소비·실행 timeout 증가·가짜 완료가 없다.
- 잠금 오류는 rollback 뒤 최신 입력으로 제한 재시도하고 다음 시점에 반환한다. 손상·권한·SQL 오류를 잠금으로 숨기지 않는다. 원래 오류와 저장 오류가 함께 남고 저장되지 않은 기록을 성공 처리하지 않는다.
- R-076/R-077: 별도 CLI·bootstrap의 기존 접근 조율과 제한 시간을 유지한다. 수동 준비/수락은 짧은 DB 차례 뒤 같은 명령에서 확정하며 다음 Manager 실행을 요구하지 않는다. 읽기 전용 list/status/usage/logs는 DB 생성·migration·journal 변경 없이 snapshot을 유지한다.

## Implementation

- [ ] 확인한 `storage/db_access.py`의 `_Gate`·`CoordinatedConnection`·`run_database_request()`와 `storage/database.py`의 정규화/연결 경계를 재사용한다. G-353의 자동 요청에 유한 접수·차례 확인·완료/대기 결과를 제공하고 프로세스 간 FIFO·기존 동기 CLI 계약을 유지한다. 비호환 schema·새 DB 서비스·범용 SQL 재생 엔진을 도입하지 않는다.
- [ ] `application/task_scheduling.py`의 `finish_storage()`·`wait_database()`와 `application/scheduler.py`의 준비/결과 수집을 자동 요청 재등록에 연결한다. 기존 task_calls receipt·checkpoint·pending 결과로 이미 완료한 실행과 DB만 남은 확정을 분리한다. transaction 밖의 임의 callback을 통째로 반복하지 않는다.
- [ ] 확인한 `application/commands.py`·`application/manual_work.py`의 명시 요청 수락, `storage/runtime_state.py`의 짧은 CAS와 bootstrap의 기존 DB 접근을 대조한다. 외부 관측 전 반납/결과 적용 전 재검사를 유지하고 자동 큐의 변경이 동기 명령의 수락 의미를 바꾸지 않게 한다.
- [ ] 확인한 `tests/test_db_access.py`, `test_task_scheduling.py`, `test_local_environment_recovery.py`, `test_manual_work.py`의 실제 SQLite·제어된 경합 fixture를 확장한다. PRODUCT·ARCHITECTURE의 DB 접근·중단 복구 절을 실제 구현에 맞춰 통합한다.

## Validation

- Worker targeted unit은 위 파일의 변경 경계다. 하나의 실제 임시 DB를 여러 프로젝트/연결이 요청할 때 한 단계 반환·FIFO·중첩 원자 처리·별칭 정규화, 외부 경합 해소 뒤 한 번 확정을 검사한다. 파일 잠금/프로세스 간 순번은 기존 필요한 최소 subprocess 회귀를 유지한다.
- 완료 Agent/Git/verify 결과 뒤 DB 적용 실패·재시작·generation 경쟁을 주입한다. 외부 효과 1회와 원래 receipt/오류 보존·현재 CAS 거부를 실제 저장 결과로 검사한다. DB 대기 중 다른 실행 큐가 진행하며 열린 transaction/cursor가 남지 않아야 한다.
- 실제 SQL/손상/권한 오류·취소·제한 시간·중첩 다른 연결 자기 대기를 기존 회귀로 유지한다. 수동 접수는 같은 명령에서 완료되고 읽기 snapshot은 운영 DB를 쓰지 않아야 한다. Windows 고유 파일 잠금은 관련 최소 native 회귀로 별도 확인하며 Linux 결과를 대신 쓰지 않는다.

## Decision Log
