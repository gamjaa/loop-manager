## Purpose

사용자의 Windows·macOS·Linux 호환성 수정 요청에 따라 OS 전제 때문에 발생하는 실행·검증 결함을 교정한다. 기존 Agent 격리 정책과 소유권 검증은 유지한다.

## Acceptance Criteria

- macOS에서 검증 자식의 identity와 ancestry를 Linux procfs 없이 확인하며, 관측 실패를 종료 성공으로 취급하지 않는다.
- Windows의 프로세스 관리 및 OS별 테스트 fixture가 해당 플랫폼 API를 사용한다.
- verify 진입점은 저장소 위치와 설치된 Python 환경을 일관되게 사용한다.
- 세 OS의 로컬 검증 진입점을 제공하고 실제 수행 결과와 미검증 범위를 구분한다.
- Windows·macOS·Linux의 Codex 호출은 OS별 내장 sandbox의 쓰기 경계를 사전 확인한 뒤 시작한다. 확인 실패 시 기존 안전 중단을 유지한다.

## Implementation

1. 프로세스 관측·검증 진입점·Git/파일 fixture의 OS 의존성을 조사한다.
2. 확인된 결함을 기존 모듈에서 수정하고 관련 회귀 테스트를 추가한다.
3. 로컬 검증 진입점과 README의 실행·지원 범위를 정리한다.

## Validation

- 프로세스 identity·ancestry, 자원 fallback, runner worker 정리와 OS fixture 관련 targeted unit test를 실행한다.
- 실제 Agent 호출은 테스트 guard로 차단한다.
- 전체 verify는 Agent에서 실행하지 않는다. Manager가 각 OS에서 수행할 검증이며 결과 확인 전 전체 호환성을 확정하지 않는다.

## Progress

- 조사: non-Windows를 Linux procfs로 취급하는 경로, POSIX 전용 테스트와 검증 스크립트의 Python launcher 가정을 확인했다.
- 구현: Windows 잠금 바이트와 identity 읽기를 분리하고 SQLite 연결을 명시적으로 닫았다. Git의 빈 global excludes 설정과 경로 디코딩, 심볼릭 링크 권한 및 경로 구분자 fixture를 교정했다.
- 구현: macOS libproc 기반 프로세스 관측과 자원 관측 불가 시 직렬 fallback을 추가했다. Windows Agent 자식은 시작 전에 Job에 배정하고 OS별 쓰기 금지 경계 검사를 통과해야 실행한다.
- 구현: verify 진입점의 저장소 경로·Python 선택·종료 코드를 정리하고 shell 파일의 LF를 고정했다.
- 검증: Windows Python 3.13.14에서 변경 관련 targeted unit test 137개를 102.039초에 실행하여 통과했다(플랫폼·권한 조건에 따른 skip 7개). 실제 모델 호출 대신 guard와 가짜 provider를 사용했다. 결과는 `.cache/verify/platform-compatibility/final.log`에 보관했다.
- 후속 검증: 최신 origin/main `e301f9c` 위로 기존 문서 commit을 rebase하여 HEAD는 `ce1c91b`가 됐다. 미커밋 변경은 보존했고 main과 겹치는 Git 관측·복구 fixture 관련 Windows 테스트 23개가 통과했다.
- 후속 검증: WSL2 Ubuntu(Linux 6.6.87.2, Python 3.12.3)의 Linux 파일시스템 복사본에서 관련 테스트 154개를 실행하여 통과했다(Windows 전용 2개 skip, 25.387초). 첫 실행의 CRLF shell 실패를 LF로 교정한 뒤 같은 범위를 재검증했다. 로그는 `.cache/verify/platform-compatibility/wsl-final.log`에 보관했다.
- 남은 검증: 전체 verify, macOS 실환경 실행, 실제 Codex sandbox 호출, Reviewer 검토 및 사용자 Merge는 수행하지 않았다. ExecPlan 완료 조건은 아직 충족하지 않았다.

## Decision Log

- 사용자 요청에 따라 GitHub Actions 검증 workflow를 제외한다. 로컬 검증 스크립트와 서버의 Manager 검증은 유지한다.
- 저장 형식·Git 게시 경계와 보안 정책을 변경하지 않는다.
- 사용자 후속 확인: 실제 Agent 실행 지원까지 포함한다. Codex의 OS별 내장 sandbox를 사용하고 별도 WSL·컨테이너·권한 우회는 도입하지 않는다. Claude의 검증되지 않은 격리는 계속 거부한다.
- Windows는 private directory 생성을 위해 Python 3.13 이상과 사전 설정된 elevated Codex sandbox를 요구하고 기존 CODEX_HOME을 사용한다. macOS·Linux의 기존 역할별 runtime home 정책은 유지한다.
- 로컬 PATH의 Codex는 0.155.0으로 기존 최소 버전 0.159.3 미만이다. 별도 설치된 0.160.0을 확인했지만 사용자 PATH를 변경하거나 실제 Agent를 호출하지 않았다.
- rebase로 main에 G-160이 추가되어 이 미게시 계획의 ID를 G-161로 변경했다. WSL 검증은 Windows worktree의 Git 경로를 재사용하지 않고 현재 파일의 독립된 Linux Git snapshot에서 수행했다.
