## Purpose

사용자가 제공한 서버 분석(전체 verify 457.5초, rebase snapshot 2,400회)을 근거로 반복 Git 조회와 테스트의 반복 준비를 줄인다. 기존 제품 동작과 안전 검사를 보존하는 직접 요청 작업이며 자동 Planner 입력과 SQLite 등록 없이 manual 경로에 기록한다.

## Acceptance Criteria

- 한 rebase 관측에서 snapshot의 index/debug, staged diff, ignored 목록과 operation 경로를 공유한다. 두 번의 안정성 관측과 Git 쓰기 직전 재검증은 각각 새로 수행한다.
- ignored 규칙은 NUL 구분 stdin 묶음 조회로 확인하며 누락·중복·잘린 결과·실패를 정상 부재로 처리하지 않는다. ignore 변경으로 숨겨진 파일과 index 보안 flags 검증을 유지한다.
- 실제 Git lifecycle의 정상·다중 충돌·수동 복구를 유지한다. 게시 중단·권한·원격 경쟁 시나리오는 실제 Git/SQLite의 게시 경계 상태에서 시작하고 기존 lease·intent·재시작·원격 보존 assertion을 유지한다.
- 전수 import 검사는 모듈마다 새 isolated interpreter를 유지하며 resource effect 금지 검사를 함께 수행한다. 중복 서비스 import 검사를 통합하고 package initializer 검사는 유지한다.
- 테스트 필수 범위·timeout·병렬 배정·verify 스크립트의 전체 실행 계약을 변경하지 않는다. 시간 절감은 서버 동일 조건 실측 전 확정하지 않는다.

## Implementation

1. 기존 snapshot 수집에 호출 범위의 상세 결과 출력을 추가하고 rebase 관측에서 활용한다. 저장 snapshot 형식이나 장기 캐시는 추가하지 않는다.
2. ignored 규칙과 rebase metadata 경로 해석을 묶는다. 관련 실제 Git·파서·실패·재관측 targeted unit test를 보강한다.
3. lifecycle 게시 경계 fixture와 assertion 대응을 정리하고 전수 fresh import 검사에 resource effect 검사를 합친다.

## Validation

- Worker: 변경한 수집·관측의 명령 수, 상세/기존 결과 동등성, index flags·충돌 stage·unusual path, ignored 묶음 실패·규칙 변경, metadata 격리·재관측의 targeted unit test.
- Worker: import subprocess 인자·격리·resource effect·모듈 범위의 targeted unit test와 기존 호환 export signature 검사.
- Manager: 실제 lifecycle 전체 19개와 전체 verify를 Agent 밖에서 실행한다. 서버에서 동일 범위의 전후 Git 명령 수·snapshot 수·모듈 시간·전체 시간을 비교한다.

### lifecycle assertion 대응

19개 시나리오 ID를 유지한다. 게시 경계 7개는 독립된 임시 Git worktree에 최신 base의 허용 후보 commit과 SQLite의 pending rebase를 준비한다. 원격은 이전 소유 OID를 유지한다. 준비 과정의 reset은 이 임시 fixture에만 적용되며 제품 실행 경계를 바꾸지 않는다.

| 시나리오 | 유지한 검증 |
| --- | --- |
| before-push / after-push / sqlite | 정확한 기존 OID lease·후보 ref, durable intent, 중단 뒤 실제 원격 대조·같은 intent 재개, 이미 push된 후보의 재push 금지 |
| permission | 실제 receive hook 거부, 원래 intent·lease 보존, 정책 해제 뒤 동일 intent 재시도 |
| remote-race / remote-deleted / new-pr | 실제 원격 변경·삭제·PR 출현에서 거부, pending checkpoint·원격·local HEAD 보존 |
| 정상·seal 중단·legacy·수동 복구·base/input 전진·누적 rebase 12개 | 실제 Git 충돌·동일 파일 후속 commit·mode·skip, journal/SQLite 경계, session·audit 보존, Worker 후보 재확인→verify→Review |

게시 경계의 공통 assertion은 수용 멱등성·소유 checkpoint·session·audit 보존과 검증 무효화를 계속 검사한다. 중복 후속 Worker→verify→Review 대신 해당 구간에 Worker·verify·Reviewer가 없음을 검사하며 후속 검증 계약은 나머지 12개에서 유지한다.
