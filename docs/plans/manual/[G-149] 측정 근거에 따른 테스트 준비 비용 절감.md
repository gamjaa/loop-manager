## Purpose

G-148의 실제 시간 자료에서 큰 비용을 차지하는 준비·반복 작업만 줄인다. 테스트가 보호하는 계약과 실제 Git·SQLite의 실패·복구 시나리오를 유지하고, 근거 없는 대규모 fixture 전환을 피한다.

## Acceptance Criteria

- 변경 대상마다 측정된 비용, 보호하는 동작과 기존 중복 여부, 선택한 개선을 기록한다. 시간 자료가 없는 항목의 병목이나 절감률을 확정하지 않는다.
- 초기 저장소 재사용을 적용하면 각 테스트의 repo·remote·index·refs·config·작업 파일이 독립적이다. origin과 모든 위치 참조가 해당 테스트의 경로를 가리키며 이전 테스트의 상태가 전달되지 않는다.
- 판단·인자 전달 테스트의 stub 전환은 필요한 인자·결과·오류 계약을 보존하고, 실제 Git·SQLite·운영체제의 실패·중단·복구 회귀는 유지한다.
- G-143의 자원 수명과 G-144의 시나리오 책임 경계를 유지한다. fixture 준비 실패·중단에서도 cleanup이 등록되고 Windows 임시 경로와 DB가 정상 정리된다.
- 같은 환경·검증 범위의 Manager 자료로 변경 전후 비용을 비교한다. 효과가 없거나 격리를 약화하는 후보는 채택하지 않고 제외 근거를 남긴다.

## Implementation

1. G-148의 코드 생성 집계로 상위 테스트와 공통 준비 비용을 비교하고 실제 외부 호출·대기·중복 실행을 먼저 확인한다. 선택한 개선 범위와 보존할 assertion을 Decision Log에 기록한다.
2. `tests/support/git.py`의 `make_remote_repository`, `tests/support/origin.py`의 `remote_fixture`와 관련 소비자를 우선 조사한다. 초기 Git 준비가 실제 병목이면 동일 테스트 프로세스 안의 준비된 초기 저장소를 독립 임시 경로로 복사하는 최소 변경을 비교한다.
3. 공유 원본은 초기 상태만 보유하고 테스트가 수정하지 못하게 한다. copied origin·worktree 등의 위치 참조, object 저장소 연결과 refs가 원본 또는 다른 테스트로 이어지지 않음을 확인한다. import 시 Git·DB·임시 디렉터리 생성과 다른 호스트에서의 캐시 공유를 추가하지 않는다.
4. Git 동작 자체를 보호하지 않는 분기·인자 테스트는 기존 작은 stub을 재사용한다. 현재 측정된 소비자만 변경하고 필요한 실제 Git 회귀를 남긴다. fixture 최적화에 안전한 이득이 없으면 그 근거를 문서화하고 테스트 변경을 강요하지 않는다.
5. Manager가 직렬 전체 verify와 시간 집계를 비교하고, 적용 효과·보존 범위·제외한 후보를 기록한다. 전체 verify 또는 Git integration을 Worker가 직접 실행하지 않는다.

## Validation

- Worker는 변경한 helper와 소비자의 직접 관련 unit case만 실행한다. fake 복사·Git port로 원본 미변경, origin 경로 재지정, 초기화 실패와 cleanup 등록을 확인한다.
- Manager 전체 verify는 실제 Git 초기 상태, 두 독립 fixture의 push·rebase·refs 상호 비간섭, SQLite 수명과 기존 실패·복구 assertion을 확인한다. 같은 환경의 전후 측정에서 준비 비용과 전체 시간을 비교한다.
