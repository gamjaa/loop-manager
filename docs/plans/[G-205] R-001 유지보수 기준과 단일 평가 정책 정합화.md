## Purpose

복원된 R-001의 유지보수 차단·prerequisite 뒤 재평가·사후 READY 재검증 기준과 현행 R-074 단일 평가·마지막 Merge 종료 정책의 충돌을 해소한 뒤, 승인된 정책에서 남은 작업만 구현한다.

## Acceptance Criteria

- 사용자가 R-001 AC 7·9~14 및 관련 본문의 적용 범위를 R-074와 정합하게 확정한다. 독립 PLAN_BLOCKED가 due 평가를 막는지, prerequisite 뒤 새 평가와 마지막 리팩터링 뒤 사후 재검증을 요구하는지 활성 Requirement에 명시한다.
- 확정된 정책은 실제 프로젝트 안전 gate·필요한 계획 차단·dependency·현재 변경 실행·Open PR 동기화·미확정 게시와 사용자 Merge를 보존한다. 주기 종료를 수행하지 않은 의미 검토 성공으로 기록하지 않는다.
- 기존 유지보수 cycle·확정 범위·게시 intent·평가 원본·session을 보존해 중단 뒤 같은 단계에서 복구한다. 독립 READY의 일반 복귀와 다음 due 기준은 승인된 정책으로만 판정한다.
- 사용자 결정과 명세의 원격 확인 뒤 최신 코드·테스트를 대조해 실제 미충족 동작만 구현한다. 기존 barrier 검증·원자 게시와 G-179의 Manager 자동 dependency 편집을 재구현하지 않는다.

## Implementation

- maintenance/cycle_service.py·maintenance_orchestration.py, storage/maintenance_state.py, planning/selection_service.py의 기존 due·확정 범위·종료 경계를 재사용한다. 계획별 검증·Review와 cycle cadence·평가 성공 근거를 구분한다.
- 현행 R-074를 유지하면 이미 구현된 prerequisite closure·마지막 Merge 종료를 다시 계획하지 않는다. 과거 재평가·사후 재검증을 복원하는 선택이면 새로운 실행 조건과 legacy cycle 재개 기준이 사용자 명세로 확정된 뒤 필요한 상태 전이·검증만 변경한다.
- docs/PLANS.md의 barrier·post-refactor revalidation 권한은 mode와 무소유 snapshot에 제한된 별도 계약이다. 해당 형식의 존재만으로 현행 cycle에 추가 평가를 실행하지 않는다.

## Validation

- 최소 unit case로 독립/필요 dependency PLAN_BLOCKED, 실제 Open PR 대기, prerequisite Merge, 마지막 리팩터링 Merge, 미확정 게시와 중단·재시작에서 승인된 호출·종료 횟수를 검증한다.
- maintenance authority·publication 회귀는 무소유 snapshot 보호, 전체 DAG 비순환성, 하나의 원격 확인 batch 뒤 원자 catalog 반영과 원본 성공 근거 보존을 확인한다.
- Manager 전체 verify는 단일 변경 실행·사용자 Merge·dependency gate 및 cycle 종료와 프로젝트 최종 충족 판단의 분리를 유지한다.

## Decision Log

- complexity medium: 기존 due·closure·종료 상태와 게시 경계의 제한된 변경이다. 아직 정해지지 않은 사용자 정책을 높은 effort로 대신 선택하지 않는다.
- risk high: 잘못된 기준은 미완료 dependency·게시를 완료로 처리하거나 유지보수 호출을 반복해 일반 작업을 막을 수 있다. 보존된 cycle·intent·원격 결과를 대조해 복구하며 실제 Merge·게시를 코드 rollback으로 되돌릴 수 있다고 가정하지 않는다.
- R-012의 기본값 5와 반복 평가 목표는 R-042·R-054·R-074 및 현재 기본값 20으로 대체됐다. 이 archive 감사만으로 R-012를 활성화하거나 후속 계획의 source로 사용하지 않는다.
- 기존 G-179는 DAG 말단 dependency를 Manager가 추가하는 남은 작업이다. 어느 정책을 선택하더라도 필요한 barrier·소유권·원자 게시 검증은 유지하므로 본 계획으로 중복하거나 임의 개정하지 않는다.

## Draft Decision

Question: R-001이 요구하는 독립 PLAN_BLOCKED의 유지보수 보류, prerequisite Merge 뒤 재평가와 마지막 리팩터링 Merge 뒤 READY 재검증을 다시 도입할지, 현행 R-074의 단일 평가·마지막 Merge 종료와 독립 차단 비확대 정책을 유지할지 R-001·R-074에 정합하게 명시해 달라.
Facts: R-001은 R-012 장벽·prerequisite 재평가·사후 재검증을 요구한다. R-074는 두 재평가를 명시적으로 제거하고 현재 PRODUCT·cycle 테스트는 별도 평가 없이 확정 범위의 마지막 Merge와 원격 게시 확인 뒤 종료한다. R-054의 현행 due 조건은 독립 PLAN_BLOCKED로 평가를 보류하지 않는다. ARCHITECTURE의 유지보수 분석 절 마지막에는 여전히 사후 재검증이 cycle 완료를 담당한다는 문장이 있어 현재 PRODUCT·R-074와도 맞지 않는다.
Options: A는 R-074의 1회 평가·종료와 현행 due 조건을 유지하도록 사용자가 R-001을 정합하게 개정한다. B는 과거 재평가·재검증 및 차단 조건의 복원 범위·기존 cycle 처리·호출 제한·종료 기준을 새로 확정하고 R-074와 관련 명세를 함께 변경한다. 부분 적용도 각 조건을 분명하게 명시해야 한다.
Impact: A는 구현된 종료 동작을 유지하므로 명세 정합성 확인 뒤 실제로 남은 작업만 재판단한다. B는 유지보수 state·재개·호출·회귀 검증의 변경이 필요하다. 선택 전에는 이 계획과 의존 작업의 Worker·workspace·branch·PR을 시작하지 않으며, 기존 Manager barrier 편집 등 독립 작업은 계속할 수 있다.
