## Purpose

이미 있는 RecoveryBoundary·Git seed·관측 batching을 재사용해 Reviewer 프로토콜 변형의 반복 준비 등 남은 중복 비용을 줄이고 실제 비교 근거를 남긴다.

## Acceptance Criteria

- 대표 rebase·publication 경계의 이미 구현된 재사용을 보존하고, Review 프로토콜 변형의 반복 Worker/verify 준비를 유효한 경계 준비로 공유한다. 축소한 각 assertion의 보호 계약이 집중 검증 또는 대표 실제 전체 흐름에 남는다.
- 준비 자료는 실제 파일/mode·Git 객체/ref/index/config·SQLite/checkpoint/journal을 복원하고 새 경로/작업 identity·digest를 현재 증거로 확인한다. 실패/중단/병렬 변형은 독립이고 자료 부재/불일치/재현 실패는 재생성 또는 실패다.
- 남은 중첩 관측은 같은 검사 구간의 완전한 입력에서만 공유한다. 필수 이중 관측·게시/SQLite 확정·Git/Agent/verify 전후·재시작은 새로 확인한다. 이미 있는 inactive journal lazy 관측과 snapshot 조회 통합은 재작성하지 않는다.
- 준비 생성/복사/복원/확인·단계/이유별 snapshot·관측 경로 전체 Git 수/시간을 같은 시나리오·환경에서 전후 비교한다. 대표 호출 수 회귀와 import 최초 실행 계약을 유지하고 집계 경계 이동·mock 확대·skip·timeout 증가로 절감을 만들지 않는다.

## Implementation

- tests/support/recovery.py의 기존 boundary 인자와 recovery_boundary.py·git fixture seed·Git timing을 사용한다. 테스트가 확인할 실패/교정 전이를 준비 단계에서 미리 성공시키지 않는다.
- 원본·소유권 판정의 소비 경계에서 실제 남은 중복만 계측해 줄인다. 준비/관측 비용과 개별·모듈 누적·전체 verify 비교 자료는 기존 진단과 Manager 실행 경계에 연결한다.
- 자동 역할·권한·검증은 docs/AGENTS.common.md와 해당 역할의 docs/AGENTS.*.md를, 프로젝트 규칙·설계·계획 작성은 AGENTS.md·docs/ARCHITECTURE.md·docs/PLANS.md를 참조한다. 기존 helper·관련 테스트를 재사용하고 지정 루트 경로를 보존한다.

## Validation

- tests/test_review_protocol_recovery.py, test_recovery_boundary.py, test_git_snapshot_cost.py 중 준비 독립성·identity·오류/교정·낡은 관측 거부의 최소 unit case를 실행한다.
- Manager 전체 verify는 실제 Git/SQLite 경쟁·중단 복구와 대표 정상 흐름을 유지하며 같은 범위 전후/첫 생성·재사용 비용을 비교한다. 전체 비교는 Worker가 실행하지 않는다.
